# M04.5.3 — Post-Training: Supervised Learning

After **pre-training**, the model has learned a lot about language and patterns.

But there is a problem:

> A base model knows how language works, but it is not necessarily good at **following user instructions**.

That's why we do **supervised post-training**, especially **Supervised Fine-Tuning (SFT)**.

The basic idea is:

```text
Base Model
    ↓
Instruction + Good Answer examples
    ↓
Supervised Fine-Tuning
    ↓
Instruction-Following Model
```

---

## 1. Instruction-Response Datasets

An **instruction-response dataset** contains examples of:

```text
Instruction
     ↓
Desired Response
```

For example:

```text
Instruction:
Explain recursion in simple terms.

Response:
Recursion is when a function calls itself...
```

Another example:

```text
Instruction:
Translate "Good morning" into Hindi.

Response:
सुप्रभात
```

Another:

```text
Instruction:
Write a Python function to reverse a string.

Response:
def reverse_string(s):
    return s[::-1]
```

The model learns from thousands, millions, or more examples like these, depending on the training setup.

---

### What does the dataset teach?

The examples can teach the model:

- How to answer questions
- How to follow instructions
- How to format responses
- How to solve particular tasks
- How to behave in conversations
- How to produce useful outputs

So the dataset is not just teaching **knowledge**.

It is also teaching:

> **"When the user asks this, this is the kind of response we want."**

---

## 2. Demonstrations

A **demonstration** is simply an example of how a task should be performed.

Think about teaching a student.

Instead of only saying:

> "Solve these problems."

you show:

```text
Problem:
2 + 2

Correct solution:
4
```

Then give more examples.

The examples demonstrate the expected behavior.

### In LLM training

```text
User:
Summarize this paragraph.

Assistant:
[Good summary]
```

This is a demonstration.

Another:

```text
User:
Return the result as JSON.

Assistant:
{
  "name": "John",
  "age": 30
}
```

This demonstrates the expected format.

---

### Demonstrations can teach different things

#### Task behavior

```text
Question → Answer
```

#### Style

```text
Question → Concise answer
```

#### Format

```text
Question → JSON
```

#### Reasoning pattern

```text
Problem → Step-by-step solution
```

#### Conversation behavior

```text
User → Assistant
User → Assistant
```

---

## 3. Supervised Fine-Tuning (SFT)

**SFT = Supervised Fine-Tuning**

This is the actual training process where the pretrained model learns from the instruction-response examples.

The model already has learned language patterns from pre-training.

Now we train it on carefully prepared examples.

```text
Pretrained Model
       ↓
Instruction-Response Dataset
       ↓
SFT
       ↓
Better instruction following
```

---

### Why is it called "supervised"?

Because we have an expected output.

For example:

```text
Input:
Explain APIs simply.

Expected response:
An API is a way for software...
```

The model generates a response and the training process compares it with the desired response.

The parameters are then updated to make the model more likely to produce the desired output.

Conceptually:

```text
Instruction
    ↓
Model
    ↓
Generated response
    ↓
Compare with desired response
    ↓
Loss
    ↓
Update parameters
```

This is still fundamentally based on token-level prediction, but now the training examples are specifically designed around desired assistant behavior.

---

## 4. What Does SFT Actually Change?

SFT can make a model much better at things such as:

### Following instructions

User:

```text
Explain Docker in 3 points.
```

The model should understand the constraint.

### Following formatting requirements

User:

```text
Return the answer as JSON.
```

The model should attempt to produce JSON.

### Following style requirements

User:

```text
Explain this like I'm a beginner.
```

The response should adapt to the requested level.

### Performing specific tasks

For example:

```text
Summarization
Translation
Classification
Question answering
Code generation
Extraction
```

---

# Base Model vs SFT Model

This distinction is very important.

### Base model

Mainly learned from:

```text
Large corpus
↓
Self-supervised learning
↓
Language patterns
```

It can generate text, but may not reliably behave like an assistant.

### SFT model

Starts from the base model and learns from:

```text
Instructions
+
Desired responses
```

So:

```text
Base model
→ Learn language patterns

SFT model
→ Learn to perform tasks and follow instructions
```

---

# 5. Instruction-Following Evaluation

After SFT, we need to test:

> **Does the model actually follow instructions correctly?**

This is called **instruction-following evaluation**.

Simply asking whether the output "sounds good" isn't enough.

We need to test specific behaviors.

---

### Simple instruction

```text
Explain HTTP.
```

Did the model actually explain HTTP?

---

### Multiple constraints

```text
Explain HTTP
in 5 bullet points
for a beginner
and keep it concise.
```

Now we check whether it followed **all** the instructions.

```text
Explain HTTP        ✓
5 bullet points     ✓
Beginner-friendly   ✓
Concise             ✓
```

---

### Formatting instruction

```text
Return:

{
  "name": "...",
  "age": "..."
}
```

We check whether the structure is correct.

---

### Negative constraints

For example:

```text
Do not use technical jargon.
```

We check whether the model respected that instruction.

---

# Why Evaluation Matters

A model can produce a response that looks fluent but still fail the task.

Example:

```text
User:
Give me exactly 3 reasons.

Model:
Here are 7 reasons...
```

The answer may be perfectly grammatical.

But it **didn't follow the instruction**.

So evaluation must check:

```text
Language quality
+
Task correctness
+
Instruction adherence
```

---

# A Simple Evaluation Example

Suppose you're building an AI tutor.

You create test prompts like:

```text
Explain recursion to a beginner.

Summarize this paragraph in 2 sentences.

Return the following information as JSON.

Give me exactly 3 examples.

Translate this into Hindi.

Explain this code and identify the bug.
```

Then compare different versions of the model.

You might measure:

```text
Instruction followed?      ✓ / ✗
Correct answer?             ✓ / ✗
Format correct?             ✓ / ✗
Important constraints met? ✓ / ✗
```

This gives you evidence that SFT actually improved the desired behavior.

---

# SFT Dataset Quality Matters

Just like pre-training, the quality of the data matters enormously.

Suppose your dataset contains:

```text
Bad instruction
      ↓
Bad response
```

and you train heavily on it.

The model can learn undesirable behavior.

So good SFT datasets should generally have:

- Clear instructions
- Correct responses
- Useful examples
- Diverse tasks
- Consistent formatting
- Appropriate difficulty

---

# Data Diversity Is Important

Suppose every training example is:

```text
"Explain this."
```

The model won't get broad exposure to different task types.

A stronger dataset might contain:

```text
Question answering
Summarization
Translation
Coding
Extraction
Classification
Reasoning
Formatting
Conversation
```

This gives the model broader instruction-following experience.

---

# One Important Difference: Knowledge vs Behavior

Think of training as two broad layers.

### Pre-training

```text
Learn patterns from massive amounts of data
```

### SFT

```text
Learn how to use those capabilities in response to instructions
```

For example, a base model may have encountered information about databases.

SFT can teach it to respond when the user says:

```text
"Explain database indexing to me like I'm a beginner."
```

So:

> **Pre-training gives the model a foundation. SFT shapes that foundation into useful task-following behavior.**

---

# Simple Real-World Example

Suppose we want an **AI LMS assistant**.

### Before SFT

The base model may know:

```text
React
JavaScript
Databases
Programming
```

but we want it to answer student questions in a particular way.

### SFT dataset

We create examples:

```text
Student:
Why did I get this question wrong?

Assistant:
Your answer was incorrect because...
The correct concept is...
```

Another:

```text
Student:
Explain this topic simply.

Assistant:
Let's break it down into...
```

Another:

```text
Student:
Give me 3 practice questions.

Assistant:
1. ...
2. ...
3. ...
```

SFT trains the model on these examples.

Now the model is more likely to behave like an **LMS tutor**.

```text
                    PRE-TRAINING

              Instruction Dataset

                  Demonstrations

```

Remember this:

```text
Pre-training
→ "Learn language and patterns."

SFT
→ "Learn how to respond to instructions."

Evaluation
→ "Check whether you actually follow those instructions."
```

### One-line memory trick

> **Instruction examples → SFT → better instruction following → evaluate whether the model actually follows the instructions.**
