Pre-training is the first major stage of language-model training. Its purpose is to teach a model general patterns of language, information and structure using a large training corpus.

The central idea is:

**Collect useful data → prepare it → convert it into tokens → train the model → evaluate the resulting base model.**

## 1. Corpus Collection and Filtering

### What is a corpus?

A **corpus** is a collection of data used to train a model. For a language model, it may contain books, websites, articles, research papers, technical documentation, source code and educational content.

Think of the corpus as the model's training library.

```text
Books
Websites
Research papers
Documentation
Source code
     ↓
Training corpus
```

The quality and composition of this corpus influence the patterns the model can learn.

### What is corpus filtering?

**Filtering** means removing data that does not meet the training pipeline's quality or suitability requirements.

Raw internet data can contain useful information alongside spam, corrupted pages, low-quality text, duplicate content and material that is unsuitable for the training objective.

A filtering pipeline attempts to identify and remove or exclude unwanted material.

### Why is filtering important?

The model learns statistical patterns from its training data. Poor-quality or irrelevant data can introduce noise into the learning process.

```text
Raw training data
       ↓
Quality filtering
       ↓
More suitable training corpus
       ↓
Potentially better learning signal
```

Filtering does not automatically guarantee a better model. Its effectiveness depends on the filtering rules, the data and the training objective.

### Key points

- A corpus is the collection of training data.
- Filtering removes data that fails the chosen quality or suitability criteria.
- Useful training material may include natural language, technical content and source code.
- Data preparation is an important part of the overall training process.

## 2. Deduplication

### What is deduplication?

**Deduplication** is the process of identifying and removing duplicate or highly similar examples from a training corpus.

For example, suppose the corpus contains the same paragraph on multiple websites. Keeping every copy may cause that content to be overrepresented.

```text
Raw corpus
    ↓
Detect repeated content
    ↓
Remove redundant copies
    ↓
Deduplicated corpus
```

### Types of duplicates

**Exact duplicates:** Two documents or passages contain identical content.

Example:

```text
Document A:
React is a JavaScript library.

Document B:
React is a JavaScript library.
```

A deduplication system can identify these identical passages and retain a single copy where appropriate.

**Near-duplicates:** Two documents or passages are not exactly identical but contain substantially similar content.

Example:

```text
A: React is used to build user interfaces.

B: React helps developers create user interfaces.
```

Detecting near-duplicates is more difficult because wording may change while meaning remains similar.

### Why is deduplication important?

Deduplication can help:

- Reduce redundant training examples.
- Improve the diversity of training data.
- Prevent repeated content from receiving disproportionate influence.
- Reduce unnecessary training computation.
- Reduce some forms of training and evaluation data contamination.

Deduplication does not mean removing every repeated concept. Different explanations of the same concept can still provide useful training diversity.

### Exact duplicates vs. near-duplicates

| Feature | Exact duplicates | Near-duplicates |
|---|---|---|
| Content | Identical | Similar but not necessarily identical |
| Detection | Generally simpler | Often more challenging |
| Example | The same paragraph copied twice | Two rewritten versions of a paragraph |
| Main concern | Repeated copies | Redundant or highly similar content |

### Key points

Deduplication makes the corpus less repetitive by reducing exact duplicates and, where appropriate, highly similar examples.

## 3. Tokenization

### What is tokenization?

**Tokenization** is the process of converting text into smaller units called **tokens**, which are then represented using numerical token IDs for model processing.

Neural networks operate on numerical representations rather than directly processing raw text as humans read it.

Consider the sentence:

```text
Transformers are powerful.
```

A tokenizer might divide it into pieces resembling:

```text
["Transform", "ers", " are", " powerful", "."]
```

This is an illustrative example only. The actual tokens depend on the tokenizer and vocabulary.

The resulting tokens are mapped to numerical IDs:

```text
Raw text
   ↓
Tokenizer
   ↓
Tokens
   ↓
Token IDs
   ↓
Model input
```

### Why not simply split text into words?

A tokenizer may split text into whole words, parts of words, punctuation or other units, depending on its design.

This approach allows a model to represent words it encounters in different contexts without requiring every possible word form to be a separate vocabulary entry.

The exact tokenization strategy depends on the tokenizer used.

### Why is tokenization important?

Tokenization affects several parts of an AI system.

**Context-window usage:** Different tokenizers can represent the same text using different numbers of tokens.

**Training cost:** The number of tokens processed influences the computational workload.

**Inference cost:** Token usage can influence the cost of model requests when pricing is token-based.

**Language representation:** Some tokenization strategies represent different languages and writing systems more efficiently than others.

### Important distinction

A **token** is not necessarily a complete word.

For example, a word can be represented by multiple tokens. Conversely, a token can contain a complete word or part of one.

Therefore:

```text
Word ≠ Token
Token → Numerical token ID
```

### Key points

- Tokenization converts text into model-processable units.
- Token IDs provide numerical representations of those units.
- Tokenization affects context usage and computational cost.
- The exact representation depends on the tokenizer.

## 4. Self-Supervised Objectives

### What is self-supervised learning?

**Self-supervised learning** is a training approach in which the training data itself provides the learning targets, rather than requiring humans to manually label every example.

An important pre-training objective for many language models is **next-token prediction**.

### Next-token prediction

Suppose the training text is:

```text
The cat sat on the mat.
```

The model learns to predict the next token from the preceding context.

For example:

```text
Context: The
Target:  cat

Context: The cat
Target:  sat

Context: The cat sat
Target:  on

Context: The cat sat on
Target:  the

Context: The cat sat on the
Target:  mat
```

The actual training process depends on the model architecture and training objective, but this example illustrates the central idea.

### How does the model learn from mistakes?

The model produces a probability distribution over possible next tokens.

The training process compares that distribution with the correct target token and calculates a **loss**, which measures the prediction error according to the training objective.

The loss is then used to improve the model's parameters.

```text
Training context
       ↓
Model predicts next token
       ↓
Compare prediction with target
       ↓
Calculate loss
       ↓
Backpropagation
       ↓
Update parameters
       ↓
Repeat over training examples
```

### Important training terms

**Prediction:** The model estimates which token should come next.

**Target:** The correct token specified by the training example.

**Loss:** A numerical measure of prediction error under the chosen objective.

**Backpropagation:** The procedure used to calculate gradients that indicate how parameters should change to reduce the loss.

**Parameters:** The numerical values learned by the model during training.

### What does the model learn?

By predicting tokens across large amounts of text, the model can learn statistical patterns related to:

- Vocabulary.
- Grammar and syntax.
- Writing styles.
- Facts and relationships represented in the training data.
- Source-code patterns.
- Concepts and relationships among tokens.

These capabilities emerge through training on patterns across examples. A language model is not simply a conventional database storing and retrieving every training document.

### The training loop

```text
Training corpus
      ↓
Tokenization
      ↓
Input token sequences
      ↓
Model predictions
      ↓
Loss calculation
      ↓
Backpropagation
      ↓
Parameter updates
      ↓
More training examples
      ↓
Improved learned parameters
```

This process is repeated many times during pre-training.

### Key points

- Self-supervised learning derives training targets from the data itself.
- Next-token prediction is an important objective for many language models.
- Loss measures errors relative to the chosen target.
- Backpropagation calculates gradients used to update parameters.
- Repeated training helps the model learn general patterns in the corpus.

## 5. Base-Model Evaluation

### What is a base model?

A **base model** is the model produced after pre-training, before any additional post-training stages that may adapt it for specific behaviors or tasks.

Completing training does not automatically establish that a model performs well. Its learned capabilities must be evaluated.

```text
Prepared training corpus
          ↓
      Pre-training
          ↓
       Base model
          ↓
       Evaluation
```

### What should be evaluated?

Depending on the model and intended purpose, evaluation may cover:

- Language understanding.
- Knowledge.
- Reasoning.
- Mathematics.
- Coding.
- Multilingual performance.
- General language-model performance.

The evaluation methods and metrics depend on the capabilities being assessed.

### Training data vs. evaluation data

A model should not be evaluated only on the exact examples it learned from during training.

Instead, the evaluation process uses **held-out data**: examples reserved for evaluation rather than used to optimize the model during the relevant training process.

```text
Available dataset
       |
       ├── Training data
       |       ↓
       |   Learn parameters
       |
       └── Held-out evaluation data
               ↓
        Measure performance
```

The precise data-splitting and contamination controls depend on the evaluation setup.

### What is generalization?

**Generalization** is the ability to perform well on new examples beyond the training examples.

For example, a model trained on many programming examples should be tested on suitable held-out coding problems rather than assessed only on code it has already seen.

Strong performance on familiar training material alone does not establish strong generalization.

### Why is evaluation necessary?

Evaluation helps determine whether pre-training produced the intended capabilities and reveals areas where the model performs poorly.

It provides evidence about the model's behavior rather than assuming that successful execution of the training pipeline means the model is sufficiently capable.

### Key points

- Pre-training produces a base model.
- Evaluation measures the model's learned capabilities.
- Held-out examples help measure performance beyond the training data.
- Generalization means performing well on new examples, not merely familiar ones.

## Practice and Interview Questions

### Easy

**Question 1: What is pre-training?**

**Answer:** Pre-training is the initial major training stage in which a model learns general patterns from a large corpus of data.

**Question 2: What is a corpus?**

**Answer:** A corpus is the collection of data used to train a model. It can contain books, websites, research papers, documentation, articles and source code.

**Question 3: What is tokenization?**

**Answer:** Tokenization converts text into tokens that can be mapped to numerical IDs for model processing.

**Question 4: What is a base model?**

**Answer:** A base model is the model produced after pre-training, before additional post-training stages that may adapt its behavior.

### Medium

**Question 5: What is the difference between filtering and deduplication?**

**Answer:** Filtering removes or excludes data that fails quality or suitability requirements. Deduplication specifically reduces repeated or highly similar examples.

**Question 6: Explain next-token prediction.**

**Answer:** Next-token prediction trains a model to estimate the next token from the preceding context. The model's prediction is compared with the target token, a loss is calculated, and the parameters are updated through optimization.

**Question 7: Why does tokenization affect the cost of using a model?**

**Answer:** Tokenization determines how much input text is represented as tokens. Token counts influence context-window usage and can affect training or inference costs when computation or pricing depends on token volume.

**Question 8: What is generalization, and how is it evaluated?**

**Answer:** Generalization is the ability to perform well on new examples rather than only on training examples. Held-out evaluation data helps measure performance beyond the training set.

### Hard — Scenario-Based

**Question 9: A training corpus contains the same technical article thousands of times. What problem can this cause, and which preprocessing method addresses it?**

**Answer:** Repeated copies can make the article overrepresented, reduce dataset diversity and consume unnecessary training computation. Deduplication can identify repeated copies and remove redundancy. It does not mean that all different explanations of the same concept must be removed.

**Question 10: A model achieves low training loss but performs poorly on new examples. What should the team investigate?**

**Answer:** The team should investigate generalization, the representativeness and quality of training data, possible overfitting, and whether the evaluation data and metrics are appropriate. Training loss alone does not demonstrate good performance on unseen examples.

**Question 11: A language-model system processes far more tokens than expected for a given document. Which stage should be investigated first?**

**Answer:** Inspect the tokenization process and the actual token counts. The tokenizer may represent the document using more tokens than expected, affecting context usage and cost.

**Question 12: Why is evaluating a model only on its training data insufficient?**

**Answer:** Training data shows how the model performs on examples used during learning, but does not establish how well it handles new examples. Held-out evaluation data provides a better basis for measuring generalization.

## Final Revision

Remember the five main topics in order:

1. **Corpus Collection and Filtering** — Gather training data and exclude unsuitable material.
2. **Deduplication** — Reduce repeated or highly similar examples.
3. **Tokenization** — Convert text into tokens and numerical IDs.
4. **Self-Supervised Objectives** — Learn patterns through objectives such as next-token prediction, using loss and parameter updates.
5. **Base-Model Evaluation** — Test the resulting model on suitable held-out data and assess its generalization.

**One-line summary:**

> Pre-training prepares a suitable corpus, tokenizes the data, optimizes the model using self-supervised objectives, and evaluates the resulting base model to determine what it has learned.
