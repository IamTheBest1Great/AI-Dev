# M04.5.1 — Pre-training

Pre-training is the **first major stage of training a language model**.

The main goal is:

> **Teach the model general patterns of language, information, and structure by training on a huge amount of data.**

A simple view:

```text
Raw Data
   ↓
Clean Data
   ↓
Tokens
   ↓
Self-Supervised Training
   ↓
Base Model
   ↓
Evaluation
```

---

## 1. Corpus Collection and Filtering

### What is a corpus?

A **corpus** is the collection of data used to train the model.

It can contain:

- Books
- Websites
- Articles
- Research papers
- Documentation
- Source code
- Educational content

Think of it as the model's **training library**.

```text
Books
Websites
Code
Papers
Articles
   ↓
Training Corpus
```

### Why can't we directly use all internet data?

Because raw data contains lots of unwanted material:

```text
Useful article        ✓
Research paper        ✓
Documentation         ✓

Spam                  ✗
Broken pages          ✗
Low-quality text      ✗
Duplicate content     ✗
Meaningless content   ✗
```

So the corpus needs to be **filtered**.

### What is filtering?

Filtering means removing data that is:

- Low quality
- Irrelevant
- Corrupted
- Unwanted
- Potentially unsafe or inappropriate for the training objective

The exact filtering rules depend on the model and its training goals.

### Why does filtering matter?

A model learns patterns from its training data.

So:

```text
Better training data
       ↓
Better learning signal
       ↓
Potentially better model
```

This is why **data preparation is a major part of model training**.

---

## 2. Deduplication

Deduplication means:

> **Removing duplicate or highly similar training data.**

Suppose the dataset contains:

```text
Document A:
React is a JavaScript library...

Document B:
React is a JavaScript library...

Document C:
React is a JavaScript library...
```

There is no great benefit in treating all three as independent pieces of information.

After deduplication:

```text
Document A
Document C
...
```

### Why is deduplication important?

It helps:

- Avoid wasting training compute
- Improve data diversity
- Prevent some content from being overrepresented
- Reduce the risk of training/evaluation contamination

### Exact vs near duplicates

Duplicates aren't always identical.

For example:

```text
A:
React is used to build user interfaces.

B:
React helps developers create user interfaces.
```

These aren't exactly the same sentence, but they are very similar.

Training pipelines can also try to detect these **near-duplicates**.

### Simple idea

```text
Raw corpus
    ↓
Remove repeated/similar data
    ↓
More useful corpus
```

---

## 3. Tokenization

The model cannot directly process raw text in the same way humans read it.

The text is first converted into **tokens**.

For example:

```text
"Transformers are powerful."
```

might be split conceptually into:

```text
["Transform", "ers", " are", " powerful", "."]
```

The exact tokens depend on the tokenizer.

These tokens are then mapped to numerical IDs:

```text
Text
 ↓
Tokens
 ↓
Token IDs
```

### Why do we need tokenization?

Neural networks work with numerical representations.

Tokenization also affects:

- How many tokens a document uses
- Context-window usage
- Training cost
- Inference cost
- How efficiently different languages are represented

So tokenization is more important than just "splitting words."

---

## 4. Self-Supervised Objectives

This is the **core learning mechanism** during language-model pre-training.

### What does self-supervised mean?

Instead of humans manually labeling every training example, the training target can be created from the text itself.

For example:

```text
The cat sat on the mat.
```

The model can be trained to predict:

```text
The
→ cat

The cat
→ sat

The cat sat
→ on

The cat sat on
→ the

The cat sat on the
→ mat
```

This is called **next-token prediction**.

---

### What is the model learning?

Initially, the model makes poor predictions.

```text
Input:
The cat sat on the

Prediction:
dog
chair
mat
table
...
```

The correct next token is known from the training text.

The model compares its prediction with the correct answer.

This produces a **loss**.

```text
Prediction
    ↓
Compare with target
    ↓
Loss
    ↓
Backpropagation
    ↓
Update parameters
```

This process is repeated over a huge amount of data.

---

### What is the training loop?

The basic loop is:

```text
Training text
     ↓
Tokenization
     ↓
Model prediction
     ↓
Calculate loss
     ↓
Backpropagation
     ↓
Update parameters
     ↓
Repeat
```

Over time, the model becomes better at predicting patterns in language.

---

### What does the model learn from this?

It can learn patterns related to:

- Vocabulary
- Grammar
- Syntax
- Writing styles
- Facts and relationships present in the data
- Code patterns
- Concepts
- Statistical relationships between tokens

A useful mental model is:

> **The model is learning patterns from enormous amounts of examples rather than simply storing the training documents as a database.**

---

## 5. Base-Model Evaluation

After pre-training, we need to determine:

> **What did the model actually learn?**

The resulting model is often called a **base model**.

```text
Large corpus
    ↓
Pre-training
    ↓
Base model
```

But we shouldn't assume the model is good just because training completed successfully.

We need to evaluate it.

### What can we test?

Depending on the model:

- Language understanding
- Knowledge
- Reasoning
- Mathematics
- Coding
- Multilingual ability
- General language-model performance

### Training data vs evaluation data

We should not simply test the model on the exact data it trained on.

Instead, we use **held-out evaluation data**.

```text
Dataset
   │
   ├── Training data
   │      ↓
   │    Model learns
   │
   └── Evaluation data
          ↓
       Model is tested
```

This helps us measure **generalization**.

### What is generalization?

It means the model can perform well on **new examples**, not just examples it has already seen.

# Easy Mental Model

Think of pre-training like teaching a student.

```text
Corpus Collection
→ Gather books and study material

Filtering
→ Remove bad material

Deduplication
→ Don't give the same book repeatedly

Tokenization
→ Break information into learnable pieces

Self-supervised learning
→ Ask "what comes next?"

Parameter updates
→ Learn from mistakes

Evaluation
→ Give new questions and test learning
```

# Final Cheat Sheet

| Concept | Simple meaning |
|---|---|
| **Corpus** | Large collection of training data |
| **Filtering** | Remove poor or unwanted data |
| **Deduplication** | Remove repeated or highly similar data |
| **Tokenization** | Convert text into tokens |
| **Self-supervised learning** | Create training signals from the data itself |
| **Next-token prediction** | Predict what token comes next |
| **Loss** | Measure how wrong the prediction was |
| **Backpropagation** | Calculate parameter updates from the loss |
| **Base model** | Model produced after pre-training |
| **Evaluation** | Test what the model learned |

### One line to remember

> **Pre-training = Collect good data → clean it → tokenize it → train on next-token prediction → evaluate the resulting base model.**
