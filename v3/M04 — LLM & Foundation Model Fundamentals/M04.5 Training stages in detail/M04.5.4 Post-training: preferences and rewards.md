# M04.5.4 — Post-Training: Preferences and Rewards

After **pre-training** and **supervised fine-tuning (SFT)**, a model can understand language and follow instructions reasonably well.

But there is still another problem:

> **There can be many possible answers that are all technically correct, but some are more useful, clear, safe, or appropriate than others.**

Preference and reward-based training tries to teach the model **which behaviors are preferred**.

A simple view:

```text
Base Model
    ↓
SFT
    ↓
Instruction-following Model
    ↓
Preference / Reward Training
    ↓
Better preferred behavior
```

---

# 1. Preference Datasets

A **preference dataset** tells us which response is better when there are multiple possible responses.

Instead of showing only:

```text
Question → Good Answer
```

we can show:

```text
Question
   +
Response A
   +
Response B
   ↓
Which response is preferred?
```

### Example

User asks:

```text
Explain recursion to a beginner.
```

The model produces two possible responses:

**Response A**

> Recursion is when a function calls itself to solve a smaller version of the same problem.

**Response B**

> Recursion is a computational paradigm involving self-referential function invocation and recursive decomposition.

Both may be technically correct.

But for a beginner, **A might be preferred** because it is easier to understand.

So the dataset records something like:

```text
A > B
```

Meaning:

> Response A is preferred over Response B.

---

### What can preferences represent?

Preferences can reflect things such as:

- Helpfulness
- Clarity
- Relevance
- Conciseness
- Correctness
- Style
- Safety
- Following the user's intent

So preference data is about more than just factual correctness.

---

# 2. Preference Optimization

Once we have preference data, we want to train the model to produce responses that are more likely to be preferred.

This is called **preference optimization**.

The basic idea is:

```text
Prompt
  ↓
Possible responses
  ↓
Preference information
  ↓
Train model
  ↓
Prefer better responses
```

Suppose the training data says:

```text
Prompt → A is preferred over B
```

The training process tries to make the model:

```text
More likely to generate A-like behavior
Less likely to generate B-like behavior
```

---

### Why do we need this after SFT?

SFT gives the model examples of desired responses:

```text
Instruction → Good response
```

Preference training provides a different type of signal:

```text
Good response > Less good response
```

So:

```text
SFT
→ "This is a good example."

Preference optimization
→ "This response is better than that response."
```

---

### DPO awareness

One well-known preference-optimization technique is **DPO (Direct Preference Optimization)**.

You don't need the mathematics yet.

For your notes, remember:

> **DPO directly trains the model using preferred and rejected responses, without requiring the classic RLHF reward-model pipeline.**

So DPO is one example of **preference optimization**.

---

# 3. RLHF and Reward Models

## What is RLHF?

**RLHF = Reinforcement Learning from Human Feedback**

The basic idea is:

```text
Model generates responses
        ↓
Humans judge them
        ↓
Preference information
        ↓
Reward signal
        ↓
Reinforcement learning
        ↓
Model improves toward preferred behavior
```

The important word is **reward**.

A higher reward means:

> "This behavior is more desirable according to the training objective."

---

## What is a reward model?

A **reward model** is a separate model trained to estimate how good or preferred a response is.

For example:

```text
Prompt:
Explain recursion.
```

Two responses:

```text
Response A
Response B
```

Humans indicate:

```text
A is preferred over B
```

The reward model learns from many such comparisons.

Later, it might produce conceptually:

```text
Response A → higher reward
Response B → lower reward
```

The numbers are only illustrative.

---

## Reward-model training

The process can look like:

```text
Human comparisons
      ↓
Preference dataset
      ↓
Train reward model
      ↓
Reward model learns preferences
```

Then:

```text
LLM
 ↓
Generates response
 ↓
Reward model scores response
 ↓
Reinforcement learning uses reward
 ↓
LLM is updated
```

---

## Why use a separate reward model?

Imagine you have millions of model responses.

You cannot necessarily ask a human to manually judge every response during every training step.

Instead:

```text
Humans
   ↓
Provide preference examples
   ↓
Train reward model
   ↓
Reward model evaluates many outputs
```

The reward model acts as an approximation of the preference signal learned from human judgments.

---

# 4. Reinforcement Learning With Verifiable Rewards

Human preferences aren't the only way to create rewards.

For some tasks, the result can be **automatically checked**.

This is called using **verifiable rewards**.

The basic idea is:

```text
Model
 ↓
Produces answer/action
 ↓
Verifier checks result
 ↓
Reward
```

---

### Example: Mathematics

Question:

```text
What is 17 × 12?
```

Model produces:

```text
204
```

A verifier knows the correct result.

```text
Correct → reward
Incorrect → lower/no reward
```

No human needs to manually judge that particular answer.

---

### Example: Coding

Suppose the model generates code.

```text
Model
 ↓
Generated code
 ↓
Run test suite
 ↓
Tests pass?
```

For example:

```text
All tests pass → positive reward
Some tests fail → lower reward
```

The test system provides an objective training signal.

---

### Example: Chess

```text
Model
 ↓
Choose a move
 ↓
Game outcome / engine evaluation
 ↓
Reward
```

The outcome can provide a measurable signal.

---

### Example: Formal proofs

A proof can be submitted to a formal verifier:

```text
Model-generated proof
       ↓
Proof checker
       ↓
Valid / invalid
       ↓
Reward
```

This is useful because correctness can be checked automatically.

---

## Why are verifiable rewards valuable?

Because for some tasks we can define:

```text
Correct
vs
Incorrect
```

without asking a human every time.

This is especially useful for tasks such as:

- Mathematics
- Programming
- Games
- Formal reasoning
- Other objectively checkable problems

---

## But not every task is verifiable

Consider:

> "Write a beautiful poem about the ocean."

There is no single objectively correct answer.

You may care about:

- Creativity
- Style
- Emotional impact
- Clarity

Those are much harder to verify automatically.

So:

```text
Objective task
→ Verifiable reward can work well

Subjective task
→ Human preference can be more useful
```

---

# Putting Everything Together

The overall idea looks like this:

```text
                SFT MODEL
                    ↓
            Generate responses
                    ↓
         ┌──────────┴──────────┐
         ↓                     ↓
 Human preferences      Verifiable outcome
         ↓                     ↓
 Preference data          Automatic reward
         ↓                     ↓
 Preference optimization   RL / reward training
         └──────────┬──────────┘
                    ↓
             Improved behavior
```

And the classic RLHF pipeline can be remembered as:

```text
Human comparisons
       ↓
Preference dataset
       ↓
Reward model
       ↓
Reinforcement learning
       ↓
Updated language model
```

---

# How SFT, Preference Optimization, and RLHF Differ

| Method | Training signal | Main idea |
|---|---|---|
| **SFT** | Desired responses | Learn from demonstrations |
| **Preference optimization** | Preferred vs rejected responses | Learn which response is better |
| **RLHF** | Human preference → reward | Optimize model behavior using reinforcement learning |
| **Verifiable reward training** | Automatically checked outcome | Optimize toward objectively measurable correctness |

---

# Important Example

Imagine you're building your **AI LMS assistant**.

User asks:

> "Explain why I got this question wrong."

### SFT

You provide examples:

```text
Student question
+
Good tutor response
```

The model learns how a tutor should answer.

### Preference training

Experts compare two answers:

```text
Answer A → explains the mistake clearly
Answer B → gives the answer but doesn't explain the mistake
```

Preference:

```text
A > B
```

The model learns to prefer the more useful tutoring behavior.

### Verifiable reward

For a math question, you can automatically check whether the explanation contains the correct result.

```text
Model explanation
      ↓
Correctness checker
      ↓
Reward
```

So different training signals can improve different aspects of the system.

---

# Key Difference Between Human Preference and Verifiable Reward

Think of it this way:

```text
Human preference:

"Which answer is better?"

        vs

Verifiable reward:

"Is this answer objectively correct?"
```

Human preference is useful for things that are difficult to define precisely.

Verifiable rewards are useful when correctness can be checked automatically.

---

# What Can Go Wrong?

Reward-based training isn't automatically perfect.

## Poor preference labels

If humans consistently prefer bad responses:

```text
Bad preference data
      ↓
Bad reward signal
      ↓
Model learns undesirable behavior
```

## Reward hacking

The model may discover a way to get high reward without actually accomplishing the intended goal.

For example:

```text
Goal:
Write correct code.

Reward:
Number of comments.
```

The model might generate lots of comments instead of useful code.

So:

> **A reward is only useful when it measures what you actually care about.**

# Simple Mental Model

Remember the progression:

```text
Pre-training
→ Learn language and patterns

SFT
→ Learn from good examples

Preference optimization
→ Learn which responses are preferred

RLHF
→ Use human-derived rewards to optimize behavior

Verifiable rewards
→ Use automatically checkable outcomes when possible
```

# Final Cheat Sheet

```text
Preference Dataset
→ Examples showing which response is preferred

Preference Optimization
→ Train the model to prefer better responses

RLHF
→ Human feedback is turned into a reward signal
   and used with reinforcement learning

Reward Model
→ A model that predicts how desirable a response is

Verifiable Reward
→ Reward produced by an automatic checker
   such as a math verifier or test suite
```

### One line to remember

> **SFT teaches the model what a good answer looks like; preference training teaches it which answers are better; RLHF uses human-derived rewards to optimize that behavior; verifiable rewards use automatically checkable correctness when possible.**
