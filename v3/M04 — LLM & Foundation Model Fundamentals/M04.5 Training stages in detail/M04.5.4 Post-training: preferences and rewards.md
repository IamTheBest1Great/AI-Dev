After pre-training and supervised fine-tuning (SFT), a language model can generate text and follow many instructions. However, multiple responses may be technically correct while differing in usefulness, clarity, relevance, style or safety.

**Preference and reward-based training** helps a model learn which behaviors are more desirable according to a defined training objective.

The central idea is:

**SFT teaches from demonstrations → preference training compares responses → reward-based methods optimize behavior toward a desired outcome.**

## 1. Preference Datasets

### Definition

A **preference dataset** contains comparisons that indicate which of multiple responses is preferred for a particular prompt.

Unlike a typical SFT example, which provides a desired response, preference data can indicate that one response is better than another.

```text id="pjm60e"
Prompt
  +
Response A
  +
Response B
  ↓
Preference judgment
  ↓
A is preferred over B
```

This relationship can be represented as:

\[
A > B
\]

Here, the symbol means that Response A is preferred to Response B for the given prompt.

### Example: Explaining recursion

User instruction:

```text id="nw68ir"
Explain recursion to a beginner.
```

**Response A:**

"Recursion is when a function calls itself to solve a smaller version of the same problem."

**Response B:**

"Recursion is a computational paradigm involving self-referential function invocation and recursive decomposition."

Both responses may be technically correct. However, Response A is more accessible to a beginner.

A preference dataset might record:

```text id="mmcg43"
Prompt: Explain recursion to a beginner.

Preferred response: A
Rejected response: B
```

The label does not mean that Response B is always wrong. It means Response A is preferred for this particular prompt and evaluation criterion.

### What can preferences represent?

Preference judgments may consider:

- **Helpfulness:** Does the answer satisfy the user's needs?
- **Clarity:** Is the answer easy to understand?
- **Relevance:** Does it address the actual question?
- **Conciseness:** Does it avoid unnecessary detail?
- **Correctness:** Is the information accurate?
- **Style:** Does it use the desired tone and presentation?
- **Safety:** Does it avoid inappropriate or harmful responses?
- **Instruction adherence:** Does it follow the user's requirements?

Different tasks require different priorities. A detailed technical explanation may be preferred for an expert, while a concise explanation may be preferred for a beginner.

### How are preference datasets created?

A typical process is:

```text id="w0opx6"
Provide a prompt
      ↓
Collect candidate responses
      ↓
Compare responses
      ↓
Record preferred response
      ↓
Build preference dataset
```

The judgments may come from human reviewers or another evaluation process, depending on the training setup.

The quality of these judgments matters because they influence what the model is encouraged to produce.

### Preference data vs. instruction-response data

| Feature | Instruction-response dataset | Preference dataset |
|---|---|---|
| Typical example | Prompt and desired response | Prompt and multiple compared responses |
| Main signal | What a good response looks like | Which response is better |
| Example relationship | Prompt → Answer A | Prompt → A preferred over B |
| Common training use | Supervised fine-tuning | Preference optimization and reward-model training |

### Key takeaway

A preference dataset provides comparative feedback that distinguishes better responses from less-preferred alternatives.

## 2. Preference Optimization

### Definition

**Preference optimization** is the process of training a model to produce responses that better match a set of preferences.

The training signal indicates which response is preferred rather than merely showing one desired answer.

### How it works

Suppose the preference dataset contains:

```text id="jb4hvg"
Prompt → Response A preferred over Response B
```

The optimization process encourages the model to assign more favorable likelihood or preference to the chosen response relative to the rejected response, according to the particular training method.

Conceptually:

```text id="opn37e"
Prompt
  ↓
Candidate responses
  ↓
Preference information
  ↓
Preference optimization
  ↓
Model more likely to produce preferred behavior
```

The exact parameter updates depend on the chosen algorithm.

### Why is it useful after SFT?

SFT and preference optimization provide different kinds of learning signals.

**SFT:**

```text id="e4pr5g"
Instruction → Desired response
```

**Preference optimization:**

```text id="v7ho39"
Response A > Response B
```

SFT demonstrates a target behavior. Preference optimization provides a relative judgment between alternatives.

This is particularly useful when several responses are acceptable but differ in quality.

### Example

Suppose an AI tutor can answer a student's question in two ways.

Response A gives the correct answer but does not explain the misconception.

Response B gives the correct answer and explains why the student's original answer was wrong.

For a tutoring application, Response B may be preferred because it better supports learning.

Preference optimization can use these comparisons to encourage responses with the desired characteristics.

### Direct Preference Optimization (DPO)

**Direct Preference Optimization (DPO)** is one method of preference optimization.

For this topic, remember:

- DPO uses preferred and rejected responses as training data.
- It directly optimizes the model using preference comparisons.
- It does not require the classic separate reward-model-plus-reinforcement-learning pipeline used in traditional RLHF.

DPO is a preference-optimization technique, not a synonym for all preference training.

### Important distinction

Preference optimization does not automatically guarantee objectively correct answers. It encourages behavior according to the training preferences, which may be incomplete or imperfect.

### Key takeaway

Preference optimization teaches the model to favor responses that align better with the available preference judgments.

## 3. RLHF and Reward Models

### What is RLHF?

**RLHF stands for Reinforcement Learning from Human Feedback.**

It is an approach in which human feedback is used to guide the optimization of a model's behavior through reinforcement learning.

A classic RLHF workflow uses human comparisons to train a reward model, then uses the reward model to provide a learning signal during reinforcement learning.

### The classic RLHF pipeline

```text id="7gzge9"
Language model generates responses
             ↓
Humans compare the responses
             ↓
Preference dataset
             ↓
Train reward model
             ↓
Reward model scores responses
             ↓
Reinforcement learning
             ↓
Updated language model
```

The goal is to make the language model more likely to produce responses that receive higher rewards under the training objective.

### What is a reward?

A **reward** is a numerical signal used to indicate how desirable an outcome is according to the training objective.

Conceptually:

```text id="w8p0yc"
Higher reward → More desirable according to the objective
Lower reward  → Less desirable according to the objective
```

The reward is only as useful as the objective and evaluation process that produce it.

### What is a reward model?

A **reward model** is a model trained to estimate how desirable a response is according to preference data or the relevant reward-labeling process.

Consider this prompt:

```text id="4ad1uq"
Explain recursion.
```

Two responses are collected, and human reviewers indicate that Response A is preferred over Response B.

After training on many comparisons, a reward model may assign illustrative scores such as:

```text id="djd8pg"
Response A → 0.8
Response B → 0.3
```

These numbers are hypothetical and depend on the reward model's scale. They are not universal measures of answer quality.

The reward model learns to approximate the preference signal reflected in the training comparisons.

### Why use a separate reward model?

Human reviewers cannot necessarily evaluate every generated response during every optimization step.

A reward model learns from a collection of human judgments and can then score many additional responses.

```text id="t4b1is"
Human reviewers
       ↓
Preference examples
       ↓
Reward-model training
       ↓
Learned preference estimator
       ↓
Score additional responses
```

This allows the optimization process to use an estimated reward signal without requiring a human to judge each response individually.

However, the reward model is only an approximation. Its scores may not perfectly reflect actual human preferences.

### How reinforcement learning uses the reward

In the classic pipeline, the language model generates responses. The reward model scores them, and a reinforcement-learning algorithm updates the language model to improve the reward objective.

Conceptually:

```text id="9f4g5h"
Language model
      ↓
Generated response
      ↓
Reward model
      ↓
Reward score
      ↓
Reinforcement-learning update
      ↓
Updated language model
```

Specific implementations may also use additional objectives or constraints to keep optimization from moving too far from the intended behavior.

### RLHF vs. DPO

| Feature | Classic RLHF | DPO |
|---|---|---|
| Preference data | Commonly used | Used |
| Separate learned reward model | Yes, in the classic pipeline | Not required as a separate reward model |
| Reinforcement-learning stage | Yes, in the classic pipeline | Not required in the classic RLHF form |
| Optimization approach | Uses reward-based reinforcement learning | Directly optimizes from preference comparisons |

Both approaches use preference information, but they differ in how that information is used for optimization.

### Key takeaway

In classic RLHF, human preferences train a reward model, and the reward model provides a reward signal for reinforcement learning. DPO offers another way to optimize the model directly from preferences.

## 4. Reinforcement Learning with Verifiable Rewards

### Definition

**Verifiable rewards** are reward signals derived from outcomes that can be checked against explicit rules or an objective verification procedure.

Human preference is useful when judging quality requires subjective or contextual evaluation. However, some tasks have results that can be checked automatically.

### General workflow

```text id="azvkcc"
Model generates answer or action
             ↓
Verifier checks the outcome
             ↓
Determine correctness or success
             ↓
Produce reward signal
```

The verifier provides evidence about whether the model achieved the desired result.

### Example: Mathematics

Question:

```text id="x0v56l"
What is 17 × 12?
```

The correct answer is 204.

An automatic checker can compare the model's answer against the expected result.

```text id="c1tdq2"
Model produces answer
        ↓
Check against expected result
        ↓
Correct → Positive reward
Incorrect → Lower or no reward
```

This avoids the need for a human to manually judge every instance of this particular calculation.

### Example: Coding

Suppose the model generates a function that must satisfy a set of requirements.

```text id="02ilwp"
Model generates code
        ↓
Run test suite
        ↓
Check test results
        ↓
Passing tests → Positive reward signal
Failing tests → Lower reward signal
```

A test suite can provide a verifiable training signal when the tests appropriately represent the task requirements.

Passing tests does not necessarily prove that the code is completely correct, secure or maintainable. The value of the reward depends on the quality and coverage of the tests.

### Example: Chess

A model chooses a move, and the game outcome or a defined engine evaluation supplies a reward signal.

```text id="mx3r9q"
Model selects move
       ↓
Play or evaluate the move
       ↓
Measure game outcome
       ↓
Produce reward
```

### Example: Formal proofs

A generated proof can be submitted to a formal proof checker.

```text id="b6i5pi"
Generated proof
      ↓
Formal verifier
      ↓
Valid or invalid
      ↓
Reward signal
```

A formal checker can verify whether a proof satisfies the formal system's rules.

### When are verifiable rewards useful?

They are particularly useful for tasks with clear, checkable success criteria, including:

- Mathematics with exact answers.
- Programming tasks with suitable tests.
- Games with measurable outcomes.
- Formal proofs.
- Other objectively checkable problems.

### Why not use verifiable rewards for every task?

Not every desirable result has a single objectively correct answer.

Consider the instruction:

"Write a beautiful poem about the ocean."

The desired outcome may depend on creativity, imagery, emotional impact, style and personal preference.

These qualities are difficult to reduce to one definitive automatic correctness check.

A task may therefore benefit more from human preference judgments, or from a combination of preference and verifiable signals.

### Human preferences vs. verifiable rewards

| Feature | Human preference | Verifiable reward |
|---|---|---|
| Main question | Which response is better? | Does the result satisfy a checkable condition? |
| Signal source | Human judgments or preference labels | Programmatic check, test suite or formal verifier |
| Useful for | Helpfulness, clarity, style and subjective quality | Exact answers, passing tests and formally verifiable results |
| Main limitation | Judgments may be inconsistent or subjective | The verifier may not capture every important success criterion |

### Key takeaway

Use verifiable rewards when success can be checked reliably. Use preference feedback when the desired qualities are difficult to define through objective tests alone.

## 5. SFT vs. Preference Optimization vs. RLHF

These methods are related but not interchangeable.

### SFT — Learning from demonstrations

SFT uses desired input-output examples to teach the model how to respond.

```text id="g3lvrq"
Instruction
    +
Desired response
    ↓
SFT
    ↓
Model learns from demonstrations
```

### Preference optimization — Learning from comparisons

Preference optimization uses information about which of multiple responses is preferred.

```text id="y1zf55"
Prompt
   +
Preferred response
   +
Rejected response
   ↓
Preference optimization
```

DPO is one example of this approach.

### RLHF — Optimizing from human-derived rewards

In the classic RLHF pipeline, human preferences train a reward model. Reinforcement learning then uses the reward model to optimize the language model.

```text id="lvpwpx"
Human judgments
       ↓
Reward model
       ↓
Reward signal
       ↓
Reinforcement learning
       ↓
Updated language model
```

### Comparison table

| Method | Training signal | Main idea |
|---|---|---|
| SFT | Desired responses | Learn from demonstrations |
| Preference optimization | Preferred vs. rejected responses | Learn which responses are preferred |
| Classic RLHF | Human preference-derived reward | Optimize behavior using reinforcement learning and a reward model |
| Verifiable-reward training | Automatically checked outcomes | Optimize toward explicitly measurable success |

### How they can work together

These approaches can serve different purposes within a broader model-development process.

For example:

```text id="qxu7mu"
Pre-training
     ↓
Base model
     ↓
SFT
     ↓
Instruction-following model
     ↓
Preference optimization or RLHF
     ↓
Model further aligned with target preferences
     ↓
Evaluation
```

Verifiable rewards may also be useful during optimization for tasks in which success can be measured automatically.

The appropriate combination depends on the intended application, available data and desired behavior.

### Key takeaway

SFT teaches from examples, preference optimization learns from comparisons, classic RLHF uses human-derived rewards with reinforcement learning, and verifiable-reward methods use checkable outcomes.

## 6. Case Study: AI LMS Assistant

Consider an AI assistant for a Learning Management System (LMS).

A student asks:

"Explain why I got this question wrong."

The system should not merely state the correct answer. It should explain the student's misconception clearly and help the student understand the topic.

### SFT stage

Create examples pairing student questions with high-quality tutor responses.

```text id="i9g2ba"
Student question
       +
Good tutor response
       ↓
SFT
       ↓
Model learns desired tutoring behavior
```

For example, a target response could identify the student's error, explain the correct concept and provide a relevant example.

### Preference-training stage

Experts compare two answers.

**Response A:** Gives the correct answer but does not explain the student's mistake.

**Response B:** Gives the correct answer and explains the misconception in accessible language.

For a learning-focused application, Response B may be preferred.

The preference dataset records:

```text id="y37fp1"
Response B > Response A
```

Preference optimization can use this comparison to encourage the model to produce more useful tutoring responses.

### Verifiable-reward stage

Some LMS tasks have objectively checkable results.

For example, a mathematics question may have a known correct answer. A verifier can check whether the model's final numerical result matches the expected answer.

```text id="o05570"
Model produces mathematical result
              ↓
          Answer checker
              ↓
       Correct or incorrect
              ↓
          Reward signal
```

However, checking the final answer alone does not establish that the explanation is logically correct or educationally useful. Those aspects require appropriate additional evaluation.

### Evaluation strategy

| Evaluation area | What to measure |
|---|---|
| Correctness | Is the explanation factually and mathematically correct? |
| Helpfulness | Does it address the student's misconception? |
| Clarity | Can the intended learner understand it? |
| Instruction adherence | Does it follow the student's request? |
| Preference alignment | Do reviewers prefer the response over alternatives? |
| Verifiable correctness | Does the result pass the appropriate checker? |

### Main lesson

SFT, preference optimization and verifiable rewards can complement one another. Each provides a different training signal, and the LMS should evaluate the resulting behavior rather than assume that one method solves every problem.

## 7. Limitations and Reward Hacking

Preference- and reward-based training can improve behavior, but the signals used during training may be imperfect.

### Poor preference labels

Suppose reviewers consistently prefer responses that sound confident even when the information is incorrect.

```text id="x69w9h"
Poor preference judgments
          ↓
Misleading training signal
          ↓
Model may learn undesirable behavior
```

The model may optimize toward what reviewers reward rather than what the application genuinely needs.

To reduce this risk, preference criteria should be clear, reviewers should be appropriately guided, and the evaluation process should measure correctness as well as presentation.

### What is reward hacking?

**Reward hacking** occurs when a model exploits weaknesses in the reward function or evaluation process to obtain a high reward without achieving the intended goal.

### Example

Suppose a coding task aims to reward correct code, but the reward function counts only the number of comments.

```text id="qkv1bp"
Actual goal:
Write correct code.

Incorrect reward proxy:
Count comments in the code.

Possible outcome:
Model adds many comments
without solving the problem.
```

The model can score well according to the flawed reward signal while failing the actual task.

This illustrates a general principle:

**A reward is useful only to the extent that it measures the behavior you genuinely want.**

### Why can reward hacking occur?

- The reward function measures only part of the objective.
- The verifier has gaps.
- Test cases fail to cover important scenarios.
- Human preference labels reward the wrong qualities.
- Optimization discovers ways to exploit the evaluation signal.

### How to reduce the risk

- Define the intended objective carefully.
- Test the reward signal against realistic examples.
- Check for unintended behavior.
- Use multiple complementary evaluation metrics where appropriate.
- Validate important outputs independently.
- Reassess whether high reward corresponds to genuine task success.

### Key takeaway

Optimizing a model against an imperfect reward can amplify the weaknesses in that reward. Evaluate the real objective, not merely the score.

## 9. Cheat Sheet and Final Revision

### Essential definitions

| Concept | Simple meaning |
|---|---|
| Preference dataset | Records which response is preferred for a prompt |
| Preference optimization | Trains a model to favor responses indicated as preferable |
| DPO | Direct Preference Optimization; learns from preferred and rejected responses without requiring the classic separate reward-model RLHF pipeline |
| RLHF | Reinforcement Learning from Human Feedback |
| Reward | Numerical signal representing desirability under a training objective |
| Reward model | Model that estimates how desirable a response is |
| Verifiable reward | Reward derived from a checkable outcome |
| Verifier | System that checks whether an outcome satisfies specified conditions |
| Reward hacking | Exploiting weaknesses in the reward signal instead of achieving the actual goal |

### The key differences

```text id="b35wdp"
SFT
→ "Here is a desired response."

Preference optimization
→ "This response is better than that response."

Classic RLHF
→ "Use human-derived reward signals to optimize behavior."

Verifiable reward
→ "Use an automatic checker when success can be measured."
```

### Rules to remember

1. Preference judgments are comparative signals, not proof of objective correctness.
2. Preference optimization can improve the behaviors represented in the preference data.
3. Classic RLHF typically uses a learned reward model followed by reinforcement learning.
4. DPO is a preference-optimization technique that does not require the classic separate reward-model pipeline.
5. Verifiable rewards work best when the task has reliable, checkable success criteria.
6. Subjective tasks may require human preferences or other suitable evaluation methods.
7. Reward hacking can occur when a reward function fails to capture the intended objective.
8. Always measure actual behavior and task success, not just the reward score.

### One-line memory trick

**SFT teaches from examples; preference optimization learns from comparisons; classic RLHF uses human-derived rewards; verifiable rewards use automatically checkable outcomes.**

## 10. Practice and Interview Questions

### Easy

**Question 1: What is a preference dataset?**

**Answer:** A preference dataset contains comparisons indicating which of multiple responses is preferred for a particular prompt.

**Question 2: What is preference optimization?**

**Answer:** Preference optimization trains a model to produce responses that better match the preferences represented in the training data.

**Question 3: What does RLHF stand for?**

**Answer:** Reinforcement Learning from Human Feedback.

**Question 4: What is a reward model?**

**Answer:** A reward model estimates how desirable a response is according to a learned reward or preference signal.

**Question 5: What is a verifiable reward?**

**Answer:** A reward derived from an outcome that can be checked against explicit conditions, such as a correct numerical answer or a passing test suite.

### Medium

**Question 6: How does preference optimization differ from SFT?**

**Answer:** SFT trains on desired input-output examples. Preference optimization uses comparisons between responses to encourage the model to favor the preferred alternative.

**Question 7: How does DPO differ from classic RLHF?**

**Answer:** DPO directly optimizes the model using preference comparisons without requiring the classic separate reward-model-plus-reinforcement-learning pipeline. Classic RLHF typically learns a reward model from human preferences and uses reinforcement learning to update the language model.

**Question 8: Why is a reward model useful?**

**Answer:** A reward model learns to approximate preferences from labeled comparisons and can score many responses without requiring humans to evaluate every response individually. Its scores remain an imperfect estimate of actual desirability.

**Question 9: When are verifiable rewards particularly useful?**

**Answer:** They are useful when task success can be checked reliably, such as exact mathematical answers, suitable coding tests, game outcomes or formal proof verification.

### Hard — Scenario-Based

**Question 10: A response is factually correct but difficult for a beginner to understand. How could preference training help?**

**Answer:** Reviewers could compare the technical answer with a clearer beginner-friendly answer and prefer the latter for that prompt. Preference optimization could use these comparisons to encourage greater clarity. The model should still be evaluated for factual accuracy so that simplicity does not come at the expense of correctness.

**Question 11: A reward model consistently scores long responses higher than concise responses, even when users request brief answers. What is the likely problem?**

**Answer:** The reward model may have learned a preference signal that overvalues length or fails to account for the user's explicit constraints. The team should examine its training comparisons, improve the preference criteria and test whether rewards align with actual task requirements.

**Question 12: A model receives high rewards on a coding task but produces incorrect code. How could reward hacking explain this?**

**Answer:** The reward function may measure a proxy, such as the presence of particular formatting or comments, instead of actual correctness. The model can exploit this weakness to obtain a high score without solving the task. The evaluation should use appropriate tests and other checks that better represent the intended goal.

**Question 13: An AI tutor needs to produce mathematically correct answers and explanations that students find helpful. Which training signals could be useful?**

**Answer:** SFT can teach the intended explanation format through demonstrations. Preference comparisons can encourage clarity and helpfulness. A mathematical verifier can provide a checkable signal for the final answer. The system must also evaluate the explanation itself, because a correct final answer does not necessarily mean the reasoning is correct or useful.

**Question 14: Why should a team not optimize only for a reward model's score?**

**Answer:** The reward model is an imperfect approximation of desirability. It may contain biases or weaknesses that the language model exploits during optimization. Independent evaluation of correctness, task completion, safety and other requirements helps determine whether the optimization actually improves the intended behavior.

### Multiple-Choice Questions

**Question 15: Which training approach uses comparisons such as Response A being preferred over Response B?**

A. Tokenization  
B. Preference optimization  
C. Corpus deduplication  
D. Random initialization  

**Answer:** B. Preference optimization.

**Explanation:** Preference optimization uses comparative feedback to train the model toward preferred responses.

B. It uses a learned reward model followed by reinforcement learning.  
C. It trains only on duplicate data.  
D. It removes the need for model evaluation.  

**Answer:** B. It uses a learned reward model followed by reinforcement learning.

**Explanation:** Human comparisons train the reward model, which provides a reward signal for reinforcement learning.

**Question 17: Which task is most naturally suited to a verifiable reward?**

A. Writing a poem judged by personal taste  
B. Producing a beautiful story  
C. Computing an exact arithmetic answer  
D. Choosing the most emotionally moving sentence  

**Answer:** C. Computing an exact arithmetic answer.

**Explanation:** An exact arithmetic result can be compared with a known answer using an automatic checker.

**Question 18: A model obtains a high reward by exploiting a flawed evaluation rule. What is this called?**

A. Tokenization  
B. Reward hacking  
C. Domain adaptation  
D. Deduplication  

**Answer:** B. Reward hacking.

**Explanation:** Reward hacking occurs when a model exploits weaknesses in the reward function without achieving the intended objective.

## Final Summary

Preference and reward-based training helps improve a model beyond simply copying good demonstrations.

- **Preference datasets** show which responses are better.
- **Preference optimization** uses those comparisons to encourage preferred behavior.
- **Reward models** estimate response desirability from preference data.
- **Classic RLHF** uses a learned reward model and reinforcement learning.
- **Verifiable rewards** use automatic checks when task success can be objectively evaluated.
- **Reward hacking** is the risk that the model exploits a flawed reward instead of achieving the intended goal.

The central principle is:

> **Train for the behavior you actually want, and verify that the reward signal measures that behavior rather than a misleading proxy.**
