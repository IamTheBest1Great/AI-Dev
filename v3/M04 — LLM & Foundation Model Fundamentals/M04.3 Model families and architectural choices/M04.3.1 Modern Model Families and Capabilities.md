## 1. Introduction to Modern AI Model Families

### 1.1 What are modern AI model families?

AI models are systems designed to process information and perform particular tasks. Different model families specialize in different capabilities, such as understanding text, interpreting images, processing audio, retrieving relevant information, or generating new content.

A common misconception is:

> AI model = chatbot.

A chatbot is just one application of AI models. Many AI models do not produce conversational responses at all.

For example, an embedding model produces numerical vectors, a speech model can convert audio into text, and a video generation model creates video content.

### 1.2 Major categories of AI models

| Model category                 | Main purpose                          | Typical output                 |
| ------------------------------ | ------------------------------------- | ------------------------------ |
| General-purpose language model | Understand and generate text          | Text or code                   |
| Reasoning-oriented model       | Solve complex, multi-step problems    | Answers or actions             |
| Vision-language model          | Understand images with language       | Text or structured information |
| Audio-language model           | Understand audio with language        | Answers or other outputs       |
| Embedding model                | Represent meaning numerically         | Vectors                        |
| Reranker                       | Order results by relevance            | Scores or ranked results       |
| Speech model                   | Recognize or generate speech          | Text or audio                  |
| Image generation model         | Create or edit images                 | Images                         |
| Video generation model         | Create or edit videos                 | Videos                         |
| Small/local model              | Support efficient or local deployment | Depends on the model           |
| Mixture-of-Experts model       | Activate selected expert components   | Depends on the model           |

These categories describe different aspects of AI. They are not necessarily mutually exclusive.

For example, a model may simultaneously be a language model, support image inputs, have strong reasoning capabilities, and use a Mixture-of-Experts architecture.

### 1.3 Three fundamental questions

When evaluating an AI model, distinguish among three questions.

Question 1: What can the model do?

This describes its capabilities, such as reasoning, vision, speech recognition, or image generation.

Question 2: How is the model built?

This describes its architecture, such as a Transformer, dense architecture, or Mixture-of-Experts architecture.

Question 3: Where does the model run?

This describes its deployment, such as a cloud API, a local computer, or an edge device.

These are related, but they are not interchangeable.

```
                    AI MODEL
                       |
          +------------+------------+
          |            |            |
     Capability    Architecture  Deployment
          |            |            |
     What it does  How it's built Where it runs
```

### 1.4 Why these distinctions matter

Suppose you are building an AI application that analyzes invoices.

You may need:

- A vision-language model to interpret invoice images.
- An embedding model to retrieve relevant reference documents.
- A reranker to identify the most relevant documents.
- A language model to produce the final response.
- A local deployment if data must remain within your infrastructure.

The system does not necessarily need one model to perform every operation.

Key takeaway: Choose models based on the task, input and output requirements, architecture, and deployment constraints rather than assuming that one chatbot model can efficiently handle everything.

## 2. General-Purpose Language Models

### 2.1 Definition

A general-purpose language model is an AI model primarily designed to understand and generate language across a broad range of tasks.

Instead of specializing in only one task, it can often handle writing, coding, summarization, translation, explanation, and question answering.

### 2.2 Common tasks

General-purpose language models can perform tasks such as:

- Answering questions.
- Writing emails and other documents.
- Summarizing long text.
- Translating languages.
- Generating and explaining code.
- Extracting information from text.
- Rewriting content.
- Conducting conversations.

For example:

Input:

```
Explain Docker in simple terms.
```

Possible output:

```
Docker packages an application and its dependencies
into a container so it can run consistently across
different environments.
```

The model receives a language input and generates a language output.

### 2.3 How language generation works

A simplified language-model pipeline is:

```
Input text
    |
    v
Tokenization
    |
    v
Tokens
    |
    v
Transformer model
    |
    v
Next-token prediction
    |
    v
Generated text
```

Tokenization converts input text into tokens, which may represent words, parts of words, or other text units.

The model processes token representations and predicts subsequent tokens. Repeating this process produces a sequence of tokens that forms the generated response.

### 2.4 Why are they called general-purpose?

One model can support several different tasks without requiring a separate model for every task.

```
              General-purpose model
                        |
          +-------------+-------------+
          |             |             |
          v             v             v
        Coding        Writing     Translation
          |             |             |
          v             v             v
      Debug code     Draft email  English -> Hindi
```

Compare this with a collection of narrowly specialized systems:

```
Model A -> Translation only
Model B -> Summarization only
Model C -> Coding only
```

A general-purpose model can reduce the need to maintain separate task-specific models, although specialized models may still outperform it on particular tasks.

### 2.5 When should you use one?

Use a general-purpose language model when an application needs a broad text assistant capable of handling multiple related tasks.

Examples include a coding assistant, document summarizer, technical tutor, or customer-support chatbot.

### 2.6 Important limitation

General-purpose capability does not guarantee optimal performance on every task.

A model may be good at explaining a programming concept but less suitable for a demanding mathematical proof or a high-precision retrieval task. Model selection should consider the difficulty and accuracy requirements of the specific task.

Key takeaway: A general-purpose language model provides broad language capabilities rather than specializing exclusively in one operation.

## 3. Reasoning-Oriented Models

### 3.1 Definition

A reasoning-oriented model is designed or optimized to perform well on problems that require multiple steps of logical processing.

These problems often involve dependencies, constraints, calculations, planning, or evaluating several possible solutions.

### 3.2 Ordinary language task versus complex reasoning

A simple language task may require a relatively direct response:

```
Question
    |
    v
Answer
```

A complex problem may require several connected operations:

```
Problem
   |
   v
Understand the requirements
   |
   v
Break the problem into steps
   |
   v
Evaluate possibilities
   |
   v
Check constraints
   |
   v
Determine a solution
   |
   v
Answer
```

This diagram describes the general problem-solving process; it does not imply that every reasoning model exposes or follows these exact internal steps.

### 3.3 Example: comparing train speeds

Consider two trains:

- Train A travels 120 km in 2 hours.
- Train B travels 180 km in 3 hours.

Speed is calculated as:

\\[ \text{Speed}=\frac{\text{Distance}}{\text{Time}} \\]

For Train A:

\\[ \frac{120}{2}=60\text{ km/h} \\]

For Train B:

\\[ \frac{180}{3}=60\text{ km/h} \\]

Both trains have the same average speed.

This example requires only straightforward calculation. A harder problem might include several schedules, resource limits, conflicting requirements, and task dependencies. Finding a valid solution would require more extensive reasoning.

### 3.4 Where are reasoning-oriented models useful?

They are particularly useful for:

- Mathematics and complex calculations.
- Algorithms and difficult coding problems.
- Planning with multiple constraints.
- Scientific problem solving.
- Multi-step logical analysis.
- Comparing possible solutions.
- Debugging complicated failures.

### 3.5 Are reasoning models a completely separate type of AI?

Not necessarily.

A reasoning-oriented model can still be a language model. The distinction describes a stronger emphasis on reasoning and problem solving, not an entirely unrelated family of AI.

```
Language model
      +
Greater emphasis on complex problem solving
      |
      v
Reasoning-oriented model
```

Modern models can combine general-purpose language capabilities with stronger reasoning capabilities.

### 3.6 Reasoning capability does not guarantee correctness

A model's reasoning-oriented design does not mean every answer will be correct.

Errors can still arise from incorrect assumptions, missing information, flawed calculations, or incomplete use of context. Important results should be validated, especially in high-stakes or precision-sensitive applications.

Key takeaway: Use reasoning-oriented models when a task involves complex dependencies, multi-step logic, difficult problem solving, or planning—not merely because a question is expressed in natural language.

## 4. Vision-Language Models (VLMs)

### 4.1 Definition

A Vision-Language Model (VLM) is a model that can process visual information together with language.

- Vision refers to visual information such as photographs, screenshots, charts, and diagrams.
- Language refers to textual information and instructions.

A VLM can use visual input to answer a question expressed in text.

### 4.2 Language models versus vision-language models

A conventional text-oriented workflow can be represented as:

```
Text input
    |
    v
Language model
    |
    v
Text output
```

A vision-language workflow can accept both an image and a text instruction:

```
Image + Text instruction
            |
            v
    Vision-language model
            |
            v
        Text answer
```

### 4.3 Example: analyzing an error screenshot

Suppose you upload a screenshot showing an error in a web application and ask:

> What is wrong here?

A VLM may interpret the visible error message and explain its likely meaning.

For a software-development application, this may help with:

- Understanding UI screenshots.
- Interpreting error messages.
- Inspecting diagrams.
- Analyzing charts.
- Describing photographs.
- Reading visible text in images.
- Extracting information from document images.

The model can also use the accompanying text instruction to focus its analysis on a particular region or question.

### 4.4 Example: interpreting a revenue chart

Suppose an image contains a chart showing revenue over time.

You ask:

> What happened to revenue?

The model must interpret the chart's visual structure and use that information to formulate an answer.

This differs from answering based only on a written description of the chart.

### 4.5 Why are VLMs important?

Real-world information is not restricted to text.

An AI application may receive:

```
Photographs
Screenshots
Charts
Diagrams
Scanned documents
Text instructions
```

A VLM helps the application reason about the visual and textual information together.

### 4.6 Limitations

Visual interpretation may be affected by image quality, small text, complicated layouts, ambiguous diagrams, or inaccurate readings of numerical values.

When an application requires exact numerical extraction, important visual results should be checked against the original data or a suitable structured extraction process.

Key takeaway: A VLM primarily helps an AI system understand visual information in combination with language; it is not the same as an image generation model.

## 5. Audio-Language Models

### 5.1 Definition

An audio-language model works with audio and language to support tasks involving spoken content or other sounds.

A general workflow is:

```
Audio recording + Question
             |
             v
     Audio-capable model
             |
             v
   Understand relevant content
             |
             v
     Answer / summary / analysis
```

### 5.2 Example: summarizing a meeting

Suppose you provide a meeting recording named `meeting.mp3` and ask:

> What were the three action items?

An audio-capable model can analyze the spoken information and identify the relevant tasks, decisions, and follow-ups.

Potential uses include:

- Meeting summaries.
- Questions about recordings.
- Understanding spoken conversations.
- Processing spoken instructions.
- Analyzing audio events.
- Combining audio understanding with textual questions.

### 5.3 Audio is broader than speech

Audio can contain many kinds of information:

```
Audio
  |
  +-- Human speech
  +-- Music
  +-- Traffic sounds
  +-- Dogs barking
  +-- Applause
  +-- Machinery
  +-- Background noise
```

Therefore, audio understanding is broader than speech recognition.

Speech recognition focuses on determining what was spoken. General audio understanding can also involve identifying or interpreting non-speech sounds.

### 5.4 When would you use an audio-language model?

Use one when your application must understand the contents of a recording rather than simply convert speech into text.

For example, a meeting assistant may need to identify decisions and explain them. A speech transcription system may only need to produce the words spoken during the meeting.

These tasks overlap, but their objectives differ.

Key takeaway: Audio-language models focus on understanding audio in context, potentially including both speech and non-speech sound.

## 6. Embedding Models

### 6.1 Definition

An embedding model converts information into a numerical vector that represents useful features of that information, often its semantic meaning.

A vector is an ordered collection of numbers.

For example, a text embedding might conceptually look like this:

```
Input:
"The cat is sleeping."

Embedding:
[0.12, -0.43, 0.87, 0.19, ...]
```

The displayed numbers are illustrative, not actual values from a particular model.

The vector may contain hundreds or thousands of dimensions, depending on the model.

### 6.2 Why are embeddings useful?

Computers need a representation that makes it possible to compare information efficiently.

Keyword-based matching searches for overlapping words. Embedding-based retrieval can help identify related meanings even when the wording differs.

For example:

```
Sentence A:
"I love dogs."

Sentence B:
"I really like puppies."

Sentence C:
"The database connection failed."
```

An embedding model may place the first two sentences closer together in vector space because their meanings are related.

The third sentence would generally represent a different semantic topic.

Important: Similarity is not a guarantee of identical meaning. Results depend on the model, data, representation, and similarity measure.

### 6.3 How embedding-based semantic search works

Imagine that a knowledge base contains three documents:

```
Document 1: How to reset your password
Document 2: How to change your email
Document 3: How to restart your server
```

A user asks:

```
"I forgot my password. How can I get access again?"
```

The words in the question are not identical to the document heading. Nevertheless, the query expresses a similar intent to Document 1.

An embedding-based search system can retrieve Document 1 because its meaning is related to the question.

### 6.4 Embeddings in a RAG system

RAG stands for Retrieval-Augmented Generation. It combines retrieval from an external knowledge source with an AI model that generates a response.

A simplified RAG indexing pipeline is:

```
Knowledge-base documents
          |
          v
     Embedding model
          |
          v
      Document vectors
          |
          v
     Vector database
```

When a user asks a question:

```
User question
      |
      v
Embedding model
      |
      v
Query vector
      |
      v
Similarity search
      |
      v
Relevant documents
      |
      v
Language model + question
      |
      v
Generated answer
```

The document-indexing stage is typically performed ahead of the query, rather than rebuilding the entire document index for every user request.

### 6.5 Important distinction: embeddings do not normally generate answers

The primary purpose of an embedding model is to create a numerical representation suitable for tasks such as semantic search, clustering, and similarity comparison.

A language model, by contrast, is typically used to generate a natural-language response.

| Language model                                          | Embedding model                                    |
| ------------------------------------------------------- | -------------------------------------------------- |
| Produces language or code                               | Produces numerical vectors                         |
| Used for answering, explaining, writing, and generating | Used for representation and similarity-based tasks |
| Example output: `A database stores organized data.`     | Example output: `[0.13, -0.51, 0.71, ...]`         |

### 6.6 Important implementation concepts

- Vector: A list of numbers representing information.
- Vector space: The mathematical space in which those vectors are represented.
- Similarity search: A process for retrieving vectors that are similar to a query vector.
- Vector database: A system designed to store and retrieve vectors efficiently.
- Semantic search: Searching based on meaning or intent rather than exact keyword matches alone.

Key takeaway: Embeddings provide a numerical representation of information that enables semantic comparison and retrieval.

## 7. Rerankers

### 7.1 Definition

A reranker is a model or component that evaluates a set of retrieved candidates and reorders them according to their relevance to a query.

Embedding retrieval is often used to search a large collection quickly. A reranker can then examine a smaller candidate set to determine which results are most useful.

### 7.2 Why do we need rerankers?

Suppose a user asks:

```
"How do I reset my password?"
```

A retrieval system returns 20 potentially relevant documents.

Some may discuss password resets directly. Others might discuss account security, changing usernames, or recovering access in less relevant ways.

The system needs to identify which of the 20 documents best addresses the actual question.

A reranker helps refine the results.

### 7.3 Typical retrieval and reranking pipeline

```
User query
    |
    v
Embedding model
    |
    v
Retrieve candidate documents
    |
    v
Reranker
    |
    v
Select highest-ranked documents
    |
    v
Language model
    |
    v
Final answer
```

For example, retrieval might return 20 candidate documents, after which the reranker selects the five most relevant documents for the next stage.

The numbers are illustrative; a real system may use different candidate and result counts.

### 7.4 How does a reranker work?

A reranker evaluates the relationship between a query and each candidate document.

Conceptually:

```
Query:
"How do I reset my password?"

Candidate A -> Relevance score: 0.95
Candidate B -> Relevance score: 0.81
Candidate C -> Relevance score: 0.23
Candidate D -> Relevance score: 0.12
```

The system can use these scores to order the candidates.

These scores are illustrative. Their interpretation and calibration depend on the model.

### 7.5 Embedding model versus reranker

| Feature           | Embedding model                      | Reranker                           |
| ----------------- | ------------------------------------ | ---------------------------------- |
| Main function     | Represents information as vectors    | Scores query-document relevance    |
| Typical position  | Initial retrieval                    | After retrieval                    |
| Primary objective | Find semantically similar candidates | Improve the ordering of candidates |
| Typical workload  | Searching large collections          | Evaluating a smaller candidate set |
| Output            | Vectors                              | Relevance scores or ranking        |
| Mental model      | Retrieve                             | Refine the ranking                 |

### 7.6 Analogy

Imagine searching a library.

An embedding-based system identifies 100 books that appear related to your question.

A reranker then examines those books and determines which five most directly answer the question.

The embedding model helps discover candidates; the reranker improves the selection.

### 7.7 When should you use a reranker?

Consider using one when:

- Initial retrieval returns too many weakly relevant results.
- Several documents use similar terminology but answer different questions.
- The quality of retrieved context is important to a RAG application.
- You need better relevance ordering before sending documents to a language model.

A reranker introduces additional computation, so its benefit should be evaluated against latency and cost.

Key takeaway: Embeddings help retrieve candidates; rerankers refine their relevance ranking.

## 8. Speech Models: ASR and TTS

### 8.1 Definition

Speech models are designed for tasks involving human speech, particularly converting speech into text or text into speech.

Two major speech-processing tasks are:

1. Speech-to-Text (ASR).
2. Text-to-Speech (TTS).

### 8.2 Speech-to-Text (ASR)

ASR stands for Automatic Speech Recognition.

It converts spoken language into text.

```
Person speaks
     |
     v
Speech recognition model
     |
     v
Transcribed text
```

Example:

Input: A person says, "How are you?"

Output: `How are you?`

Common applications include:

- Voice typing.
- Meeting transcription.
- Automatic subtitles.
- Call-center transcription.
- Voice-controlled applications.
- Spoken search queries.

### 8.3 Text-to-Speech (TTS)

TTS stands for Text-to-Speech.

It converts written text into synthesized speech.

```
Written text
     |
     v
Text-to-speech model
     |
     v
Generated audio
```

Example:

Input: `Welcome to the application.`

Output: An audio recording speaking those words.

TTS is useful for voice assistants, accessibility tools, spoken notifications, and applications that read content aloud.

### 8.4 Speech models versus audio-language models

These categories overlap, but their primary objectives differ.

| Feature        | Speech model                    | Audio-language model                           |
| -------------- | ------------------------------- | ---------------------------------------------- |
| Main focus     | Speech recognition or synthesis | Understanding audio in context                 |
| Typical input  | Speech or text                  | Audio, often with text instructions            |
| Typical output | Text or synthesized speech      | Answers, analysis, summaries, or other outputs |
| Example        | Transcribe a meeting            | Identify decisions discussed in the meeting    |

A speech model can transcribe a meeting without necessarily summarizing the decisions. An audio-language model can potentially use the meeting's audio to answer questions about those decisions.

### 8.5 Relationship between speech and audio understanding

```
                    Speech AI
                       |
             +---------+---------+
             |                   |
             v                   v
        Speech -> Text       Text -> Speech
            ASR                  TTS

          Broader audio understanding
                       |
                       v
            Interpret audio content
                       |
                       v
               Answer questions
```

There is significant overlap between modern speech and audio-capable systems. The distinction is based on their primary tasks, not a strict separation between all available implementations.

Key takeaway: ASR converts speech to text, TTS converts text to speech, and audio-language models can support broader audio understanding.

## 9. Image Generation Models

### 9.1 Definition

An image generation model creates images from instructions or other supported inputs. Depending on the model, it may also edit existing images.

Its primary objective is creating visual content rather than understanding an image and describing it.

### 9.2 Basic workflow

```
Text prompt / supported image input
                 |
                 v
        Image generation model
                 |
                 v
           Generated image
```

Example prompt:

```
A futuristic city at sunset,
cinematic lighting, realistic style.
```

The model produces an image based on the prompt and its learned capabilities.

### 9.3 What can image generation models do?

Depending on the model, they may support:

- Generating images from text.
- Editing existing images.
- Adding or removing objects.
- Changing image backgrounds.
- Transforming artistic styles.
- Producing illustrations.
- Creating concept art.
- Modifying elements of a visual design.

### 9.4 Vision versus image generation

This is a particularly important distinction.

Vision-language model:

```
Input image
     |
     v
Understand visual information
     |
     v
Text answer
```

Example question:

"What is wrong with this screenshot?"

Image generation model:

```
Text prompt
     |
     v
Create visual content
     |
     v
Generated image
```

Example instruction:

"Create a futuristic dashboard."

The first workflow focuses on interpretation; the second focuses on creation.

### 9.5 When should you use an image generation model?

Use one when an application needs to create or edit visual assets, such as illustrations, product concepts, marketing images, or design mockups.

Use a vision-language model when the application needs to understand existing visual content.

Key takeaway: Image understanding and image generation are different tasks, even though some modern systems support both.

## 10. Video Generation Models

### 10.1 Definition

A video generation model creates moving visual content from supported inputs, which may include text prompts, images, or existing video.

A simplified workflow is:

```
Text / image / supported video input
                 |
                 v
        Video generation model
                 |
                 v
            Generated video
```

Example prompt:

```
A robot walking through a
futuristic city at night.
```

The intended output is a video depicting the described scene.

### 10.2 Why is video generation more complex than image generation?

An image represents a single visual moment. A video represents a sequence of moments that must form a coherent visual experience.

```
Frame 1 -> Frame 2 -> Frame 3 -> Frame 4 -> ...
```

The model must handle several related requirements:

| Challenge              | Meaning                                                    |
| ---------------------- | ---------------------------------------------------------- |
| Motion consistency     | Objects should move coherently between frames              |
| Object consistency     | Objects should retain their identity                       |
| Character consistency  | A character should remain recognizable across the sequence |
| Scene consistency      | The environment should not change unpredictably            |
| Temporal relationships | Events should occur in a plausible order                   |

For example, a character walking across a room should not unexpectedly change appearance or position between adjacent frames.

### 10.3 Image generation versus video generation

| Feature              | Image generation                 | Video generation                          |
| -------------------- | -------------------------------- | ----------------------------------------- |
| Main output          | Static image                     | Moving visual sequence                    |
| Primary challenge    | Visual quality and composition   | Visual quality plus temporal consistency  |
| Important properties | Objects, lighting, style, layout | Objects, motion, scene continuity, timing |
| Example              | A futuristic car in Mumbai       | A futuristic car driving through Mumbai   |

Key takeaway: Video generation extends visual generation to time-dependent content, making motion and consistency important additional challenges.

## 11. Small and Local Models

This section shifts from what a model can do to how it can be deployed.

### 11.1 What is a small model?

A small model generally has fewer parameters and lower computational requirements than a very large model.

Parameters are learned numerical values in a model.

For illustration, the source material gives these approximate examples:

- Large model: 100B+ parameters.
- Small model: 1B–10B parameters.

Here, `B` means billion.

These ranges are illustrative, not universal definitions. Whether a model is considered small depends on its architecture, task, hardware requirements, and comparison group.

### 11.2 Why use a smaller model?

Potential benefits include:

- Faster inference for suitable workloads.
- Lower computational cost.
- Reduced memory requirements.
- Easier deployment.
- Greater suitability for local hardware.
- More practical deployment on edge devices.
- Potentially lower latency and fewer infrastructure dependencies.

However, these benefits depend on the implementation and workload.

### 11.3 What is a local model?

A local model runs on your own device or infrastructure rather than sending every inference request to a remote AI service.

Local deployment can use a laptop, workstation, on-premises server, or supported edge device.

Local model workflow:

```
Your computer
     |
     v
Local AI model
     |
     v
Response
```

Cloud API workflow:

```
Your computer
     |
     v
Network request
     |
     v
Remote AI service
     |
     v
Response
```

A local model does not inherently have to be small, but smaller models are often more practical on consumer hardware.

### 11.4 Why run models locally?

Privacy: Sensitive data can potentially remain within your environment rather than being transmitted to an external service.

Cost: You may avoid per-request API charges, although you still incur hardware, electricity, maintenance, and operational costs.

Offline usage: A downloaded model may run without an internet connection.

Latency: Local inference can reduce network overhead and may respond quickly for suitable workloads.

### 11.5 Important trade-offs

| Consideration             | Small/local model                          | Large remote model                                            |
| ------------------------- | ------------------------------------------ | ------------------------------------------------------------- |
| Compute requirements      | Usually lower                              | Often higher                                                  |
| Hardware constraints      | Important                                  | Primarily handled by the provider                             |
| Internet dependency       | Can be independent of internet after setup | Usually requires network access                               |
| Privacy                   | Data can remain local                      | Data handling depends on the remote service and configuration |
| Operating costs           | Hardware and maintenance                   | API charges or service costs                                  |
| Difficult reasoning tasks | May have weaker performance                | May offer stronger capabilities, depending on the model       |

These are general tendencies, not guaranteed outcomes.

Model architecture, training quality, quantization, hardware acceleration, and task difficulty all influence actual performance.

### 11.6 Choosing between local and cloud deployment

For example, imagine a document-processing application used inside an organization.

If documents are highly sensitive and the organization has suitable hardware, local inference may be attractive.

If the application needs capabilities that its local hardware cannot support efficiently, a cloud model may be more suitable, subject to security and data-handling requirements.

Key takeaway: Small/local deployment is primarily a decision about resource efficiency, privacy, cost, latency, and infrastructure—not a separate task capability.

## 12. Mixture-of-Experts (MoE) Models

### 12.1 Definition

A Mixture-of-Experts (MoE) model contains multiple components called experts. A routing mechanism selects a subset of those experts for a particular input or token.

Instead of activating every expert for every operation, the model can direct the computation to selected experts.

### 12.2 Intuitive analogy

Imagine a company with three specialists:

- An engineer.
- A designer.
- An accountant.

A manager decides which specialist is needed for a particular task.

If the request is "Fix this database problem," the engineer may be the most relevant specialist. The designer and accountant do not necessarily need to participate in that task.

An MoE model uses a related routing concept.

The analogy is useful for understanding specialization and routing, although neural-network experts do not necessarily correspond to human professions or explicit, fixed areas of expertise.

### 12.3 How MoE works

A simplified MoE workflow is:

```
Input
  |
  v
Router
  |
  v
Select a subset of experts
  |
  v
Selected experts process the input
  |
  v
Combine expert outputs
  |
  v
Continue model computation
```

For example, a routing decision may activate Expert 2 and Expert 5 while leaving other experts inactive for that particular operation.

The actual selection mechanism depends on the architecture.

### 12.4 Total parameters versus active parameters

This is an important concept when reading model specifications.

Total parameters describe the model's overall parameter count.

Active parameters describe the parameters involved in a particular computation or token, depending on the model's architectural definition.

Consider this illustrative MoE model:

```
Total parameters  = 100B
Active parameters = 20B
```

The model contains 100 billion parameters overall, but approximately 20 billion may be active for the relevant token computation under the example's assumptions.

This does not mean the model becomes a 20B-parameter model in every sense. Its total capacity and storage requirements remain related to the full architecture.

### 12.5 Why use MoE?

Potential benefits include:

- Greater total model capacity.
- Specialized computational pathways.
- More efficient use of computation for some workloads.
- Scaling model capacity without activating every parameter for every token.

### 12.6 Engineering challenges

MoE architectures introduce additional complexity, including:

Routing: The system must select appropriate experts.

Load balancing: Work should be distributed so that a small subset of experts does not become excessively overloaded.

Distributed training and inference: Experts may be distributed across multiple devices.

Communication overhead: Distributed execution can require communication among devices, potentially reducing the benefit of sparse activation.

Therefore, MoE is an architectural choice with trade-offs, not an automatic guarantee of superior performance.

### 12.7 Dense models versus MoE models

A simplified dense-model workflow is:

```
Input
  |
  v
Dense network computation
  |
  v
Output
```

In a conventional dense Transformer, the main dense network layers generally apply their computations across the model's active pathway for each token.

A simplified MoE workflow is:

```
Input
  |
  v
Router
  |
  v
Selected experts
  |
  v
Output
```

| Feature                   | Dense model                                            | MoE model                                                |
| ------------------------- | ------------------------------------------------------ | -------------------------------------------------------- |
| Main architecture concept | Dense computation through the network layers           | Routing to selected expert components                    |
| Expert routing            | Not a defining feature                                 | A defining feature                                       |
| Active parameters         | Dense layers participate according to the architecture | Only selected expert parameters may be active            |
| Engineering complexity    | Does not require MoE expert routing                    | Includes routing and expert-management complexity        |
| Main consideration        | Compute and capacity of the dense architecture         | Capacity, sparse computation, routing, and communication |

The table describes the broad architectural distinction; exact computational details depend on the implementation.

### 12.8 When should you choose an MoE model?

MoE may be useful when a design requires substantial overall model capacity while limiting the amount of expert computation used for each token.

The decision should also account for deployment hardware, communication overhead, latency, expert utilization, and implementation complexity.

Key takeaway: MoE combines multiple expert components with routing that selects a subset for particular computations. Its defining idea is conditional activation rather than simply having a large number of parameters.

## 13. Model Categories, Capabilities, Architecture, and Deployment

### 13.1 Capability versus architecture versus deployment

These three concepts are frequently confused in AI discussions.

#### Capability: What can the model do?

Examples include:

- Reasoning.
- Image understanding.
- Audio understanding.
- Speech generation.
- Image generation.
- Semantic retrieval.

#### Architecture: How is the model designed?

Examples include:

- Transformer architecture.
- Dense model.
- Mixture-of-Experts architecture.

#### Deployment: Where and how does the model run?

Examples include:

- Cloud API.
- Local machine.
- Edge device.
- On-premises infrastructure.

The relationship is:

```
Capability
    |
    | describes
    v
What the model can do

Architecture
    |
    | describes
    v
How the model is internally designed

Deployment
    |
    | describes
    v
Where/how the model executes
```

These dimensions are independent enough that you must evaluate each separately.

For example, a model can have language and vision capabilities, use a Transformer architecture with MoE components, and be deployed through a cloud API.

### 13.2 Model categories can overlap

Do not assume that every model belongs to only one category.

Consider these conceptual examples.

Model A

```
Language model
    |
    +-- Reasoning capable
    +-- Vision capable
    +-- MoE architecture
```

Model B

```
Language model
    |
    +-- Small
    +-- Suitable for local deployment
```

Model C

```
Multimodal model
    |
    +-- Audio capable
    +-- Language capable
    +-- Speech capable
```

These are examples of overlapping properties, not claims about particular commercial models.

### 13.3 Why classification requires multiple dimensions

Suppose someone tells you that a model is "large," "reasoning capable," and "multimodal."

Those labels answer different questions:

| Label             | What it tells you                                   |
| ----------------- | --------------------------------------------------- |
| Large             | Something about model size or resource requirements |
| Reasoning capable | Something about problem-solving capabilities        |
| Multimodal        | Something about supported information types         |
| MoE               | Something about architecture                        |
| Local             | Something about deployment                          |

A model can have several of these labels simultaneously.

### 13.4 Dense versus MoE: the architectural dimension

Dense and MoE describe how model computation is organized, not simply what tasks the model can perform.

- A dense model follows dense computational pathways through the relevant layers.
- An MoE model routes computations to selected experts in its MoE components.

Neither label alone determines whether a model supports images, excels at reasoning, or performs well on a particular benchmark.

### 13.5 Capability versus generation

Another important distinction is the direction of information processing.

```
Understanding:
Existing information
       |
       v
Interpretation
       |
       v
Answer or analysis
```

```
Generation:
Prompt or supported input
       |
       v
Generative model
       |
       v
New content
```

A model can interpret existing content, generate new content, or support both capabilities.

Key takeaway: Classify a model along multiple dimensions instead of treating model family names as mutually exclusive labels.

## 16. Model Selection Framework

When selecting an AI model for a project, use the following five questions.

### 16.1 Question 1: What kind of information must the model understand?

Identify the input modality.

| Input requirement                | Relevant model capability                 |
| -------------------------------- | ----------------------------------------- |
| Written questions or documents   | Language                                  |
| Images, screenshots, or diagrams | Vision                                    |
| Audio recordings                 | Audio understanding                       |
| Spoken commands                  | Speech recognition or audio understanding |
| Multiple input types             | Multimodal processing                     |

### 16.2 Question 2: What must the model produce?

Identify the required output.

| Required output     | Relevant model         |
| ------------------- | ---------------------- |
| Written explanation | Language model         |
| Numerical vector    | Embedding model        |
| Relevance ranking   | Reranker               |
| Transcribed speech  | ASR model              |
| Synthesized speech  | TTS model              |
| New image           | Image generation model |
| New video           | Video generation model |

### 16.3 Question 3: How difficult is the task?

Consider the complexity of the required reasoning.

- Straightforward language tasks: A general-purpose language model may be sufficient.
- Complex, multi-step problems: A reasoning-oriented model may be more suitable.
- Semantic retrieval: An embedding model, possibly combined with a reranker, may be appropriate.
- Visual interpretation: Consider a VLM.
- Speech processing: Choose a speech model or audio-capable model according to the required operation.

### 16.4 Question 4: Where should the model run?

Determine whether the application should use cloud infrastructure or local hardware.

Consider:

- Privacy and data handling.
- Available processing power and memory.
- Latency requirements.
- Internet connectivity.
- Operating and infrastructure costs.
- Maintenance requirements.

Do not choose local deployment solely because it may improve privacy, or cloud deployment solely because the model is larger. Assess the complete workload and constraints.

### 16.5 Question 5: Does the architecture matter?

Consider architecture when evaluating performance, cost, resource requirements, or deployment complexity.

For example, a dense model and an MoE model may have different computational characteristics even when both perform language tasks.

## 19. Practice and Recall Pack

The following questions cover definitions, comparisons, practical applications, system design, and troubleshooting.

### 19.1 Easy — Fundamentals

Question 1: What is a general-purpose language model?

Answer: A general-purpose language model is designed to understand and generate language across many tasks, including writing, summarization, translation, coding, and question answering.

Question 2: What distinguishes a reasoning-oriented model from a general-purpose language model?

Answer: A reasoning-oriented model places greater emphasis on complex, multi-step problem solving. It can still possess general language capabilities.

Question 3: What is a vision-language model?

Answer: A vision-language model processes visual information together with language. It can perform tasks such as analyzing screenshots, interpreting charts, and answering questions about images.

Question 4: What does an embedding model produce?

Answer: It produces a numerical vector representing information in a form useful for tasks such as semantic search and similarity comparison.

Question 5: What is the main purpose of a reranker?

Answer: A reranker evaluates retrieved candidates and reorders them according to their relevance to a query.

Question 6: What do ASR and TTS stand for?

Answer: ASR stands for Automatic Speech Recognition and converts speech into text. TTS stands for Text-to-Speech and converts text into synthesized audio.

Question 7: What is the difference between image and video generation?

Answer: Image generation produces static visual content, while video generation produces a sequence of visual frames that must maintain reasonable motion and temporal consistency.

Question 8: What is the basic idea of an MoE model?

Answer: An MoE model contains multiple experts and uses a routing mechanism to activate a subset of them for a particular computation.

### 19.2 Medium — Applying the Concepts

Question 9: A document has been written using the words "recover account access," but a user searches for "forgot password." Why might an embedding model retrieve this document?

Answer: The two expressions can convey related meanings even though they use different words. An embedding model represents their semantic features numerically, enabling similarity-based retrieval beyond exact keyword overlap.

Question 10: Why might a RAG application use both an embedding model and a reranker?

Answer: The embedding model retrieves potentially relevant documents efficiently from a large collection. The reranker then evaluates the candidate documents against the query to improve their ordering before the most relevant context is sent to the language model.

Question 11: What is the difference between an embedding model and a language model in a typical RAG system?

Answer: The embedding model converts the query and documents into numerical vectors to support retrieval. The language model uses the question and retrieved context to generate a natural-language response.

Question 12: Why might a smaller model be suitable for an application that processes sensitive internal documents?

Answer: If the model can run on suitable local infrastructure, the application can potentially keep documents within its own environment and avoid transmitting every request to a remote API. Hardware capacity, accuracy, maintenance, and operating costs must still be considered.

Question 13: Why is video generation generally more complicated than generating a single image?

Answer: Video generation must maintain visual coherence across a sequence of frames. It must account for motion, character and object identity, scene consistency, and temporal relationships rather than producing just one visual moment.

Question 14: A model is described as multimodal, reasoning capable, and MoE. Are these descriptions contradictory?

Answer: No. They describe different dimensions. Multimodal refers to input or output modalities, reasoning capability describes problem-solving behavior, and MoE describes an architectural design.

Question 15: Why is a local model not necessarily a small model?

Answer: Local describes where the model runs, whereas small describes its relative size or resource requirements. A large model may run locally if sufficient hardware is available, and a small model may be deployed in the cloud.

### 19.3 Hard — Technical Reasoning and Architecture

Question 16: An MoE model has 100 billion total parameters and 20 billion active parameters for a particular token. Does that mean the model is equivalent to a dense 20-billion-parameter model?

Answer: No. The model retains its 100-billion-parameter overall architecture and capacity, while the specified computation activates approximately 20 billion parameters under the example's assumptions. Its behavior, storage requirements, computational pathways, and capabilities cannot be inferred from active parameter count alone.

Question 17: A semantic search system returns relevant documents, but the final AI response frequently uses documents that only partially address the question. Which architectural improvement could help?

Answer: Add or improve a reranking stage. The reranker can compare the user's query with the retrieved candidates and prioritize the documents that best address the question. Retrieval quality, candidate coverage, and answer generation should also be evaluated because reranking cannot select a good document that was never retrieved.

Question 18: Why might a highly capable cloud model be unsuitable for a particular production application?

Answer: The application may have strict data-residency requirements, limited network connectivity, latency constraints, or a budget that makes remote inference unsuitable. Model capability is only one selection criterion; deployment constraints and operational requirements also matter.

Question 19: Why does a high similarity score from an embedding system not guarantee that a document contains the correct answer?

Answer: Embedding similarity measures a learned relationship between representations, not factual correctness. A document may be semantically related to the query while lacking the required details, containing outdated information, or providing an incorrect answer. Relevance ranking and factual validation remain important.

Question 20: Explain why total parameter count alone is insufficient to compare two AI models.

Answer: Parameter count does not fully describe model architecture, active computation, training quality, supported modalities, inference efficiency, accuracy, or performance on a particular task. A meaningful comparison requires task-specific evaluation and consideration of resource requirements.

Question 24: A company needs an AI assistant to run without internet access on employee laptops. What should you evaluate before choosing a local model?

Answer: Evaluate available memory and compute, model size, inference speed, answer quality, supported tasks, software compatibility, and offline operation. Also consider data privacy, maintenance, model updates, and the difference between hardware costs and cloud API costs. A small model may be more practical, but it must still meet the application's accuracy requirements.

Question 25: A generative system creates realistic individual frames, but characters frequently change appearance across a video. Which model capability is lacking, and why?

Answer: The system is struggling with temporal and character consistency. Generating a plausible individual frame does not guarantee that the same character will retain its identity across successive frames. Video generation must account for motion, persistent visual identity, and consistency throughout the sequence.

Question 26: An MoE model has many experts, but inference performance is worse than expected. What factors would you investigate?

Answer: Investigate routing efficiency, load balancing among experts, device placement, inter-device communication overhead, memory movement, and the actual number of active parameters. Sparse activation reduces some computations, but routing and distributed execution can introduce costs that offset those gains. Measure the complete inference pipeline rather than judging efficiency by total parameter count alone.

### 21.2 Five distinctions to memorize

1\. Language model versus embedding model

- Language model: Generates language.
- Embedding model: Represents information numerically.

2\. Embedding model versus reranker

- Embedding model: Retrieves relevant candidates.
- Reranker: Refines the candidate ranking.

3\. VLM versus image generation

- VLM: Understands images.
- Image generation: Creates images.

4\. ASR versus TTS

- ASR: Speech to text.
- TTS: Text to speech.

5\. Dense versus MoE

- Dense: Uses dense computational pathways.
- MoE: Routes computation to selected experts.

### 21.4 The most important MoE rule

Do not confuse total parameters with active parameters.

A model may contain many expert parameters overall while activating only a subset for a given token. This can reduce computation relative to activating every expert, but routing, memory, and communication still affect overall efficiency.

### 21.5 The final mental model

When you encounter a new model, ask:

1. Input: What information can it process?
2. Output: What can it produce?
3. Purpose: What is it designed or optimized to do?
4. Deployment: Where can it run?
5. Architecture: How is its computation organized?

These questions help explain the model's role without relying on memorized names.

Final takeaway: Modern AI model categories describe different capabilities, specialized operations, architectural choices, and deployment options. Understanding these distinctions allows you to select appropriate components and combine them into effective AI applications, including RAG systems, multimodal assistants, interview tools, and generative applications.
