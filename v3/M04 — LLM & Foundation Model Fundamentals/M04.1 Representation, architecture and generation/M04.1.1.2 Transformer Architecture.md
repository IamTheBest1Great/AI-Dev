## 1. Transformer Architecture: The Big Picture

### 1.1 What is a Transformer?

A Transformer is a neural network architecture that processes sequences using attention mechanisms and learned transformations.

It is the foundation of many modern language models. It allows a model to build contextual representations of tokens, helping it process language and, in generative models, predict subsequent tokens.

### 1.2 What problem does it solve?

Consider this incomplete sentence:

> The cat is ...

A language model might predict:

> sleeping

However, it cannot simply manipulate words as humans do. It must convert text into numerical representations, process relationships between tokens and calculate which next token is most likely.

A simplified processing pipeline is:

Input text

"The cat is"

Tokenization and token IDs

Token embeddings and positional information

Stack of Transformer blocks

Attention + feed-forward processing

Final representation → vocabulary logits

Next-token selection

The exact positional mechanism and block organization depend on the model architecture.

### 1.3 The two most important operations

A Transformer repeatedly performs two major kinds of computation.

Attention — information exchange

> Which information from other tokens is relevant to the current token?

Feed-forward network — information transformation

> Given the current representation, how should it be transformed?

Additional components support these operations:

| Component            | Main purpose                                                  |
| -------------------- | ------------------------------------------------------------- |
| Token embedding      | Converts token IDs into learned vectors                       |
| Positional mechanism | Supplies information about sequence position                  |
| Attention            | Combines information across token positions                   |
| FFN                  | Transforms each token representation                          |
| Residual connection  | Provides a shortcut for information and gradients             |
| Normalization        | Helps control activation scale                                |
| Causal mask          | Blocks access to future positions in autoregressive attention |
| Multiple blocks      | Repeatedly refine token representations                       |

Key takeaway: A Transformer does not understand a sentence in a single step. It repeatedly transforms numerical representations while allowing tokens to exchange relevant information.

## 2. Input Representation

Before attention can operate, text must be represented numerically.

### 2.1 Token Embeddings

#### What problem do embeddings solve?

Tokenization converts text into tokens, and token IDs identify those tokens.

For example:

```
Text:       The cat is sleeping
Tokens:     The | cat | is | sleeping
Token IDs:  123 | 456 | 789 | 1011
```

The numbers are identifiers. The number `456` is not inherently more meaningful than `782`, and their numerical difference does not tell us how similar two words are.

Neural networks instead need useful numerical representations.

#### How embeddings work

An embedding is a learned vector associated with a token ID.

Suppose a hypothetical model has:

- Vocabulary size: 50,000 tokens
- Embedding dimension: 768

Its embedding matrix has the conceptual shape:

\\[ E \in \mathbb{R}^{50000 \times 768} \\]

Each row corresponds to a token.

```
Token ID 456
     ↓
Select row 456 from embedding matrix
     ↓
[0.12, -0.43, 0.91, ...]
     ↓
Initial token representation
```

The values are learned during training.

#### Why use vectors?

Vectors provide a continuous numerical space in which the model can learn useful patterns. Training adjusts the embeddings so that they support the model's learning objectives.

For example, the model can learn useful relationships among words such as `cat`, `dog` and `lion`. These relationships are not guaranteed to form a simple visual map, and the model's actual vector space typically has many dimensions.

#### Embeddings versus contextual representations

Consider the word bank.

- In `river bank`, it refers to the side of a river.
- In `bank account`, it refers to a financial institution.

The initial token embedding is not, by itself, a complete representation of the word's meaning in either sentence. Contextual information develops as the representation passes through Transformer blocks.

```
Token ID
   ↓
Token embedding
   ↓
Attention and FFN across successive layers
   ↓
Contextual token representation
```

The same token can therefore receive different contextual representations depending on the surrounding tokens.

#### Interview questions

Why not directly use token IDs?

Token IDs are categorical identifiers. Their numerical magnitudes have no inherent semantic meaning, whereas learned embeddings provide continuous representations that a neural network can work with.

Are embeddings fixed?

The embedding matrix is learned during training. Once training is complete, its parameters are generally fixed during ordinary inference.

Does the embedding alone understand the sentence?

No. The Transformer layers progressively incorporate information from the context.

### 2.2 Positional Mechanisms

#### What problem does positional information solve?

Knowing which tokens are present is not enough. Their order also matters.

Compare:

```
Dog bites man.
Man bites dog.
```

The same words appear, but their arrangement changes who performs the action and who receives it.

A Transformer needs a mechanism that lets its processing distinguish sequence positions.

#### How position is represented

Consider:

```
The   cat   sat   on   the   mat
 0     1     2    3     4     5
```

The model needs information that distinguishes `cat` at position 1 from a token at position 5.

Different Transformer architectures use different positional mechanisms, including:

- Learned positional embeddings
- Sinusoidal positional encodings
- Rotary Positional Embeddings (RoPE)

A useful conceptual distinction is:

\\[ \text{Token identity} \neq \text{Token position} \\]

The model needs information about both.

#### Why is attention alone insufficient?

Standard attention calculates relationships from the representations supplied to it. Without positional information or a suitable positional mechanism, it generally cannot adequately distinguish all different orderings of the same tokens.

Key takeaway: Token embeddings represent what token is present; positional mechanisms help the model account for where it occurs and how positions relate.

### 2.3 Rotary Positional Embeddings (RoPE)

RoPE stands for Rotary Positional Embedding. It is a positional mechanism used in many decoder-only LLM architectures.

#### What problem does RoPE address?

It allows position to influence the relationships calculated by attention.

The model should be able to distinguish not only that two tokens occupy positions, but also their positional relationship—for example, whether they are adjacent or separated by many positions.

#### How RoPE works

Self-attention creates query, key and value representations. RoPE applies position-dependent rotations to the relevant components of the query and key vectors.

```
Query (Q) ──→ Position-dependent rotation ──→ Q′
Key   (K) ──→ Position-dependent rotation ──→ K′
                                              ↓
                                        Attention scores
```

Imagine a vector as an arrow. At one position its direction is rotated by one amount; at another position it is rotated differently. The resulting query-key interactions can encode positional relationships.

The actual method uses mathematical rotations across pairs of dimensions. The intuition is useful even before studying the trigonometric equations.

#### Why apply RoPE to queries and keys?

Attention scores are calculated by comparing queries with keys. Applying positional rotations to these representations makes position influence the attention scores.

This differs from simply adding a separate position vector to every token embedding.

| Token embedding                                                | RoPE                                            |
| -------------------------------------------------------------- | ----------------------------------------------- |
| Provides an initial learned token representation               | Applies position-dependent rotations            |
| Represents the starting token information                      | Makes position influence query-key interactions |
| Is not sufficient by itself to establish full sentence context | Works within the attention mechanism            |

#### Interview-ready answer

RoPE incorporates positional information by applying position-dependent rotations to query and key representations. This allows attention scores to reflect positional relationships between tokens.

Common interview trap: RoPE is not simply a position vector added to the original token embedding.

## 3. Attention Mechanisms

Attention is one of the core mechanisms of a Transformer.

### 3.1 Self-Attention

Self-attention lets each token representation gather information from other token positions in the same sequence.

Consider:

> The cat sat on the mat.

When processing `cat`, information about `sat`, `on` or `mat` may be useful. But these tokens do not necessarily contribute equally.

Self-attention computes data-dependent weights to determine how information from the available positions is combined.

#### How it works

Input token representations

Create Q, K and V projections

Compare queries with keys

Calculate and normalize attention weights

Weighted combination of value vectors

Updated token representations

Attention does not merely select one important word. It generally calculates a weighted combination of value vectors, producing a new representation.

### 3.2 Query, Key and Value (Q, K, V)

Queries, keys and values are learned projections of the input representations.

| Component | Intuition                          | Role                                            |
| --------- | ---------------------------------- | ----------------------------------------------- |
| Query (Q) | What information am I looking for? | Determines what a token seeks from other tokens |
| Key (K)   | What information might I offer?    | Used to calculate compatibility with queries    |
| Value (V) | What information can I contribute? | Supplies the content combined by attention      |

These are useful mental models, not literal questions or descriptions understood by the model.

#### Simple analogy

Imagine searching a library.

- Query: What subject am I searching for?
- Key: What subject does this book relate to?
- Value: What information does the book contain?

A query-key comparison helps determine relevance. The value supplies the information that can be used.

In a Transformer, all three are numerical vectors learned through training.

#### Important distinction

Queries and keys determine the attention weights. Values supply the information aggregated using those weights.

Remember: Q and K determine where attention goes; V determines what information is brought together.

### 3.3 Scaled Dot-Product Attention

The standard scaled dot-product attention equation is:

\\[ \operatorname{Attention}(Q,K,V) = \operatorname{softmax} \left( \frac{QK^\top}{\sqrt{d_k}} \right)V \\]

Here is what each component does.

Step 1 — Calculate compatibility

\\[ S=QK^\top \\]

The query-key dot products give scores describing the compatibility between queries and keys.

Step 2 — Scale the scores

\\[ S\_{\text{scaled}}=\frac{S}{\sqrt{d_k}} \\]

Here, \\(d_k\\) is the dimensionality of the key vectors.

As vector dimensions increase, dot products can become large in magnitude. Dividing by \\(\sqrt{d_k}\\) helps keep scores in a manageable range, reducing the likelihood that softmax becomes excessively sharp and improving gradient behavior.

Step 3 — Apply softmax

\\[ A=\operatorname{softmax}(S\_{\text{scaled}}) \\]

Softmax converts scores into normalized weights across the positions being attended to.

For illustration, suppose the resulting weights are:

| Token   | Attention weight |
| ------- | ---------------- |
| Token A | 0.70             |
| Token B | 0.20             |
| Token C | 0.10             |
| Total   | 1.00             |

The model then places more weight on Token A's value vector in this example.

The actual weights depend on the input, learned parameters, positions and attention mask.

Step 4 — Combine values

\\[ O=AV \\]

The attention weights multiply the value vectors to produce the output representation.

#### Why use softmax?

Softmax turns the scores into a normalized distribution of relative weights. This allows the weighted combination to emphasize some values more than others.

#### Why scale by \\(\sqrt{d_k}\\)?

It controls the magnitude of the dot-product scores, helping avoid excessively concentrated softmax weights that can make optimization difficult.

Key takeaway: Attention calculates relevance, normalizes it into weights and uses those weights to aggregate information.

### 3.4 Multi-Head Attention

A single attention calculation provides one learned way to relate tokens. Language contains many patterns, so Transformers commonly use multiple attention heads.

#### What is an attention head?

Each head has its own learned query, key and value projections. It performs attention in its own learned representation space.

```
                        Input
                          |
             ┌────────────┼────────────┐
             ↓            ↓            ↓
          Head 1        Head 2        Head 3
          Q₁ K₁ V₁      Q₂ K₂ V₂      Q₃ K₃ V₃
             ↓            ↓            ↓
          Attention    Attention    Attention
             └────────────┼────────────┘
                          ↓
                     Concatenate
                          ↓
                  Linear projection
                          ↓
                        Output
```

The outputs of the heads are combined, typically by concatenation followed by a learned linear projection.

#### Why multiple heads?

Different heads can learn different relationship patterns or focus on different aspects of the representations.

For example, a trained head may become useful for a particular long-range dependency, while another may capture a different linguistic or structural pattern.

However, the model is not explicitly assigned fixed responsibilities such as:

- Head 1 = grammar
- Head 2 = nouns
- Head 3 = verbs

These patterns, when present, emerge through training.

#### Self-attention versus multi-head attention

Self-attention describes how representations interact within a sequence. Multi-head attention describes performing multiple learned attention operations in parallel and combining their results.

Interview question: Why not use one large attention operation?

Multiple heads allow the model to learn several sets of attention projections and represent different token relationships in parallel.

### 3.5 Causal Masking

Causal masking is fundamental to autoregressive, decoder-only language models.

#### What problem does it solve?

Suppose the training sentence is:

> The cat is sleeping.

When predicting the next token after `The cat is`, the model must not use `sleeping` as information that was already available.

Otherwise, the model could access the answer during training.

#### How causal masking works

At each position, attention is allowed to use the current position and earlier positions, but not future positions.

For the sequence `The cat is sleeping`, the permitted attention pattern is:

| Query position | The | cat | is | sleeping |
| -------------- | --- | --- | -- | -------- |
| The            | ✓   | ✗   | ✗  | ✗        |
| cat            | ✓   | ✓   | ✗  | ✗        |
| is             | ✓   | ✓   | ✓  | ✗        |
| sleeping       | ✓   | ✓   | ✓  | ✓        |

Each row represents a query position; each column represents a key position.

A causal mask blocks attention scores for disallowed future positions before the attention weights are computed.

#### Why is it called causal?

The restriction ensures that each position uses information that would have been available at that point in an autoregressive sequence.

It prevents future-token information from leaking into earlier predictions.

#### Is causal masking used everywhere?

Not normally in standard encoder-only Transformers. Encoders generally use bidirectional attention because the full input is available during processing.

Key takeaway: Causal masking is a restriction inside attention, not the entire token-generation procedure.

## 4. Transformer Block Components

Attention is important, but a Transformer block includes other operations that transform information and make deep networks easier to train.

### 4.1 Feed-Forward Network (FFN)

A Feed-Forward Network (FFN) is a neural network applied to token representations after attention.

#### What problem does it solve?

Attention allows tokens to exchange information. The FFN then transforms the resulting representation using learned linear transformations and nonlinear operations.

Think of the two stages as:

- Attention: Which information from other tokens is relevant?
- FFN: How should the representation containing that information be transformed?

#### How a basic FFN works

A simplified two-layer FFN is:

\\[ h=\phi(W_1x+b_1) \\]

\\[ \operatorname{FFN}(x)=W_2h+b_2 \\]

Where:

- \\(x\\) = input representation
- \\(W_1,W_2\\) = learned weight matrices
- \\(b_1,b_2\\) = learned biases
- \\(\phi\\) = nonlinear activation function
- \\(h\\) = intermediate representation

Conceptually:

```
Input representation
        ↓
First linear transformation
        ↓
Nonlinear activation
        ↓
Second linear transformation
        ↓
Output representation
```

Modern LLMs may use gated FFN variants rather than this simple two-layer form.

#### Does an FFN mix information between tokens?

Generally, no. Within a Transformer layer, the same FFN parameters are applied independently at every token position.

```
Token 1 → FFN ──→ Updated Token 1
Token 2 → FFN ──→ Updated Token 2
Token 3 → FFN ──→ Updated Token 3
```

The same weights are reused, but each token has its own input representation.

| Attention                                              | FFN                                             |
| ------------------------------------------------------ | ----------------------------------------------- |
| Allows information exchange across token positions     | Transforms each token position independently    |
| Uses Q, K and V                                        | Uses learned transformations and nonlinearities |
| Builds representations from relationships among tokens | Further processes the representations           |

Interview-ready statement: Attention mixes information across positions; the FFN transforms each position's representation.

### 4.2 Residual Connections

A residual connection adds a sublayer's input back to its output.

A simplified equation is:

\\[ y=x+F(x) \\]

Here, \\(x\\) is the input, \\(F(x)\\) is the transformation performed by a sublayer, and \\(y\\) is the resulting representation.

#### Why are residual connections needed?

Transformers contain many layers. Without shortcut paths, preserving useful information and propagating gradients through all those transformations can become more difficult.

Residual connections provide a direct path through which information and gradients can flow.

#### Intuition

Suppose you are editing a document. Rather than discarding the original and rebuilding everything from scratch, you retain the original content and add the results of the latest processing step.

```
Original representation
          +
Transformed information
          ↓
Updated representation
```

This is only an analogy; the actual operation is numerical addition.

#### Where do they appear?

A Transformer block commonly uses a residual connection around its attention sublayer and another around its FFN sublayer.

The exact placement of normalization and residual operations varies across architectures.

Key takeaway: Residual connections support information preservation and gradient flow, helping deep Transformer networks train effectively.

### 4.3 Layer Normalization and RMSNorm

As activations pass through many Transformer layers, their numerical scale matters. Normalization helps keep these computations better behaved during training.

#### Layer Normalization (LayerNorm)

LayerNorm normalizes a token's feature activations using their mean and variance, followed by learned scaling and shifting.

Conceptually:

```
Token activations
       ↓
Calculate mean and variance
       ↓
Normalize feature values
       ↓
Apply learned scale and shift
       ↓
Normalized representation
```

For \\(n\\) features, the normalized value of feature \\(i\\) can be expressed as:

\\[ \hat{x}\_i=\frac{x_i-\mu}{\sqrt{\sigma^2+\epsilon}} \\]

Where:

- \\(x_i\\) = the original feature value
- \\(\mu\\) = mean across the normalized features
- \\(\sigma^2\\) = variance across those features
- \\(\epsilon\\) = a small constant for numerical stability

Learned scale and shift parameters are normally applied after normalization.

#### Root Mean Square Normalization (RMSNorm)

RMSNorm normalizes using the root mean square (RMS) magnitude of the activations. Unlike standard LayerNorm, it does not perform the same mean-centering operation.

A simplified expression is:

\\[ \operatorname{RMS}(x) = \sqrt{\frac{1}{n}\sum\_{i=1}^{n}x_i^2} \\]

\\[ \hat{x}\_i=\frac{x_i}{\operatorname{RMS}(x)+\epsilon} \\]

Implementations may use a slightly different placement of the stabilizing constant and generally apply learned scaling parameters.

#### LayerNorm vs RMSNorm

| Feature                 | LayerNorm                       | RMSNorm                           |
| ----------------------- | ------------------------------- | --------------------------------- |
| Uses mean               | Yes                             | No mean-centering step            |
| Uses variance           | Yes                             | Uses root mean square magnitude   |
| Main purpose            | Normalize activation statistics | Normalize activation magnitude    |
| Computational structure | Includes mean-centering         | Simpler normalization calculation |

RMSNorm is used in many modern LLM architectures. Neither method is universally correct for all architectures.

#### Why normalize?

Normalization can improve the numerical behavior of the network and make optimization more manageable. It is especially relevant when many layers are stacked together.

### 4.4 Pre-Norm vs Post-Norm

Normalization can appear in different places relative to the sublayer and residual connection.

Post-Norm:

```
Input
  ↓
Sublayer
  ↓
Residual addition
  ↓
Normalization
  ↓
Output
```

Pre-Norm:

```
Input
  ↓
Normalization
  ↓
Sublayer
  ↓
Residual addition
  ↓
Output
```

These diagrams show simplified block layouts. Real implementations may include additional details.

Many modern LLMs use pre-normalization because it can make optimization in deep networks easier.

| Pre-Norm                                            | Post-Norm                                                                        |
| --------------------------------------------------- | -------------------------------------------------------------------------------- |
| Normalization occurs before the sublayer            | Normalization occurs after the residual addition                                 |
| Provides a direct residual path around the sublayer | Places normalization after the combined representation                           |
| Common in many modern LLMs                          | Used in some Transformer designs, including the original Transformer formulation |

Do not confuse their purpose: residual connections provide a shortcut path, whereas normalization controls the scale and distribution of activations.

## 5. Transformer Blocks

A Transformer block combines attention, feed-forward processing and supporting components into a reusable processing stage.

### 5.1 Encoder Block

An encoder block processes an input sequence to create contextual token representations.

A simplified block looks like:

```
Input representations
        ↓
Self-attention
        ↓
Residual connection + normalization
        ↓
Feed-forward network
        ↓
Residual connection + normalization
        ↓
Output representations
```

The order of normalization and residual operations depends on the design.

#### Why is encoder attention bidirectional?

In a standard encoder, the full input sequence is available. Therefore, a token can attend to tokens before and after it.

For example:

> The cat sat on the mat.

When processing `cat`, the encoder can use information from both `The` and `sat`, as well as other available tokens.

```
The ↔ cat ↔ sat ↔ on ↔ the ↔ mat
```

This diagram is a simplified illustration of bidirectional access, not a claim that every pair receives equal attention.

#### What is an encoder useful for?

Encoder-only architectures are commonly suited to tasks requiring strong representations of the input, such as:

- Classification
- Text embeddings
- Semantic representation
- Information extraction

Interview answer: An encoder builds contextual representations using attention over the available input sequence. Standard encoder attention is bidirectional rather than causally masked.

### 5.2 Decoder Block

The term decoder block has two related meanings that must be distinguished.

#### A. Original encoder-decoder Transformer

The original Transformer architecture uses a decoder with three major computational stages:

```
Masked self-attention
          ↓
Cross-attention
          ↓
Feed-forward network
```

Residual connections and normalization also support these operations.

Masked self-attention lets the decoder attend to its available previous output tokens without accessing future output tokens.

Cross-attention allows the decoder to use the encoder's representations.

Conceptually:

```
Decoder representations ──→ Queries
                                  \
                                   Cross-attention
                                  /
Encoder representations ──→ Keys and values
```

The decoder can therefore use both its existing generation context and information from the source sequence.

#### B. Decoder-only LLM

Modern GPT-style decoder-only models do not have a separate encoder.

Their blocks generally contain:

```
Causal self-attention
          ↓
Feed-forward network
```

with normalization and residual connections.

There is no encoder output and therefore no conventional encoder-decoder cross-attention in the standard decoder-only block.

Important interview distinction:

Do not say that GPT-style models contain a separate encoder and decoder. They are decoder-only Transformers built from stacked decoder-style blocks.

### 5.3 Repeated Transformer Blocks

One block provides one stage of processing. A complete Transformer stacks many such blocks.

```
Initial token representations
             ↓
        Transformer 1
             ↓
        Transformer 2
             ↓
        Transformer 3
             ↓
             ...
             ↓
        Transformer N
             ↓
     Final representations
```

Each block receives the previous block's output and transforms it further.

Consider the ambiguous word `bank`. Its initial embedding alone does not fully encode the sentence-specific meaning. As the representation passes through layers, attention can introduce information about surrounding words, and FFNs can further transform it.

However, it is inaccurate to assign every layer a rigid, human-readable job. The representations evolve through distributed learned transformations across the network.

Key takeaway: Stacking blocks allows the model to refine representations progressively rather than relying on a single processing step.

## 6. Transformer Architecture Types

Transformer architectures can be classified according to how their blocks are organized and how attention is allowed to operate.

### 6.1 Encoder-Only

Architecture:

```
Input sequence
      ↓
Encoder block
      ↓
Encoder block
      ↓
Encoder block
      ↓
Contextual representation
      ↓
Task-specific output
```

An encoder-only model typically uses bidirectional attention, so token representations can incorporate information from the entire available input.

#### Example: Sentiment classification

Input:

> This movie was excellent.

The model uses the sentence context to produce a representation suitable for a classification task, such as predicting positive sentiment.

The important distinction is that the primary objective is to understand or represent the provided input, not necessarily to generate one next token at a time.

Mental model: Read the available input and build a useful representation.

### 6.2 Decoder-Only

Architecture:

```
Input tokens
      ↓
Decoder-style block
      ↓
Decoder-style block
      ↓
Decoder-style block
      ↓
Final representation
      ↓
Next-token prediction
```

Decoder-only language models generally use causal self-attention.

At any position, the model can attend to permitted previous and current positions, but not future positions.

#### Why is this suitable for text generation?

The model is trained to predict the next token from the tokens that precede it.

For example:

```
The               → cat
The cat           → is
The cat is        → sleeping
```

This training objective aligns naturally with autoregressive text generation.

Mental model: Use the available token history to predict what comes next.

### 6.3 Encoder-Decoder / Sequence-to-Sequence

An encoder-decoder Transformer has two major components.

```
Input sequence
      ↓
    Encoder
      ↓
Encoded representations
      ↓
    Decoder
      ↓
Generated output sequence
```

The encoder processes the source sequence. The decoder generates the target sequence, using both its previous output tokens and information from the encoder through cross-attention.

This is also called a sequence-to-sequence (seq2seq) architecture.

#### Example: Machine translation

Input:

> How are you?

The encoder produces representations of the source text. The decoder uses these representations and its generation context to produce a translation, such as:

> Comment allez-vous ?

Translation is a natural example because it involves transforming one sequence into another.

Other applications include summarization and sequence transformation, depending on the model and training approach.

#### Why not always use decoder-only?

Both architectures can support generation, but encoder-decoder systems explicitly separate source processing from target generation. That can be useful for tasks where an input sequence must be transformed into an output sequence.

### 6.4 Self-Attention vs Cross-Attention

This is a fundamental architectural distinction.

#### Self-attention

Queries, keys and values come from the same representation stream.

```
One sequence
   ├──→ Q
   ├──→ K
   └──→ V
         ↓
      Attention
```

A token gathers information from representations in its own sequence.

#### Cross-attention

Queries come from one representation stream, while keys and values come from another.

In a typical encoder-decoder Transformer:

```
Decoder output ──→ Q

Encoder output ──→ K, V
```

This lets the decoder determine which parts of the encoded source are relevant to the current generation step.

| Feature                   | Self-attention                                     | Cross-attention                                                        |
| ------------------------- | -------------------------------------------------- | ---------------------------------------------------------------------- |
| Queries come from         | The same sequence as keys and values               | A different stream from keys and values                                |
| Keys and values come from | The same sequence as queries                       | Usually the encoder output in the original encoder-decoder Transformer |
| Main role                 | Build relationships within a representation stream | Relate one stream to another                                           |
| Typical example           | Decoder attending to previous generated tokens     | Decoder attending to source text representations                       |

Important: Cross-attention is central to the original encoder-decoder Transformer, but it is not a standard component of ordinary decoder-only GPT-style blocks.

## 7. LLM-Focused Architecture

This section connects Transformer components to how modern decoder-only LLMs operate.

### 7.1 Decoder-Only LLM Pipeline

Suppose the prompt is:

> The capital of France is

A simplified decoder-only model processes it as follows.

1. Tokenization: Break the prompt into tokens.
2. Token IDs: Map the tokens to vocabulary identifiers.
3. Embeddings: Convert token IDs into learned vectors.
4. Positional mechanism: Incorporate positional information, often through a mechanism such as RoPE.
5. Transformer blocks: Process the representations through causal self-attention, FFNs, residual connections and normalization.
6. Final representation: Obtain the final contextual representation at the prediction position.
7. Vocabulary logits: Calculate an unnormalized score for each possible next token.
8. Probabilities: Convert the scores into a probability distribution.
9. Token selection: Select a token using the model's configured decoding strategy.

```
"The capital of France is"
              ↓
       Tokenization
              ↓
       Token embeddings
              ↓
      Positional mechanism
              ↓
    Stacked Transformer blocks
              ↓
       Final representation
              ↓
       Vocabulary logits
              ↓
       Token probabilities
              ↓
        Choose next token
              ↓
            "Paris"
```

`Paris` is an illustrative expected continuation, not a guarantee that every generation configuration will produce it.

#### What are vocabulary logits?

Logits are unnormalized scores produced for possible vocabulary tokens.

The model can assign different scores to candidates such as `Paris`, `London` or other tokens. Softmax can convert these logits into probabilities.

The highest-probability token is not necessarily selected in every configuration. Greedy decoding, sampling and other strategies can behave differently.

### 7.2 Autoregressive Generation

Autoregressive generation means that a model generates tokens using the previously available sequence as context. Newly generated tokens are included in the context for subsequent predictions.

Consider:

```
Prompt: I am
```

An illustrative generation sequence is:

```
I am
  ↓
Predict "learning"
  ↓
I am learning
  ↓
Predict "AI"
  ↓
I am learning AI
  ↓
Predict the next token
```

The process continues until the model reaches a stopping condition, such as an end-of-sequence token or a generation limit.

#### The probability formulation

The basic next-token prediction can be expressed as:

\\[ P(x_t\mid x_1,x_2,\ldots,x\_{t-1}) \\]

Here:

- \\(x_t\\) = the token being predicted
- \\(x_1,\ldots,x\_{t-1}\\) = the preceding tokens available as context

The goal is to estimate the probability of a next token conditioned on the preceding sequence.

For a complete generated sequence, the autoregressive factorization is:

\\[ P(x_1,\ldots,x_T) = \prod\_{t=1}^{T} P(x_t\mid x_1,\ldots,x\_{t-1}) \\]

This shows how the probability of a sequence can be expressed through successive conditional next-token probabilities.

#### Why is it called autoregressive?

The model's previous outputs become part of the context used to generate subsequent outputs.

Remember: Autoregression describes the dependency between successive predictions. Causal masking enforces the corresponding visibility restriction within attention.

### 7.3 Training vs Generation

This is an important interview topic because the two processes use the same basic causal principle in different ways.

#### During training

The training sequence is generally already available.

For example:

```
The cat sat on the mat
```

The model can calculate predictions at multiple positions in parallel, with the corresponding next-token targets:

| Available context  | Prediction target |
| ------------------ | ----------------- |
| The                | cat               |
| The cat            | sat               |
| The cat sat        | on                |
| The cat sat on     | the               |
| The cat sat on the | mat               |

A causal mask prevents the prediction at one position from accessing future-token information.

The target alignment is shifted: the model's representation at a position predicts the next token, subject to the model's specific tokenization and training setup.

#### During generation

The model typically predicts the next token, appends it to the sequence and then predicts again.

```
Prompt
  ↓
Predict token 1
  ↓
Append token 1
  ↓
Predict token 2
  ↓
Append token 2
  ↓
Continue until stopping
```

| Training                                                    | Generation                                                |
| ----------------------------------------------------------- | --------------------------------------------------------- |
| Training targets are available                              | Future target tokens are not yet known                    |
| Many position-level predictions can be computed in parallel | New token predictions are generally produced sequentially |
| Uses causal masking to prevent future information leakage   | Uses the available context to predict the next token      |

A key efficiency technique during generation is caching previously computed keys and values, which avoids repeatedly recomputing some attention-related information. KV cache is the subject of a later topic.

### 7.4 Causal Attention

Causal attention is the mechanism that enforces the autoregressive visibility rule.

Consider:

> I love learning AI.

At the position representing `learning`, the model can attend to:

```
I
love
learning
```

It cannot use `AI` as future information at that position.

The general rule is:

```
Past and current positions → allowed
Future positions           → blocked
```

The restriction is applied at every layer that uses causal self-attention.

#### Causal attention vs autoregressive generation

| Causal attention                                | Autoregressive generation                                |
| ----------------------------------------------- | -------------------------------------------------------- |
| A constraint within the attention calculation   | A token-generation procedure                             |
| Controls which positions are visible to a query | Generates successive tokens from available context       |
| Prevents future-token leakage                   | Uses earlier/generated tokens to predict subsequent ones |

Causal masking supports autoregressive generation, but the terms describe different things.

## 8. Important Concept Comparisons

The following distinctions are especially valuable in interviews because the concepts work together but solve different problems.

### 8.1 Self-Attention vs Multi-Head Attention

| Self-attention                                                 | Multi-head attention                                       |
| -------------------------------------------------------------- | ---------------------------------------------------------- |
| Describes attention among representations in the same sequence | Performs multiple learned attention operations in parallel |
| Uses query-key compatibility and value aggregation             | Uses separate learned projections for different heads      |
| Establishes information exchange between token positions       | Allows multiple learned attention patterns to be combined  |

Multi-head attention commonly uses self-attention in Transformer blocks, but the terms are not interchangeable.

### 8.2 Attention vs FFN

| Attention                                | FFN                                                              |
| ---------------------------------------- | ---------------------------------------------------------------- |
| Mixes information across token positions | Processes each token position independently within that sublayer |
| Calculates data-dependent weights        | Applies learned transformations and nonlinearities               |
| Uses Q, K and V                          | Uses linear layers and activation functions, or a gated variant  |

This is one of the most important Transformer distinctions.

Memory hook: Attention = communication. FFN = transformation.

### 8.3 Residual Connections vs Normalization

| Residual connections                                   | Normalization                                                     |
| ------------------------------------------------------ | ----------------------------------------------------------------- |
| Adds the sublayer input to its output                  | Normalizes activations                                            |
| Provides a shortcut path for information and gradients | Helps maintain well-behaved activation scale and statistics       |
| Uses addition                                          | Uses a normalization calculation and typically learned parameters |

These operations complement each other, but they do not have the same purpose.

### 8.4 Token Embeddings vs RoPE

| Token embeddings                          | RoPE                                                                |
| ----------------------------------------- | ------------------------------------------------------------------- |
| Map token IDs to learned vectors          | Apply position-dependent rotations to query and key representations |
| Provide initial token information         | Make position influence attention relationships                     |
| Operate at the input-representation stage | Operate within the attention mechanism                              |

Remember: Embeddings answer "What token is this?" RoPE helps attention account for "How are these token positions related?"

### 8.5 Encoder-Only vs Decoder-Only

| Feature                    | Encoder-only                                            | Decoder-only                               |
| -------------------------- | ------------------------------------------------------- | ------------------------------------------ |
| Typical attention pattern  | Bidirectional                                           | Causal                                     |
| Future tokens in the input | Generally available to attention                        | Blocked at earlier positions               |
| Common purpose             | Input understanding and representations                 | Autoregressive text generation             |
| Typical output             | Contextual representations or task-specific predictions | Next-token probabilities or generated text |

These are common architectural roles, not absolute restrictions on every conceivable task.

### 8.6 Encoder-Decoder vs Decoder-Only

| Encoder-decoder                                             | Decoder-only                                                  |
| ----------------------------------------------------------- | ------------------------------------------------------------- |
| Contains separate encoder and decoder stacks                | Has no separate encoder stack                                 |
| Decoder can use encoder outputs through cross-attention     | Standard blocks use causal self-attention                     |
| Naturally separates source processing and target generation | Generates using the causal context of a single token sequence |
| Commonly associated with seq2seq tasks                      | Commonly used for autoregressive LLMs                         |

### 8.7 Self-Attention vs Cross-Attention

| Self-attention                                      | Cross-attention                                                                    |
| --------------------------------------------------- | ---------------------------------------------------------------------------------- |
| Q, K and V come from the same representation stream | Q comes from one stream; K and V come from another                                 |
| Models relationships within the sequence            | Lets one sequence use information represented by another                           |
| Used in encoders and decoders                       | Used in the conventional encoder-decoder architecture to connect source and target |

### 8.8 Causal Masking vs Autoregressive Generation

This distinction is worth memorizing precisely.

- Causal masking: A rule inside attention that blocks future positions.
- Autoregressive generation: A process that predicts a token using previously available context and then uses that token to continue generating.

The first helps enforce the constraints required by the second.

## 9. Worked Example: Processing a Sentence

Let's follow the sentence:

> The cat sat on the mat.

through a decoder-only Transformer.

### Step 1 — Tokenization

The input is divided into tokens.

For illustration:

```
The | cat | sat | on | the | mat
```

Actual tokenizers may divide words differently.

### Step 2 — Token IDs

Each token maps to a vocabulary identifier.

```
101 | 205 | 367 | 44 | 101 | 889
```

These numbers are illustrative, not the IDs of a particular tokenizer.

### Step 3 — Embeddings

Each token ID selects a learned vector from the embedding matrix.

```
101 → embedding vector
205 → embedding vector
367 → embedding vector
...
```

At this point, each token has an initial numerical representation.

### Step 4 — Positional mechanism

The architecture incorporates position-related information. If the model uses RoPE, it applies position-dependent rotations to query and key vectors within attention.

### Step 5 — Generate Q, K and V

Learned projections create query, key and value vectors from the input representations.

### Step 6 — Calculate attention

The model computes scaled dot products between queries and keys, then converts the scores into weights and combines the value vectors.

### Step 7 — Apply causal masking

For each query position, future positions are blocked. Earlier and current positions remain available.

### Step 8 — Combine multiple heads

In multi-head attention, parallel heads perform attention using separate learned projections. Their outputs are combined through concatenation and a learned projection.

### Step 9 — Residual connections and normalization

Residual connections add the sublayer input back to the transformed output. Normalization is applied according to the architecture's design.

### Step 10 — Feed-forward processing

The FFN applies additional learned transformations independently at each token position.

### Step 11 — Repeat through the stack

```
Block 1 → Block 2 → Block 3 → ... → Block N
```

Each block further transforms the representations.

### Step 12 — Calculate next-token scores

The final representation at the prediction position is mapped to vocabulary logits and then probabilities.

Possible candidates might include `quickly`, `today`, `sleeping` or other tokens, depending on the context and learned model.

### Step 13 — Generate a token

The decoding procedure selects the next token. The selected token is appended to the sequence, and generation continues using the expanded context.

Important understanding: The model does not perform attention once and finish. It applies the Transformer computation across many token positions and repeated layers, then uses the final prediction-position representation to generate a continuation.

## 10. Practical Application: Machine Translation

Consider a translation system that converts:

> How are you?

into:

> Comment allez-vous ?

This illustrates why an encoder-decoder architecture can be useful.

### Step 1 — Encode the source

The encoder processes the complete source sequence, building contextual representations of its tokens.

### Step 2 — Start target generation

The decoder receives the appropriate target-side context, such as the beginning-of-sequence marker and any previously generated tokens.

### Step 3 — Use cross-attention

The decoder creates queries from its own representations. The encoder's representations supply keys and values.

This allows the decoder to use source information relevant to the current output.

### Step 4 — Generate the translation

The decoder predicts target tokens in sequence, using its previous output tokens and encoder information.

```
Source text
    ↓
Encoder
    ↓
Source representations
    ↓
Decoder + cross-attention
    ↓
Target-token predictions
    ↓
Translated sequence
```

### Why this architecture makes sense

The input and output are different sequences with different linguistic structures. The encoder builds source representations, while the decoder generates the translated sequence.

A decoder-only model can also perform translation, but the encoder-decoder design explicitly separates source encoding from target generation.

## 14. Final Revision Sheet

### 14.1 The most important formulas

Scaled dot-product attention

\\[ \operatorname{Attention}(Q,K,V) = \operatorname{softmax} \left(\frac{QK^\top}{\sqrt{d_k}}\right)V \\]

Remember:

- \\(QK^\top\\): calculates query-key compatibility.
- \\(\sqrt{d_k}\\): scales the scores.
- Softmax: normalizes the scores into weights.
- \\(V\\): supplies the information combined using the weights.

Residual connection

\\[ y=x+F(x) \\]

Adds the input representation to the sublayer's transformation.

RMS magnitude

\\[ \operatorname{RMS}(x) = \sqrt{\frac{1}{n}\sum\_{i=1}^{n}x_i^2} \\]

Measures the root mean square magnitude of the features.

Autoregressive next-token probability

\\[ P(x_t\mid x_1,\ldots,x\_{t-1}) \\]

Represents the probability of the next token conditioned on its preceding context.

### 14.2 Ten facts to memorize

1. Token IDs are identifiers, not semantic vectors.
2. Embeddings are learned vector representations of tokens.
3. Positional mechanisms provide information about position or positional relationships.
4. RoPE applies position-dependent rotations to query and key representations.
5. Attention combines information from value vectors using query-key-derived weights.
6. Multi-head attention performs multiple learned attention operations in parallel.
7. Causal masking blocks future-token access.
8. Attention mixes information across token positions; the FFN transforms each position.
9. Residual connections provide shortcut paths, while normalization controls activation statistics or magnitude.
10. Decoder-only LLMs repeatedly predict next tokens using the available sequence context.

### 14.3 Architecture comparison at a glance

| Architecture    | Attention pattern                                            | Typical role                                  |
| --------------- | ------------------------------------------------------------ | --------------------------------------------- |
| Encoder-only    | Bidirectional                                                | Input representations and understanding tasks |
| Decoder-only    | Causal self-attention                                        | Autoregressive generation                     |
| Encoder-decoder | Encoder attention plus decoder attention and cross-attention | Source-to-target sequence transformation      |

### 14.4 Five distinctions interviewers often test

Q vs K vs V: Q and K determine the weights; V carries the information being aggregated.

Attention vs FFN: Attention mixes across positions; FFN transforms each position.

Residual vs normalization: Addition and shortcut paths versus activation normalization.

Causal masking vs autoregression: Visibility rule versus generation process.

Self-attention vs cross-attention: Same representation stream versus separate query and key/value streams.

### 14.5 Explain the whole Transformer in 60 seconds

A Transformer converts token IDs into learned embeddings and incorporates positional information. The representations pass through a stack of Transformer blocks. Within each block, attention allows tokens to exchange information, with multi-head attention performing multiple learned attention calculations in parallel. The FFN transforms each token representation. Residual connections provide shortcut paths, while normalization helps maintain stable numerical behavior. For decoder-only LLMs, causal masking prevents positions from accessing future tokens. The final representations produce vocabulary logits, which are converted into next-token probabilities. Autoregressive generation selects a token, appends it and repeats the process.

### 15.3 Interview Questions and Model Answers

1\. Explain how a Transformer processes text.

It converts token IDs into learned embeddings, incorporates positional information and passes the representations through stacked Transformer blocks. Each block uses attention to exchange information between tokens and an FFN to transform the representations. The architecture also uses residual connections and normalization. Decoder-only LLMs convert the final prediction-position representation into vocabulary logits for next-token generation.

2\. Why is multi-head attention useful?

It enables several learned attention projections to operate in parallel, allowing the model to learn and combine different patterns of relationships between token representations.

3\. Why is causal masking important in GPT-style models?

It prevents an earlier position from attending to future tokens, avoiding future-information leakage and making the attention pattern compatible with autoregressive next-token prediction.

4\. What is the difference between an encoder and a decoder?

A standard encoder builds contextual representations using bidirectional attention over the available input. A decoder used for autoregressive generation uses causal self-attention; in the original encoder-decoder architecture, it also uses cross-attention to access encoder representations.

5\. How do residual connections help deep Transformers?

They provide shortcut paths for information and gradients, making it easier to optimize deep networks and preserve useful representations through repeated transformations.

6\. Does every decoder have cross-attention?

No. The conventional encoder-decoder Transformer has cross-attention in its decoder. A standard decoder-only LLM has no separate encoder output and generally uses causal self-attention plus an FFN.

7\. Why can training be parallelized when inference is sequential?

During training, the complete target sequence is available, so the model can calculate predictions at many positions simultaneously under causal masking. During ordinary generation, each newly selected token becomes part of the context for the next prediction.

8\. What is the difference between LayerNorm and RMSNorm?

LayerNorm normalizes using the feature mean and variance. RMSNorm normalizes using root mean square magnitude without mean-centering.

9\. What is the role of cross-attention in translation?

Cross-attention lets the decoder use relevant information from the encoder's source-text representations while generating the target sequence.

10\. If a model can identify all the tokens, why does it still need a positional mechanism?

Knowing which tokens are present does not establish their order. A positional mechanism allows the model's processing to distinguish sequence positions and encode positional relationships.

### Final mental model

The Transformer architecture is easiest to understand as a series of complementary operations:

Represent the input

Embeddings convert token IDs to vectors; positional mechanisms account for sequence order.

Exchange information

Attention calculates relevance and aggregates information from value vectors.

Transform the information

The FFN processes each token representation; residual connections and normalization support deep computation.

Repeat across blocks

Stacked Transformer blocks progressively refine the contextual representations.

Generate the next token

Decoder-only LLMs use causal attention and autoregressive generation to produce a sequence.
