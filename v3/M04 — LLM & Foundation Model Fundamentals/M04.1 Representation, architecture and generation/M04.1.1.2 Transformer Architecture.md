# First, the Big Picture

Before going into individual components, understand what a Transformer is doing overall.

Suppose you give a decoder-only LLM:

```text
The cat is
```

The model needs to predict something like:

```text
sleeping
```

But it cannot simply look at the words as humans do.

It must turn them into numerical representations and repeatedly process those representations.

The journey is roughly:

```text
"The cat is"
      ↓
Tokenization
      ↓
Token IDs
      ↓
Token Embeddings
      ↓
Positional Information / RoPE
      ↓
Transformer Block
      ↓
Transformer Block
      ↓
Transformer Block
      ↓
...
      ↓
Final Representation
      ↓
Vocabulary Scores
      ↓
Next-token prediction
```

The Transformer block is where most of the interesting work happens.

---

# A. Input Representation

The Transformer needs an initial representation of the tokens before it can reason over their relationships.

---

# A.1 Token Embeddings

## What problem are embeddings solving?

You already know that tokenization might turn:

```text
The cat is sleeping
```

into something like:

```text
"The" | "cat" | "is" | "sleeping"
```

and then into IDs:

```text
123 | 456 | 789 | 1011
```

But these IDs are just identifiers.

For example:

```text
cat  → 456
dog  → 782
car  → 931
```

There is no useful mathematical meaning in saying:

```text
dog = 782
cat = 456
```

`782` is not "more dog-like" than `456`.

So the model needs to convert each ID into a **learned vector**.

---

## What actually happens?

The model has an embedding matrix.

Imagine:

```text
Vocabulary size = 50,000
Embedding dimension = 768
```

Then conceptually the matrix is:

```text
50,000 rows
×
768 numbers per row
```

Each row corresponds to one token.

So:

```text
Token ID 456
      ↓
Row 456 of embedding matrix
      ↓
[0.12, -0.43, 0.91, ...]
```

That vector is the token's initial representation.

---

## Why is it called an embedding?

Because the token is being **embedded into a continuous numerical space**.

You can imagine:

```text
cat ──────┐
dog ──────┤
lion ─────┘     → somewhat related region

car ──────┐
truck ────┤     → another region
```

This doesn't mean the model literally stores a 2D map of words. The actual vector space can have hundreds or thousands of dimensions.

The important idea is:

> Related patterns can be represented by related numerical structures.

---

## Very important: embedding ≠ final meaning

This is a common interview trap.

The initial embedding of:

```text
bank
```

doesn't yet fully represent:

```text
river bank
```

versus:

```text
bank account
```

The embedding is the **starting point**.

As the token passes through Transformer layers, its representation becomes **contextualized**.

So:

```text
Token Embedding
      ↓
Transformer layers
      ↓
Contextual representation
```

---

## Interview cross-question

### "Why not directly use token IDs?"

Because token IDs are categorical identifiers and their numeric magnitude has no semantic meaning. Neural networks need meaningful continuous representations, so token IDs are mapped through a learned embedding matrix.

### "Are embeddings fixed?"

The embedding matrix is learned during training.

### "Does the embedding itself understand the whole sentence?"

No. Context is introduced by the Transformer layers.

---

# A.2 Positional Mechanisms

Now we've solved one problem:

> "What token is this?"

But another problem remains:

> **"Where is this token?"**

---

## Why does order matter?

Consider:

```text
Dog bites man
```

and:

```text
Man bites dog
```

The vocabulary is almost identical.

But the meaning changes because the positions change.

A Transformer based purely on attention needs some mechanism to represent sequence position.

---

## What does positional information do?

Suppose:

```text
The   cat   sat   on   the   mat
 0     1     2    3     4     5
```

The model needs a way to distinguish:

```text
cat at position 1
```

from:

```text
cat at position 5
```

So some positional mechanism is used.

---

## The conceptual equation

At a high level, think:

```text
Token information
       +
Position information
       ↓
Representation used by attention
```

The exact implementation depends on the architecture.

---

## Why can't attention figure out the order automatically?

Because attention fundamentally computes relationships between representations.

Without an additional positional mechanism, sequences containing the same set of representations can lack sufficient information to distinguish ordering.

That's why positional mechanisms exist.

---

## Interview cross-question

### "What happens if there is no positional information?"

The model has difficulty distinguishing different orderings of the same tokens.

### "Does every Transformer use the same positional encoding?"

No.

Different architectures have used different methods, including learned positional embeddings, sinusoidal methods, and RoPE.

---

# A.2.1 RoPE Awareness

Now we come to **RoPE**.

RoPE stands for:

> **Rotary Positional Embedding**

This is important because it is widely used in modern decoder-only LLM architectures.

---

## Why was RoPE introduced?

We want attention to understand not only:

```text
Token A is at position 10
Token B is at position 11
```

but also useful information about the relationship:

```text
A is one position away from B
```

or:

```text
A is 20 positions away from B
```

RoPE is designed to make positional relationships naturally influence attention.

---

## What actually happens?

This is the part worth understanding.

In self-attention, we create:

```text
Q = Query
K = Key
V = Value
```

RoPE applies a **position-dependent rotation** to parts of the query and key vectors.

Very roughly:

```text
Q ──→ rotate based on position ──→ Q'
K ──→ rotate based on position ──→ K'
```

Then attention is calculated using these position-aware representations.

So:

```text
Q, K
 ↓
Position-dependent rotation
 ↓
Attention
```

---

## Why only think about Q and K?

Because attention determines relevance through the interaction of queries and keys.

The positional information therefore needs to influence the attention relationship.

This is one reason RoPE is different from simply doing:

```text
embedding + position vector
```

---

## What does the rotation mean intuitively?

Imagine a vector as an arrow.

For one token:

```text
↗
```

For another position:

```text
↘
```

The direction changes according to position.

The attention calculation can then use these position-dependent directions to encode positional relationships.

You do **not** need to remember the trigonometric equations initially.

---

## Interview answer

> "RoPE incorporates positional information by applying position-dependent rotations to query and key representations. This causes attention scores to depend on token positions and their relative relationships."

### Cross-question

**"Is RoPE just added to token embeddings?"**

A better answer:

> "No. Unlike simple additive positional embeddings, RoPE applies position-dependent rotations to the query and key representations inside the attention mechanism."

That answer shows actual understanding.

---

# B. Attention Mechanisms

Now we reach the heart of the Transformer.

The central problem is:

> **How does one token know which other tokens are relevant to it?**

Attention solves this.

---

# B.1 Self-Attention

Take:

```text
The cat sat on the mat.
```

Suppose we are processing:

```text
cat
```

Does `cat` need information from:

```text
The
sat
on
the
mat
```

Possibly yes.

But does every token matter equally?

Probably not.

So the model computes **attention weights**.

---

## What does attention actually do?

For each token, the model creates:

```text
Q
K
V
```

Let's understand those properly.

### Query

The query represents:

> "What kind of information am I looking for?"

### Key

The key represents:

> "What kind of information do I contain?"

### Value

The value is:

> "The actual information that can be passed onward."

---

## Example

Suppose a token's query is asking, conceptually:

```text
"What information helps me understand who is being talked about?"
```

Other tokens have keys describing what they may offer.

The model compares:

```text
Query ↔ Keys
```

This produces scores.

Then the scores are normalized.

Then those weights are used to combine the values.

So:

```text
Q
 ↓
Compare with K
 ↓
Scores
 ↓
Softmax
 ↓
Weights
 ↓
Weighted combination of V
 ↓
New token representation
```

That last part is very important.

Attention doesn't simply say:

```text
"Look at cat."
```

It actually creates a **new vector representation** by combining information from relevant tokens.

---

# The attention equation

You should eventually understand this:

```text
Attention(Q, K, V)
=
softmax(QKᵀ / √dₖ)V
```

Don't memorize it blindly.

Understand the pieces.

### `QKᵀ`

Measures compatibility between queries and keys.

### `/ √dₖ`

Scales the scores.

### `softmax`

Converts the scores into normalized weights.

For example:

```text
Token A → 0.70
Token B → 0.20
Token C → 0.10
```

### `V`

The actual information that gets combined according to those weights.

---

## Why softmax?

Suppose raw scores are:

```text
2.1
1.3
0.5
```

Softmax turns them into something like:

```text
0.59
0.27
0.14
```

Now they behave like relative weights.

---

## Why divide by √dₖ?

This is a very common cross-question.

As vector dimensions grow, dot products can become large.

Large attention scores can make softmax overly sharp.

That can hurt gradient behavior.

Scaling keeps the scores in a more manageable range.

---

## Interview answer

> "Self-attention lets each token compute a weighted combination of information from other tokens in the same sequence. Queries and keys determine relevance, and values provide the information that is aggregated."

---

# B.2 Multi-Head Attention

Now imagine the model has only one attention calculation.

That gives one way of looking at token relationships.

But language contains many kinds of relationships.

So Transformers use **multiple attention heads**.

---

## What is a head?

Each attention head gets its own learned projections of the input into:

```text
Q
K
V
```

So conceptually:

```text
Input
  │
  ├── Head 1 → Q₁ K₁ V₁
  ├── Head 2 → Q₂ K₂ V₂
  ├── Head 3 → Q₃ K₃ V₃
  └── Head N → Qₙ Kₙ Vₙ
```

Each head performs attention.

Then the outputs are combined.

---

## Why multiple heads?

Different heads can learn to capture different interaction patterns.

For example, one head might become useful for a certain long-range relationship while another might capture another linguistic pattern.

But here's the important interview point:

> **The model is not explicitly told what each head should learn.**

The patterns emerge from training.

So don't say:

```text
Head 1 = grammar
Head 2 = nouns
Head 3 = verbs
```

as a fixed rule.

That's only an intuition.

---

## Conceptually

```text
                Input
                  ↓
        ┌─────────┼─────────┐
        ↓         ↓         ↓
      Head 1    Head 2    Head 3 ...
        ↓         ↓         ↓
        └─────────┼─────────┘
                  ↓
              Concatenate
                  ↓
           Linear projection
                  ↓
               Output
```

---

## Interview cross-question

### "Why not just use one large attention operation?"

Multiple heads allow the model to create several different learned projections/subspaces and capture different relationships in parallel.

### "Are heads independent?"

They have separate projections within the multi-head operation, but their outputs are later combined.

### "Is multi-head attention the same as self-attention?"

Not exactly.

```text
Self-attention
→ attention among representations from the same sequence

Multi-head attention
→ multiple attention heads performing such attention in parallel
```

---

# B.3 Causal Masking

Now comes the key feature of **generative LLMs**.

Suppose the training text is:

```text
The cat is sleeping.
```

The model is trained to predict the next token.

When trying to predict:

```text
sleeping
```

it should see:

```text
The
cat
is
```

but it should not already see:

```text
sleeping
```

Otherwise, the model has been given the answer.

---

## How is this enforced?

With a **causal mask**.

Imagine this attention matrix:

```text
        The cat is sleeping

The      ✓   ✗  ✗    ✗
cat      ✓   ✓  ✗    ✗
is       ✓   ✓  ✓    ✗
sleeping ✓   ✓  ✓    ✓
```

The lower-triangular pattern means:

> Each position can see itself and positions before it, but not positions after it.

---

## Why is it called causal?

Because the model is only allowed to use information that would already be available in the sequence generation process.

---

## Why is it essential?

Without it, the model could simply look at future tokens during training.

Then next-token prediction wouldn't represent the real inference situation.

---

## Interview answer

> "Causal masking restricts attention so that position t can only attend to positions up to t. This prevents future-token information from leaking into autoregressive next-token prediction."

### Cross-question

**"Is causal masking needed for encoder-only models?"**

Not normally.

Encoder-only models generally use bidirectional attention because the entire input is available.

---

# C. Transformer Block Components

Now put the pieces together.

A Transformer block does more than attention.

A simplified decoder-style block looks like:

```text
Input
 ↓
Normalization
 ↓
Causal Self-Attention
 ↓
Residual Connection
 ↓
Normalization
 ↓
FFN
 ↓
Residual Connection
 ↓
Output
```

The exact ordering varies by architecture.

Now understand what each piece contributes.

---

# C.1 Feed-Forward Network

This is commonly abbreviated:

> **FFN**

Attention lets tokens exchange information.

But after the information is gathered, the model needs to **transform that information**.

That's what the FFN helps with.

---

## Think of the distinction like this

Attention asks:

> **"Which information from other tokens is relevant?"**

FFN asks:

> **"Now that I have this representation, how should I transform it?"**

---

## Simplified FFN

Conceptually:

```text
Input
 ↓
Linear layer
 ↓
Nonlinear activation
 ↓
Linear layer
 ↓
Output
```

For example:

```text
x
 ↓
W₁x + b₁
 ↓
activation
 ↓
W₂h + b₂
 ↓
output
```

Modern LLMs can use gated FFN variants rather than a simple two-layer FFN.

---

## Very important property

The FFN is generally applied **independently at each token position** within that layer.

So:

```text
Token 1 → FFN
Token 2 → FFN
Token 3 → FFN
Token 4 → FFN
```

with the same learned FFN weights.

This is different from attention.

### Attention:

```text
Token ↔ Other Tokens
```

### FFN:

```text
Token → transform itself
```

---

## Interview cross-question

### "Does FFN mix information between tokens?"

Not in the same way attention does.

Attention performs token-to-token interaction.

The FFN performs a position-wise transformation of each token representation.

That's an excellent distinction to remember.

---

# C.2 Residual Connections

Now imagine we have:

```text
Input
 ↓
Attention
 ↓
New representation
```

What if the model wants to keep some of the original information?

It shouldn't have to throw it away.

So we use a shortcut:

```text
                ┌───────────────┐
Input ──────────┤               │
 ↓              ↓               │
Attention ───→ Add (+) ─────────┘
                  ↓
                Output
```

Conceptually:

```text
Output = Input + Processed(Input)
```

---

## Why is this useful?

Because deep networks have many layers.

Without shortcut paths, it can become harder to preserve useful information and propagate gradients through many transformations.

Residual connections give information and gradients a more direct path.

---

## Simple analogy

Imagine you're editing a document.

You have the original:

```text
The cat is sleeping.
```

You don't completely discard it every time you make a correction.

Instead:

```text
Original
+
New changes
=
Updated version
```

That's roughly the intuition behind a residual connection.

---

## Interview answer

> "Residual connections add the sublayer input back to its output, providing a shortcut path for information and gradients and helping deep Transformer networks train effectively."

---

# C.3 Layer Normalization / RMSNorm Awareness

Transformers perform huge numbers of numerical operations.

As those representations move through layers, we want the activations to remain numerically well behaved.

Normalization helps.

---

## LayerNorm

Layer Normalization calculates statistics over the features of a token representation.

Conceptually:

```text
Raw activations
     ↓
Calculate statistics
     ↓
Normalize
     ↓
Scale/shift
     ↓
Output
```

It uses mean and variance.

---

## RMSNorm

RMSNorm uses the root mean square magnitude of the activations.

It is simpler because it does not perform the same mean-centering operation as LayerNorm.

Conceptually:

```text
LayerNorm
→ mean + variance based normalization

RMSNorm
→ RMS-based normalization
```

---

## Why do we need normalization?

Imagine values becoming badly scaled as they pass through many layers.

Optimization can become more difficult.

Normalization helps keep the numerical behavior under control.

---

## Interview cross-question

### "LayerNorm vs RMSNorm?"

A good answer:

> "LayerNorm normalizes using the mean and variance, while RMSNorm uses the root mean square magnitude and omits the mean-centering step. RMSNorm is simpler and is commonly used in modern LLMs."

---

## Pre-Norm vs Post-Norm

Another common cross-question.

### Post-Norm

```text
Input
 ↓
Sublayer
 ↓
Residual
 ↓
Norm
```

### Pre-Norm

```text
Input
 ↓
Norm
 ↓
Sublayer
 ↓
Residual
```

Many modern LLMs use a **pre-normalization style** because it can make optimization of deep models easier.

---

# D. Transformer Blocks

Now all of those components become one **Transformer block**.

---

## What is a Transformer block?

Think of it as one processing stage.

For a decoder-only architecture, conceptually:

```text
Input
 ↓
Self-Attention
 ↓
Residual + Normalization
 ↓
FFN
 ↓
Residual + Normalization
 ↓
Output
```

That entire unit is one block.

---

# D.1 Encoder Block

An encoder block is designed to process an input sequence and create contextual representations.

A simplified conceptual structure:

```text
Input
 ↓
Self-Attention
 ↓
Residual + Norm
 ↓
FFN
 ↓
Residual + Norm
 ↓
Output
```

The major difference from a decoder used for generation is the attention pattern.

---

## Encoder attention is generally bidirectional

Suppose:

```text
The cat sat on the mat
```

When processing:

```text
cat
```

it can use surrounding tokens.

Conceptually:

```text
The ←→ cat ←→ sat ←→ on ←→ the ←→ mat
```

There is no causal restriction forcing it to look only backward.

That's useful when the entire input is available.

---

## What is an encoder good at?

Tasks where understanding the full input is important.

Examples:

```text
Classification
Embeddings
Semantic representation
Information extraction
```

### Interview answer

> "An encoder block builds contextual representations using attention over the available input sequence. In a standard encoder, attention is bidirectional rather than causally masked."

---

# D.2 Decoder Block

Here we need to be careful.

There are **two related meanings** of "decoder block."

---

## Original Transformer decoder

The original Transformer from the encoder-decoder architecture contains:

```text
Masked Self-Attention
        ↓
Cross-Attention
        ↓
FFN
```

Why cross-attention?

Because the decoder needs information from the encoder.

Conceptually:

```text
Encoder
   ↓
Encoder representations
   ↓
Cross-Attention
   ↑
Decoder
```

The decoder asks:

> "Given what I have generated so far, what information from the encoder should I use?"

---

# Decoder-only LLM

Now look at a modern decoder-only LLM.

There is **no separate encoder**.

Therefore there is no encoder output for cross-attention.

Instead, the block mainly uses:

```text
Causal Self-Attention
        ↓
FFN
```

plus residual connections and normalization.

This is extremely important for interviews.

### Don't say:

> "GPT has an encoder and a decoder."

Instead:

> "GPT-style models are decoder-only Transformers. They use stacked decoder-style blocks with causal self-attention and do not have a separate encoder."

---

# D.3 Repeated Transformer Blocks

Why do we need many blocks?

Because one processing step is not enough.

Suppose:

```text
Input
 ↓
Block 1
 ↓
Block 2
 ↓
Block 3
 ↓
...
 ↓
Block N
```

Each block takes the representations from the previous block and transforms them further.

---

## Think about a token's journey

Initially:

```text
"bank"
```

gets an embedding.

After several layers, its representation contains much more contextual information.

So:

```text
Raw token representation
        ↓
Layer 1
        ↓
Layer 2
        ↓
Layer 3
        ↓
...
        ↓
Deep contextual representation
```

You shouldn't say each layer has one fixed human-readable job.

A better statement:

> **The layers perform distributed transformations that progressively refine the representations.**

---

# E. Transformer Architecture Types

Now move from:

> "What happens inside a block?"

to:

> **"How are blocks arranged into a complete Transformer?"**

There are three important families.

---

# E.1 Encoder-Only

Architecture:

```text
Input
 ↓
Encoder
 ↓
Encoder
 ↓
Encoder
 ↓
Representation
```

The model reads the input and creates contextual representations.

Because it can generally use the whole input, it uses bidirectional attention.

---

## Example

Input:

```text
"This movie was excellent."
```

The model can use the whole sentence to determine:

```text
positive sentiment
```

This is very different from predicting the next token.

---

## Mental model

```text
Encoder-only
=
"Read the entire input and build a useful representation."
```

---

# E.2 Decoder-Only

Architecture:

```text
Input tokens
 ↓
Decoder-style block
 ↓
Decoder-style block
 ↓
Decoder-style block
 ↓
...
 ↓
Next-token prediction
```

The key rule is:

```text
Past/current information ✓
Future information ✗
```

That comes from causal masking.

---

## Why does this architecture work well for generation?

Because the training objective can be:

```text
Predict next token
```

For example:

```text
The → cat
The cat → is
The cat is → sleeping
```

The same basic mechanism used during training can then be used during generation.

---

# E.3 Encoder-Decoder

This combines both.

```text
Input
 ↓
Encoder
 ↓
Encoder representation
 ↓
Decoder
 ↓
Output
```

The decoder uses:

```text
its previous output
+
information from encoder
```

The connection is provided through **cross-attention**.

---

# E.3.1 Mixed / Seq2Seq Architecture

The more standard technical term is:

> **Encoder-Decoder / Sequence-to-Sequence**

"Mixed" isn't wrong as an informal description, but use **encoder-decoder** in interviews.

---

## Example: Translation

Input:

```text
How are you?
```

Encoder:

```text
understands the input sequence
```

Decoder:

```text
generates the translated sequence
```

Output:

```text
Comment allez-vous ?
```

So:

```text
Sequence A
    ↓
Encoder
    ↓
Decoder
    ↓
Sequence B
```

---

## Why use encoder-decoder instead of decoder-only?

Because some tasks naturally have:

```text
Input sequence
→
Output sequence
```

where explicitly encoding the source and then generating the target is useful.

Examples include:

```text
Translation
Summarization
Sequence transformation
```

---

# F. LLM-Focused Architecture

Now we connect everything to modern generative LLMs.

---

# F.1 Decoder-Only Transformer

This is probably the most important section for your LLM studies.

Suppose your prompt is:

```text
The capital of France is
```

The model performs roughly:

```text
Prompt
 ↓
Tokenization
 ↓
Token IDs
 ↓
Embeddings
 ↓
RoPE / positional mechanism
 ↓
Transformer Block 1
 ↓
Transformer Block 2
 ↓
Transformer Block 3
 ↓
...
 ↓
Transformer Block N
 ↓
Final representation
 ↓
Vocabulary logits
 ↓
Probabilities
 ↓
Select next token
```

Suppose:

```text
Paris → high probability
```

Then:

```text
The capital of France is Paris
```

is the new sequence.

Then the model predicts again.

---

# F.2 Autoregressive Generation

This word is very important.

**Autoregressive** means that the model uses previously available/generated tokens as context for generating the next token.

Suppose the prompt is:

```text
I am
```

The model predicts:

```text
learning
```

Now the sequence is:

```text
I am learning
```

Then it predicts:

```text
AI
```

Now:

```text
I am learning AI
```

Then another token.

So generation looks like:

```text
Prompt
 ↓
Predict token 1
 ↓
Append token 1
 ↓
Predict token 2
 ↓
Append token 2
 ↓
Predict token 3
 ↓
...
```

---

## Why is this called autoregressive?

Because the model's previous outputs become part of the input/context for future predictions.

The probability idea is:

```text
P(next token | previous tokens)
```

That's the core generative objective.

---

## Training vs generation

This is an important interview topic.

### During generation

The model produces:

```text
one token
→ next token
→ next token
→ ...
```

### During training

We usually already have the full training sequence, so the model can calculate many next-token predictions in parallel using a causal mask.

For example:

```text
"The cat sat on the mat"
```

can provide training targets such as:

```text
The   → cat
cat   → sat
sat   → on
on    → the
the   → mat
```

The causal mask ensures each position only uses information that would have been available at prediction time.

That's an excellent interview distinction.

---

# F.3 Causal Attention

Causal attention is the attention rule that enforces the autoregressive constraint.

Suppose the sequence is:

```text
I love learning AI
```

At the position representing:

```text
learning
```

the model can use:

```text
I
love
learning
```

but cannot use:

```text
AI
```

as future information when predicting that token.

So:

```text
Past + current → allowed
Future          → blocked
```

# ⚡ Now Understand the Most Important Relationships

This is where interviewers usually start cross-questioning.

---

# Self-Attention vs Multi-Head Attention

### Self-attention

Answers:

> **How should tokens in the same sequence interact?**

### Multi-head attention

Answers:

> **How can we perform multiple learned attention computations in parallel?**

So:

```text
Self-Attention
      ↓
one attention mechanism

Multi-Head Attention
      ↓
many attention heads
      ↓
combine results
```

---

# Attention vs FFN

This distinction is extremely important.

### Attention

Allows:

```text
Token A ↔ Token B
```

So information moves **between tokens**.

### FFN

Processes:

```text
Token A
```

individually at that stage.

So:

```text
Attention → communication
FFN       → transformation
```

A very good interview phrase:

> **"Attention mixes information across positions; the FFN transforms each position's representation."**

---

# Residual vs Normalization

They also solve different problems.

### Residual

```text
Preserve information / provide shortcut path
```

### Normalization

```text
Keep activation statistics well behaved
```

Together they help the deep network train and process information effectively.

---

# Causal Masking vs Autoregressive Generation

They are related but not the same.

### Causal masking

A **constraint inside attention**:

```text
Don't look at future positions.
```

### Autoregressive generation

A **generation procedure/objective**:

```text
Generate one token using previously available tokens.
```

So:

```text
Causal masking
       ↓
enforces visibility constraint

Autoregressive generation
       ↓
uses previous tokens to generate the next
```

---

# Encoder-Only vs Decoder-Only

### Encoder-only

```text
Full input
 ↓
Bidirectional context
 ↓
Representation
```

Good for understanding/representation tasks.

### Decoder-only

```text
Previous tokens
 ↓
Causal context
 ↓
Next-token prediction
```

Good for text generation.

---

# Encoder-Decoder vs Decoder-Only

### Encoder-Decoder

```text
Encoder
 ↓
Representation
 ↓
Decoder + cross-attention
 ↓
Output
```

### Decoder-only

```text
No separate encoder
 ↓
Causal self-attention
 ↓
Next-token prediction
```

This is one of the most important distinctions you should be able to explain without hesitation.

---

# Self-Attention vs Cross-Attention

### Self-attention

The same representation stream produces:

```text
Q
K
V
```

Conceptually:

```text
Sequence → Q
Sequence → K
Sequence → V
```

### Cross-attention

One stream supplies the queries and another supplies keys/values.

For an encoder-decoder model:

```text
Decoder → Q

Encoder output → K, V
```

So the decoder can ask:

> "Which parts of the source/input should I use right now?"

---

# RoPE vs Token Embedding

### Token embedding

Tells the model:

> "What token representation am I starting with?"

### RoPE

Helps attention know:

> "How are positions related?"

So:

```text
Embedding → token representation
RoPE      → positional relationship in attention
```

---

# 🧠 One Complete Example

Let's process:

```text
The cat sat on the mat
```

through a decoder-only Transformer.

### Step 1 — Tokens

```text
The | cat | sat | on | the | mat
```

### Step 2 — IDs

```text
101 | 205 | 367 | 44 | 101 | 889
```

### Step 3 — Embeddings

Each ID is mapped to a vector.

```text
101 → vector
205 → vector
367 → vector
...
```

### Step 4 — Position / RoPE

The model incorporates the positional information into the representations used for attention.

```text
The → position 0
cat → position 1
sat → position 2
...
```

### Step 5 — Q, K, V

Each representation is projected into:

```text
Q
K
V
```

### Step 6 — Attention

The model calculates how strongly positions should interact.

### Step 7 — Causal mask

Future positions are blocked.

### Step 8 — Multi-head attention

Multiple heads perform attention in parallel.

### Step 9 — Residual + normalization

The old representation is preserved through the residual path, and normalization helps stabilize the computation.

### Step 10 — FFN

Each token representation undergoes further nonlinear transformation.

### Step 11 — Repeat

The output goes into the next block.

```text
Block 1
 ↓
Block 2
 ↓
Block 3
 ↓
...
 ↓
Block N
```

### Step 12 — Next-token prediction

The final representation is converted into vocabulary scores.

For example:

```text
sleeping → 0.40
quickly  → 0.15
today    → 0.05
...
```

### Step 13 — Generate

The chosen token is appended.

Then the process repeats.

---

# 🎯 How You Should Explain Transformer Architecture in an Interview

Don't recite every component independently.

Tell the story:

> "A Transformer first converts token IDs into learned embedding vectors and incorporates positional information, often using a mechanism such as RoPE. These representations are passed through a stack of Transformer blocks. Within each block, self-attention allows token representations to exchange information, and multi-head attention performs this through multiple learned attention projections. For decoder-only LLMs, causal masking prevents a position from attending to future tokens. The attention output is further transformed by a feed-forward network, while residual connections provide shortcut paths and normalization such as LayerNorm or RMSNorm helps stabilize the activations. Repeating these blocks produces increasingly contextualized representations. In a decoder-only LLM, the final representation is converted into vocabulary logits and used for autoregressive next-token generation."

That answer is strong because an interviewer can now ask:

```text
"How does QKV work?"
"Why multi-head?"
"Why causal masking?"
"Why RoPE?"
"Why residual connections?"
"Why RMSNorm?"
"What's the difference between encoder and decoder?"
"What's cross-attention?"
"Why decoder-only for LLMs?"
```

and you can answer each one.

## The deepest concept to remember

The Transformer is essentially doing **two major things repeatedly**:

```text
1. Attention
   "What information from other tokens is relevant to me?"

2. FFN
   "How should I transform the information I now have?"
```

Then:

```text
Residual → don't lose the existing information
Normalization → keep the computation stable
Position/RoPE → tell attention about order
Multiple layers → repeat and refine
Causal mask → don't look into the future
Autoregressive generation → generate one token at a time
```

Once this mental model is solid, **M04.1.1.3 — Context Windows and KV Cache** becomes much easier, because KV cache is essentially about **avoiding unnecessary recomputation of attention-related information during autoregressive generation**.
