## 1. Understanding Sampling

### 1.1 What is sampling?

Sampling is a token-selection method that chooses the next token using a probability distribution produced by a language model.

Before sampling happens, the model has already processed the context and calculated its next-token scores.

The simplified inference pipeline is:

Prompt and context

Transformer

Processes the available context

Logits

Raw scores for possible tokens

Probabilities

Relative likelihood of each token

Decoding and token selection

Greedy, sampling or other strategies

Select and append the next token

Sampling concerns the final selection step. It is not a separate neural network and does not replace the Transformer.

### 1.2 Why does sampling exist?

Suppose a model produces this probability distribution for the sentence:

> The cat is ...

| Candidate token | Probability |
| --------------- | ----------- |
| sleeping        | 0.60        |
| walking         | 0.20        |
| sitting         | 0.10        |
| running         | 0.05        |
| Other tokens    | 0.05        |
| Total           | 1.00        |

The model considers `sleeping` the most likely next token, but other continuations are possible.

A sampling-based decoder can choose a token according to these probabilities.

- `sleeping` is the most likely choice.
- `walking` is less likely, but can still be selected.
- `sitting` is even less likely, but can still be selected.

A higher probability makes a token more likely to be sampled; it does not guarantee selection.

### 1.3 Sampling vs greedy decoding

There are two fundamental approaches to token selection.

Greedy decoding: Always choose the highest-probability eligible token.

Sampling: Choose a token probabilistically, allowing lower-probability tokens to be selected.

For the example above:

- Greedy decoding selects `sleeping`.
- Sampling may select `sleeping`, but it can sometimes select `walking` or another eligible token.

Why permit that variation? Because always selecting the highest-probability token can lead to repetitive or overly predictable output. Sampling introduces diversity into the generation process.

### 1.4 The probability distribution does not mean every token is equally likely

Sampling is not random selection from the entire vocabulary with equal chances.

Instead, tokens receive different probabilities. Tokens with higher probabilities are favored, while lower-probability tokens may still be selected.

Key takeaway: Sampling converts the model's probability distribution into a token choice, introducing controlled variation rather than always selecting the top-ranked candidate.&#x20;

## 2. Greedy Decoding

### 2.1 What is greedy decoding?

Greedy decoding selects the highest-probability next token at every generation step.

Suppose the model produces:

| Token  | Probability |
| ------ | ----------- |
| Paris  | 0.70        |
| London | 0.15        |
| Berlin | 0.10        |
| Rome   | 0.05        |

Greedy decoding selects:

```
Paris
```

There is no random choice between these candidates when the highest score is unambiguous and the decoding configuration is fixed.

### 2.2 How greedy decoding works

Suppose the prompt is:

> The capital of France is

At the first step, the model calculates a distribution:

| Token        | Probability |
| ------------ | ----------- |
| Paris        | 0.85        |
| London       | 0.04        |
| Berlin       | 0.03        |
| Rome         | 0.02        |
| Other tokens | 0.06        |

Greedy decoding selects `Paris`.

The resulting text is:

> The capital of France is Paris

The model then calculates the next-token distribution using this updated context.

Suppose the next distribution is:

| Token        | Probability |
| ------------ | ----------- |
| `.`          | 0.80        |
| `and`        | 0.05        |
| `,`          | 0.04        |
| Other tokens | 0.11        |

Greedy decoding selects the period.

The process repeats until a stopping condition is met.

```
Prompt
  ↓
Calculate token probabilities
  ↓
Select the highest-probability token
  ↓
Append token
  ↓
Calculate new probabilities
  ↓
Select the highest-probability token
  ↓
Repeat
```

### 2.3 Why is it called greedy?

A greedy algorithm makes the best choice according to its current decision criterion at each step.

In this case, the rule is:

> Which eligible token has the highest probability right now? Select it.

It does not explore alternative tokens at that selection step.

### 2.4 Advantages and disadvantages

| Advantages                                          | Disadvantages                                                                     |
| --------------------------------------------------- | --------------------------------------------------------------------------------- |
| Predictable selection rule                          | Can produce repetitive or overly conservative text                                |
| No sampling randomness when choices are unambiguous | May miss a better overall continuation that starts with a lower-probability token |
| Simple to understand and implement                  | Does not explore alternative continuations                                        |

An important limitation is that greedy decoding makes a locally optimal choice at each step. It does not guarantee the highest-probability complete sequence.

For example, a token with the highest probability now may lead to a less likely continuation later. Greedy decoding does not reconsider that earlier choice.

### 2.5 When is greedy decoding useful?

It can be useful when predictable, straightforward output is preferred and diversity is not a priority.

However, greedy decoding does not guarantee factual correctness. If the highest-scoring token is wrong, greedy decoding can still select it.

Memory hook: Greedy = choose the biggest probability every time.&#x20;

## 3. Temperature

### 3.1 What is temperature?

Temperature is a decoding parameter that controls how concentrated or spread out the token probability distribution becomes during sampling.

Its practical effect is:

- Lower temperature → more concentrated distribution and generally more predictable selections.
- Higher temperature → flatter distribution and generally more varied selections.

Temperature affects how the model's scores are used for token selection. It does not retrain the model or change its learned parameters.

### 3.2 How temperature works mathematically

Let \\(z_i\\) be the logit for token \\(i\\), and let \\(T\\) be a positive temperature.

Temperature scaling modifies the logits before softmax:

\\[ P_i(T) = \frac{e^{z_i/T}} {\sum\_{j=1}^{V}e^{z_j/T}} \\]

Where:

- \\(z_i\\) = the original logit for token \\(i\\).
- \\(T\\) = temperature.
- \\(V\\) = vocabulary size.
- \\(P_i(T)\\) = probability after temperature scaling and softmax.

The division by temperature changes the differences between the logits before probabilities are calculated.

For \\(T=1\\), the distribution is the ordinary softmax distribution of the original logits.

For a positive temperature below 1, the distribution becomes more concentrated around the highest-scoring tokens.

For a temperature above 1, the distribution becomes flatter.

### 3.3 Low temperature

Consider these illustrative logits:

| Token  | Logit |
| ------ | ----- |
| Paris  | 8     |
| London | 6     |
| Berlin | 4     |
| Rome   | 2     |

With a low temperature, the gap between the scaled logits becomes larger.

As a result, the highest-scoring token receives a larger share of the probability mass.

Conceptually:

```
Paris   → dominant probability
London  → small probability
Berlin  → smaller probability
Rome    → very small probability
```

This makes the output more predictable because sampling is more likely to select one of the strongest candidates.

Useful for: Tasks where consistency and focused responses are more valuable than variety.

### 3.4 High temperature

With a higher temperature, the differences between scaled logits become smaller.

Conceptually:

```
Paris   → still favored, but less dominant
London  → more relative probability
Berlin  → more relative probability
Rome    → more relative probability
```

This gives lower-ranked candidates more opportunity to be selected.

Useful for: Brainstorming, creative writing and tasks where diverse continuations are desirable.

However, excessively high temperature can produce less coherent or less appropriate outputs.

### 3.5 Temperature is not intelligence

Temperature changes the selection distribution. It does not increase the model's learned capabilities, add factual knowledge or improve its reasoning by itself.

For example, raising temperature does not make a model smarter at solving a difficult problem. It changes how varied its token choices can be.

### 3.6 What does temperature 0 mean?

In mathematical temperature scaling, the formula divides logits by \\(T\\), so \\(T=0\\) cannot be substituted directly into the formula.

In practical inference systems, a temperature setting of zero is commonly handled as greedy-style selection or a limiting approximation that favors the highest-scoring token. Exact handling is implementation-specific.

Avoid assuming that temperature zero guarantees identical outputs across all systems and runtimes. Numerical behavior, model versions, ties and serving implementations may still affect reproducibility.

| --------------------------- | --------------------------------------- | ---------------------------------------------- |
| \\(0\<T<1\\)                | More concentrated                       | More predictable                               |

Key takeaway: Temperature controls the concentration of the distribution, not the model's learned intelligence.&#x20;

## 4. Top-p Sampling (Nucleus Sampling)

### 4.1 What is top-p sampling?

Top-p sampling, also called nucleus sampling, restricts sampling to the smallest set of highest-probability tokens whose cumulative probability reaches or exceeds a specified threshold \\(p\\).

Unlike ordinary sampling from the entire vocabulary, top-p excludes low-ranked candidates outside this set for the current selection step.

The value \\(p\\) usually lies between 0 and 1.

### 4.2 Worked example

Suppose the current probability distribution is:

| Token | Probability | Cumulative probability |
| ----- | ----------- | ---------------------- |
| A     | 0.45        | 0.45                   |
| B     | 0.25        | 0.70                   |
| C     | 0.15        | 0.85                   |
| D     | 0.08        | 0.93                   |
| E     | 0.04        | 0.97                   |
| F     | 0.03        | 1.00                   |

Set:

\\[ p=0.80 \\]

Now sort the tokens from highest to lowest probability and add their probabilities until the cumulative total reaches at least 0.80.

Step 1: Include A.

\\[ 0.45 < 0.80 \\]

Not enough probability mass has been retained.

Step 2: Include B.

\\[ 0.45+0.25=0.70 \\]

The threshold has not been reached.

Step 3: Include C.

\\[ 0.45+0.25+0.15=0.85 \\]

Now the cumulative probability exceeds 0.80.

Therefore, the retained candidate set is:

```
A, B, C
```

Tokens D, E and F are excluded from the sampling pool for this step.

### How nucleus sampling works

Retained candidates

A · 0.45

B · 0.25

C · 0.15

Cumulative probability: 0.85, meeting the 0.80 threshold.

Excluded candidates

D · 0.08

E · 0.04

F · 0.03

These candidates are outside the retained set for this selection step.

### 4.3 What happens after filtering?

After filtering the candidate tokens, a typical top-p implementation renormalizes the retained probabilities before sampling.

In our example, the retained probability mass totals 0.85.

The conditional probabilities become:

\\[ P(A\mid A,B,C)=\frac{0.45}{0.85}\approx0.529 \\]

\\[ P(B\mid A,B,C)=\frac{0.25}{0.85}\approx0.294 \\]

\\[ P(C\mid A,B,C)=\frac{0.15}{0.85}\approx0.176 \\]

These adjusted probabilities sum to approximately 1.

The decoder can now sample from A, B and C. A remains the most likely selection, but B and C can also be selected.

### 4.4 Why use top-p?

A language model's vocabulary may contain many possible next tokens, including numerous candidates with extremely low probabilities.

Sampling from the entire vocabulary can allow an unlikely token to be selected.

Top-p limits the sampling pool to a set containing most of the probability mass. This gives the decoder flexibility without allowing every low-probability candidate.

### 4.5 Why does the candidate count vary?

Imagine two different next-token distributions.

Distribution A: One token has most of the probability mass.

A relatively small group may reach the top-p threshold.

Distribution B: Probability is spread across many tokens.

More candidates may be needed to reach the same threshold.

Therefore, top-p retains a variable number of candidates depending on the distribution at each step.

For example, \\(p=0.80\\) does not mean exactly 80 tokens or 80% of the vocabulary are retained. It means the smallest qualifying set retains at least 80% of the probability mass.

### 4.6 Does top-p determine which token will be selected?

No. Top-p determines the eligible candidate set. Sampling determines which eligible token is selected.

The highest-probability token remains the most likely choice under the renormalized distribution, but the decoder may select another retained candidate.

Key takeaway: Top-p keeps the smallest high-probability candidate set reaching a cumulative threshold, then typically samples from that set.&#x20;

## 5. Top-k vs Top-p

Top-k and top-p both limit the set of tokens considered during sampling, but they use different rules.

### 5.1 What is top-k sampling?

Top-k sampling retains the \\(k\\) highest-probability candidate tokens.

Suppose:

| Token | Probability |
| ----- | ----------- |
| A     | 0.45        |
| B     | 0.25        |
| C     | 0.15        |
| D     | 0.08        |
| E     | 0.04        |
| F     | 0.03        |

If:

\\[ k=3 \\]

the retained candidates are:

```
A, B, C
```

Exactly three candidates are retained when at least that many eligible tokens exist.

### 5.2 Compare top-k and top-p

| Feature              | Top-k                                       | Top-p                                                                             |
| -------------------- | ------------------------------------------- | --------------------------------------------------------------------------------- |
| Selection rule       | Keep the highest-probability \\(k\\) tokens | Keep the smallest highest-probability set reaching cumulative probability \\(p\\) |
| Parameter            | Integer \\(k\\)                             | Probability threshold \\(p\\)                                                     |
| Number of candidates | Fixed, subject to available eligible tokens | Variable                                                                          |
| Sensitivity          | Based on candidate ranking                  | Based on candidate ranking and probability distribution                           |
| Main purpose         | Restrict sampling to a fixed-size shortlist | Restrict sampling to a probability-mass-based shortlist                           |

### 5.3 When would their results differ?

Suppose the leading token is overwhelmingly likely:

```
A → 0.92
B → 0.04
C → 0.02
D → 0.01
E → 0.01
```

For \\(p=0.90\\), top-p can retain just A because its probability alone already reaches the threshold.

For \\(k=3\\), top-k retains A, B and C.

Now suppose probability is evenly spread across many tokens. Top-p may need to retain a much larger group to reach its target, while top-k still retains the same number.

### 5.4 Can top-k and top-p be combined?

Yes, some decoding implementations support both.

When combined, both filters restrict the available candidate set. The precise filtering order and parameter semantics depend on the implementation.

Interview memory hook:

- Top-k = fixed number of candidates.
- Top-p = variable number determined by cumulative probability.

## 6. Sampling Trade-offs and Use Cases

There is no single decoding strategy that is ideal for every task. The appropriate settings depend on whether the priority is predictability, diversity or adherence to a particular output style.

### 6.1 Greedy decoding

### Greedy decoding

Behavior: Always select the highest-probability eligible token.

Strength: Predictable token selection.

Weakness: Can be repetitive or overly conservative and may miss a better complete sequence.

Possible use: Tasks where a straightforward, stable selection rule is desirable.

### 6.2 Sampling

### Probability-based sampling

Behavior: Select a token according to the configured probability distribution.

Strength: Allows different continuations and greater diversity.

Weakness: Can produce less predictable or less appropriate choices.

Possible use: Creative writing, brainstorming and open-ended generation.

### 6.3 Low temperature

Low temperature concentrates probability around the highest-scoring candidates.

This reduces variation during sampling but does not guarantee factual correctness or identical outputs across every implementation.

### 6.4 High temperature

High temperature flattens the distribution, increasing the relative probability of lower-scoring candidates.

This may encourage more varied or surprising outputs, but excessively high temperature can make generation less coherent.

### 6.5 Top-p

Top-p restricts sampling to the smallest high-probability set reaching a chosen cumulative threshold.

It offers a way to control the candidate set without fixing the number of candidates in advance.

### 6.6 Decision guide

| Requirement                                                                  | Reasonable starting strategy       |
| ---------------------------------------------------------------------------- | ---------------------------------- |
| Always select the current highest-probability token                          | Greedy decoding                    |
| Prefer focused, predictable sampling                                         | Lower positive temperature         |
| Encourage more variety                                                       | Sampling with a higher temperature |
| Exclude very low-probability candidates while retaining a variable-sized set | Top-p sampling                     |
| Restrict the shortlist to a fixed number of candidates                       | Top-k sampling                     |

These are starting points, not universal prescriptions. Model behavior and implementation details affect the result.

### 6.7 Important limitation

More randomness does not automatically produce better answers. A high-temperature response can be creative but incorrect; a low-temperature response can be predictable but still wrong.

Similarly, a top-p threshold controls candidate eligibility rather than factual accuracy.

Key takeaway: Choose decoding settings according to the task's requirements. Predictability, diversity and correctness are separate concerns.&#x20;

## 7. Determinism and Reproducibility

### 7.1 What does determinism mean?

A process is deterministic when the same defined inputs and conditions produce the same result.

In LLM inference, it is tempting to assume:

> Same prompt + same model = exactly the same response.

That is not always true.

### 7.2 Why can sampled outputs differ?

Suppose the model gives:

| Token  | Probability |
| ------ | ----------- |
| Paris  | 0.70        |
| London | 0.15        |
| Berlin | 0.10        |
| Rome   | 0.05        |

One sampled generation may choose `Paris`.

Another may choose `London`, even though Paris has the higher probability.

Once a different token is selected, the context changes. The model subsequently calculates a different next-token distribution, and the rest of the response can diverge.

```
Random selection at step 1
          ↓
Different selected token
          ↓
Different context
          ↓
Different next-token distribution
          ↓
Potentially different full response
```

A small difference early in generation can therefore create a much larger difference in the final output.

### 7.3 Does temperature zero guarantee determinism?

Not universally.

Temperature zero is commonly used to request greedy-style selection, which removes sampling randomness in the usual conceptual model. However, exact reproducibility can still depend on the inference implementation.

Potential factors include:

- Different model versions or model configurations.
- Numerical precision and computation order.
- Backend or hardware differences.
- Tie-breaking behavior when candidates have equal scores.
- Serving-system behavior, including how requests are processed.

Even when the prompt and model version remain the same, exact output reproducibility can depend on the full execution environment.

### 7.4 How can reproducibility be improved?

For controlled experiments, keep the following consistent where supported:

1. Model and model version.
2. Prompt and supplied context.
3. Sampling parameters, such as temperature, top-p and top-k.
4. Random seed when the inference system supports it.
5. Other decoding constraints and relevant runtime settings.

A fixed random seed can help reproduce sampling choices in a controlled environment, but it is not a universal guarantee of identical results across different backends or versions.

### 7.5 Interview-ready answer

Greedy decoding is deterministic in principle when the input, model behavior and tie-breaking rules are fixed. Sampling introduces randomness, and a different selection can change the context for later predictions. In real systems, numerical and implementation differences can affect reproducibility even when sampling is disabled.

Key takeaway: Sampling is one source of variation, but determinism depends on the complete inference process.&#x20;

## 8. How Sampling Fits into LLM Inference

### 8.1 The complete selection pipeline

You have already studied the following inference components:

- Context window.
- Prefill.
- KV cache.
- Logits.
- Probabilities.
- Autoregressive decoding.

Sampling fits after the model produces its next-token scores and the decoding process has established the applicable distribution and constraints.

```
Prompt
  ↓
Context window
  ↓
Prefill
  ↓
Transformer
  ↓
Logits
  ↓
Temperature adjustment, if configured
  ↓
Probability distribution
  ↓
Top-k / top-p filtering, if configured
  ↓
Greedy selection or sampling
  ↓
Append selected token
  ↓
Decode again with KV cache
  ↓
Check stopping conditions
  ↓
Repeat or stop
```

This is a conceptual pipeline. The precise order of transformations and filters varies across implementations.

### 8.2 What does each stage do?

| Stage           | Responsibility                                                     |
| --------------- | ------------------------------------------------------------------ |
| Transformer     | Calculates the model's representation and next-token logits        |
| Temperature     | Changes the concentration of the distribution                      |
| Top-k           | Limits candidates to the highest-ranked \\(k\\) tokens             |
| Top-p           | Limits candidates using cumulative probability mass                |
| Greedy decoding | Selects the highest-probability eligible token                     |
| Sampling        | Selects a token probabilistically from the applicable distribution |
| KV cache        | Reuses past key/value representations during subsequent decoding   |
| Stopping rules  | Determine whether generation should continue                       |

Not every inference request uses every technique. For example, greedy decoding does not require randomness, and some configurations omit top-k or top-p filtering.

### 8.3 Transformer vs decoder

This is an important architectural distinction.

Transformer:

> Given the current context, what scores should be assigned to possible next tokens?

Decoding process:

> Given those scores and the configured rules, which token should be selected?

The Transformer calculates the model's output distribution. The decoding process determines how to turn it into an actual output token.

### 8.4 Is sampling part of the Transformer?

In the conventional architecture, sampling is part of the decoding or token-selection process after the model produces its scores. It is not one of the Transformer block's attention or feed-forward operations.

The trained Transformer weights ordinarily remain unchanged when you change temperature or top-p.

Key takeaway: The Transformer predicts; the decoding process chooses.&#x20;

## 9. Complete Worked Example

Let's use the sentence:

> The cat is ...

Suppose the model produces this distribution for the next token.

| Token    | Probability |
| -------- | ----------- |
| sleeping | 0.60        |
| hungry   | 0.20        |
| running  | 0.10        |
| playing  | 0.06        |
| outside  | 0.04        |
| Total    | 1.00        |

These probabilities are illustrative. They are not the output of a real model.

### 9.1 Greedy decoding

Greedy decoding selects the highest-probability token:

```
sleeping
```

The text becomes:

> The cat is sleeping

### 9.2 Ordinary sampling

Sampling chooses according to the distribution.

`sleeping` has a 0.60 probability and is therefore more likely to be selected than any other individual candidate. However, a different token can also be selected.

For example:

```
One generation:  sleeping
Another generation: hungry
```

These are possible selection outcomes, not guaranteed results.

### 9.3 Low temperature

Low temperature concentrates the distribution around the leading candidates.

This makes `sleeping` more dominant and the output generally more predictable.

The selected token is still determined by the actual distribution and the decoding method.

### 9.4 Higher temperature

Higher temperature flattens the distribution.

Lower-ranked tokens such as `running` or `playing` receive more relative probability, so varied continuations become more likely.

Again, increasing temperature does not guarantee that one particular alternative will be selected.

### 9.5 Top-p with \\(p=0.80\\)

Using the original distribution, accumulate probabilities in descending order:

| Token    | Probability | Cumulative probability |
| -------- | ----------- | ---------------------- |
| sleeping | 0.60        | 0.60                   |
| hungry   | 0.20        | 0.80                   |
| running  | 0.10        | 0.90                   |
| playing  | 0.06        | 0.96                   |
| outside  | 0.04        | 1.00                   |

The cumulative probability reaches 0.80 after adding `hungry`.

The top-p candidate set is therefore:

```
sleeping
hungry
```

The remaining candidates are excluded for this step.

After renormalization, the probabilities within the retained set become:

\\[ P(\text{sleeping})=\frac{0.60}{0.80}=0.75 \\]

\\[ P(\text{hungry})=\frac{0.20}{0.80}=0.25 \\]

A sampling decoder now chooses from these two eligible tokens using the renormalized distribution.

### 9.6 Top-k with \\(k=3\\)

Top-k ignores the cumulative-probability threshold and retains exactly the three highest-ranked tokens:

```
sleeping
hungry
running
```

The resulting candidate set differs from top-p with \\(p=0.80\\).

### 9.7 What happens next?

Suppose the chosen token is `sleeping`.

The context becomes:

> The cat is sleeping

The model calculates the next-token distribution again. A decoder may select punctuation, another word or an end-of-sequence token, depending on the probabilities and configuration.

This process repeats until a stopping condition is triggered.

The same selection process happens at each generation step, not just at the beginning of the answer.&#x20;

## 10. Combining Temperature, Top-p and Sampling

Temperature and top-p solve different problems, so they can be combined.

### 10.1 Their roles

Temperature changes the probability distribution.

It controls how concentrated or flat the distribution becomes before token selection.

Top-p filters the candidate set.

It keeps the smallest highest-probability set whose cumulative probability reaches the chosen threshold.

Sampling chooses a token.

It uses the applicable probabilities to select a candidate.

### 10.2 Combined example

A conceptual sequence might be:

```
Raw logits
    ↓
Temperature scaling
    ↓
Softmax probabilities
    ↓
Top-p candidate filtering
    ↓
Renormalize retained probabilities
    ↓
Sample a token
    ↓
Append the token
```

The exact sequence of temperature scaling, filtering and other transformations is implementation-dependent. Some decoders support additional operations that change scores or restrict candidates.

### 10.3 Why combine them?

Imagine a creative-writing task.

You want diverse language, but you also want to avoid sampling from extremely unlikely candidates.

A possible approach is to use sampling with a moderate temperature and top-p filtering.

- Temperature helps determine how concentrated the distribution is.
- Top-p excludes candidates outside the retained probability mass.
- Sampling allows different eligible continuations.

The ideal settings depend on the model and task. No combination guarantees creativity, coherence or correctness.

### 10.4 Does top-p change the model?

No. Top-p normally filters the available choices during decoding rather than changing the trained model weights.

Likewise, temperature changes the decoding distribution without retraining the model.

Key takeaway: Temperature shapes the distribution, top-p limits the candidate set, and sampling selects a token from the eligible choices.&#x20;

## 14. Final Revision Sheet

### 14.1 Essential definitions

Sampling: Choose the next token using a probability distribution.

Greedy decoding: Always choose the highest-probability eligible token.

Temperature: Adjust the concentration of the distribution.

Top-p: Keep the smallest highest-probability candidate set whose cumulative probability reaches \\(p\\).

Top-k: Keep the highest-probability \\(k\\) candidates.

### 14.2 Important formulas

Temperature-scaled softmax

\\[ P_i(T)= \frac{e^{z_i/T}} {\sum\_{j=1}^{V}e^{z_j/T}} \\]

Top-p candidate-set rule

Sort candidates by probability and retain the smallest prefix for which:

\\[ \sum\_{i=1}^{m}P_i\ge p \\]

Here, \\(m\\) is the number of retained candidates. Their probabilities are commonly renormalized before sampling.

### 14.3 Fast comparison

| Method           | Rule                                                         |
| ---------------- | ------------------------------------------------------------ |
| Greedy           | Choose the highest-probability eligible token.               |
| Sampling         | Choose probabilistically from eligible candidates.           |
| Low temperature  | Concentrate probability around leading candidates.           |
| High temperature | Flatten the distribution.                                    |
| Top-k            | Keep a fixed number of top candidates.                       |
| Top-p            | Keep enough top candidates to reach a probability threshold. |

### 14.4 The six facts to memorize

1. Sampling happens after the model calculates its next-token scores.
2. Greedy decoding always selects the highest-probability eligible token.
3. Temperature changes the probability distribution without changing the learned weights.
4. Top-p filters candidates by cumulative probability; top-k filters by candidate count.
5. Sampling can introduce randomness that causes later parts of a response to diverge.
6. Decoding parameters control selection behavior; they do not independently guarantee factual accuracy.

### 15.3 Interview questions

1\. What is the difference between greedy decoding and sampling?

Greedy decoding selects the highest-probability eligible token. Sampling chooses probabilistically from the applicable distribution, allowing lower-probability candidates to be selected.

2\. Explain temperature mathematically.

Temperature divides logits by a positive parameter \\(T\\) before softmax. Lower temperatures sharpen the distribution, while higher temperatures flatten it. This changes token-selection behavior without changing the trained model weights.

3\. What is top-p sampling?

Top-p, or nucleus sampling, sorts candidates by probability and retains the smallest set whose cumulative probability reaches the specified threshold. The retained candidates are commonly renormalized before sampling.

4\. What is the difference between top-k and top-p?

Top-k retains a fixed number of top candidates. Top-p retains a variable number based on cumulative probability mass.

5\. Does high temperature make a model more intelligent?

No. Temperature changes the probability distribution used for selection. It does not add knowledge, improve the trained model's capabilities or guarantee better reasoning.

6\. Why can the same prompt produce different outputs?

Sampling can select different tokens, and each selected token changes the context for subsequent predictions. Numerical and implementation differences can also affect reproducibility.

7\. Can temperature and top-p be used together?

Yes. Temperature adjusts distribution concentration and top-p filters the candidate set. The exact order of processing depends on the implementation.

8\. Is sampling part of the Transformer architecture?

Sampling is ordinarily part of the decoding process. The Transformer calculates token scores; the decoder uses those scores and its configuration to select the next token.

### Final mental model

Transformer: Predict

Calculates the contextual representation and next-token logits.

Temperature: Shape

Makes the probability distribution more concentrated or more spread out.

Top-k / Top-p: Filter

Restricts the available candidates using either a fixed count or cumulative probability.

Sampling: Choose

Selects a token probabilistically from the eligible distribution.

Autoregression: Repeat

Appends the chosen token and repeats the process until generation stops.
