# M04.1.1.4 — Sampling

This topic explains **how an LLM chooses the next token after it has calculated the probabilities**.

You already learned:

```text
Prompt
  ↓
Transformer
  ↓
Logits
  ↓
Probabilities
  ↓
?????
```

**Sampling is the `?????` part.**

The model may have many possible next tokens:

```text
sleeping → 0.60
walking  → 0.20
sitting  → 0.10
running  → 0.05
...
```

Now the model needs a way to **choose one**.

That choice can be made in different ways.

Your existing Transformer notes specifically mention that token selection can use **greedy decoding or sampling**, and that **temperature** controls whether choices are more predictable or more random. 

---

# 1. What is Sampling?

In simple words:

> **Sampling means choosing the next token using the probability distribution produced by the model.**

Suppose the model gives:

```text
Token       Probability

Paris       0.70
London      0.15
Berlin      0.10
Rome        0.05
```

A sampling-based decoder doesn't always have to pick the highest one.

It can choose according to the probabilities.

So:

```text
Paris   → most likely
London  → less likely
Berlin  → less likely
Rome    → least likely
```

A higher-probability token is **more likely to be selected**, but a lower-probability token can sometimes be selected too.

### Why would we want that?

Because if the model **always** chooses the top token, the output can become repetitive and predictable.

Sampling gives the model some room to produce different valid continuations.

---

# 2. Greedy Decoding

Greedy decoding is the simplest strategy.

It means:

> **Always choose the token with the highest probability.**

Example:

```text
Paris    → 0.70
London   → 0.15
Berlin   → 0.10
Rome     → 0.05
```

Greedy decoding chooses:

```text
Paris
```

No randomness.

Then the model predicts the next token again and chooses the highest-probability token again.

```text
Step 1 → highest probability
Step 2 → highest probability
Step 3 → highest probability
...
```

---

## Example

Prompt:

```text
"The capital of France is"
```

Suppose:

```text
Paris      → 0.85
London     → 0.04
Berlin     → 0.03
Rome       → 0.02
```

Greedy:

```text
→ Paris
```

Then:

```text
"The capital of France is Paris"
```

Maybe the next probabilities are:

```text
.       → 0.80
and     → 0.05
,       → 0.04
...
```

Greedy picks:

```text
.
```

And so on.

---

## Why is it called "greedy"?

Because at every step it makes the **locally best choice**:

```text
"What is the highest probability token right now?"
→ Take it.
```

It doesn't consider alternative possibilities.

---

## Good mental model

```text
Greedy = "Take the biggest probability every time."
```

---

# 3. Temperature

Temperature controls **how sharply or softly the probability distribution is used for sampling**.

Your uploaded notes describe it simply as:

> **Lower temperature → more predictable**
> **Higher temperature → more random**. 

Let's understand what that means.

---

## Imagine these logits

```text
Paris   → 8
London  → 6
Berlin  → 4
Rome    → 2
```

With a **low temperature**, the distribution becomes more concentrated around the top choices.

Conceptually:

```text
Paris   → very high
London  → very low
Berlin  → tiny
Rome    → tiny
```

So the result becomes more predictable.

With a **higher temperature**, the probabilities become flatter.

Conceptually:

```text
Paris   → high
London  → medium
Berlin  → some chance
Rome    → some chance
```

More possibilities can now get selected.

---

## Easy analogy

Imagine a teacher recommending answers.

### Low temperature

Teacher says:

> "I'm almost certain Paris is the answer."

### High temperature

Teacher says:

> "Paris is most likely, but London/Berlin/Rome are being given more opportunity."

---

# 3.1 Does temperature change the model?

**No.**

This is important.

Temperature does not retrain the model.

It changes the **distribution used when selecting the next token**.

So:

```text
Model weights
    ↓
do not change

Temperature
    ↓
changes token selection behavior
```

---

# 3.2 Temperature = 0?

You'll often hear:

> "Temperature 0 means deterministic."

For study purposes, you can think of it as **very strongly favoring the highest-probability token**.

But there is an important limitation:

> Temperature alone does **not guarantee that an entire generation will always be identical across every system**.

We'll discuss that under determinism.

---

# 4. Top-p Sampling

This is a very important sampling method.

**Top-p** is also called **nucleus sampling**.

Instead of considering the entire vocabulary, we keep the **smallest set of tokens whose probabilities add up to at least `p`**.

---

## Example

Suppose:

```text
Token      Probability

A          0.45
B          0.25
C          0.15
D          0.08
E          0.04
F          0.03
```

Take:

```text
p = 0.80
```

Start from the most likely:

```text
A → 0.45
A + B → 0.70
A + B + C → 0.85
```

We have now reached at least `0.80`.

So the candidate set becomes:

```text
A
B
C
```

Tokens:

```text
D
E
F
```

are removed from the sampling pool for that step.

Then the model samples from:

```text
A, B, C
```

---

## Why is this useful?

The vocabulary may contain thousands or millions of possible tokens.

Many will have extremely tiny probabilities.

We don't necessarily want to allow all of them.

Top-p says:

> **"Only keep the most relevant probability mass."**

---

# 4.1 Top-p vs Top-k

You asked about top-p, but this distinction is useful.

### Top-k

Keep exactly the top `k` tokens.

Example:

```text
top-k = 3

Keep:
A
B
C
```

Always exactly 3 candidates.

### Top-p

Keep enough top tokens to reach probability `p`.

Example:

```text
top-p = 0.80

Maybe keep:
3 tokens in one step
8 tokens in another step
```

So:

```text
Top-k → fixed number of candidates
Top-p → variable number based on probability mass
```

This distinction often appears in interviews.

---

# 5. Sampling Tradeoffs

Now the important practical question:

> **Why not just always use one strategy?**

Because different strategies give different behavior.

---

## Greedy decoding

```text
Highest probability → always chosen
```

### Advantage

Very predictable.

### Disadvantage

Can become repetitive or overly conservative.

---

## Sampling

```text
Higher probability → more likely
Lower probability → possible
```

### Advantage

More variety and diversity.

### Disadvantage

Can produce less predictable or occasionally less appropriate outputs.

---

## Low temperature

```text
More focused
More predictable
Less variation
```

Good for cases where you want consistency.

---

## High temperature

```text
More varied
Less predictable
More exploration
```

Useful when variety is desirable, but going too high can make outputs less coherent.

---

## Top-p

```text
Only sample from a likely subset
```

This can keep sampling from wandering into extremely unlikely tokens.

---

# 5.1 Think of it as a control knob

```text
                 OUTPUT STYLE

More predictable
       ↑
       │
  Greedy
       │
Low temperature
       │
       │
Top-p / sampling
       │
High temperature
       ↓
More varied
```

This is only a conceptual picture, not a strict ranking of all decoding methods.

---

# 6. Determinism Limitations

This one is important for interviews.

People often assume:

> **"Same prompt + same model = always exactly the same output."**

That's not necessarily true.

---

## Why can outputs differ?

With sampling enabled, there is a random choice involved.

For example:

```text
Paris → 0.70
London → 0.15
Berlin → 0.10
```

One generation might choose:

```text
Paris
```

Another could choose:

```text
London
```

even though Paris was more likely.

Then the next token is generated from the new context.

So a small difference at step 1 can cause a much larger difference later.

```text
Step 1 differs
   ↓
Context differs
   ↓
Next probabilities differ
   ↓
More differences
```

---

# 6.1 Does temperature 0 guarantee determinism?

Not necessarily across every real-world system.

Even when you strongly favor the highest-probability token, other factors can affect reproducibility.

For example:

```text
Different backend implementation
Different numerical behavior
Different model/version
Different hardware/runtime behavior
Different tie situations
```

So the safe interview statement is:

> **"Greedy decoding is deterministic in principle for fixed inputs and fixed model behavior, while sampling introduces randomness. In real systems, exact reproducibility can still depend on implementation and runtime details."**

That's much better than saying:

> "Temperature 0 always guarantees identical output."

---

# 7. How Sampling Fits Into LLM Inference

You already learned this pipeline:

```text
Prompt
  ↓
Context
  ↓
Transformer
  ↓
Logits
  ↓
Probabilities
  ↓
????
```

**Sampling/decoding happens here:**

```text
Prompt
  ↓
Transformer
  ↓
Logits
  ↓
Softmax
  ↓
Probabilities
  ↓
Temperature / Top-p / Greedy
  ↓
Choose token
  ↓
Append token
  ↓
Decode again
```

So sampling is **not part of the Transformer itself**.

It is part of the **decoding/token-selection process after the model has produced the probability distribution**.

---

# 8. One Complete Example

Suppose:

```text
The cat is
```

The model gives:

```text
Token       Probability

sleeping    0.60
hungry      0.20
running     0.10
playing     0.06
outside     0.04
```

---

## Greedy

Choose:

```text
sleeping
```

because it has the highest probability.

---

## Sampling

The model samples according to the probability distribution.

Most of the time:

```text
sleeping
```

is more likely.

But sometimes:

```text
hungry
```

could be selected.

---

## Low temperature

The distribution becomes more concentrated around:

```text
sleeping
```

So output becomes more predictable.

---

## Higher temperature

The lower-probability choices receive more relative opportunity.

So there is more variation.

---

## Top-p

Suppose the probabilities after processing are:

```text
sleeping → 0.60
hungry   → 0.20
running  → 0.10
playing  → 0.06
outside  → 0.04
```

With:

```text
p = 0.80
```

we keep:

```text
sleeping → 0.60
hungry   → 0.20
```

because:

```text
0.60 + 0.20 = 0.80
```

Everything after that is excluded from the candidate set.

Then we sample from the remaining candidates.

---

# 9. Temperature and Top-p Can Be Used Together

This is another useful interview point.

They do **different things**.

### Temperature

Changes the **shape of the probability distribution**.

### Top-p

Changes **which candidates are allowed into the sampling pool**.

So conceptually:

```text
Logits
  ↓
Temperature adjustment
  ↓
Probabilities
  ↓
Top-p filtering
  ↓
Sample token
```

The exact implementation order can vary by decoding system, so don't treat that diagram as a universal API pipeline.

---

# 10. Why Sampling Happens Again and Again

Remember autoregressive generation:

```text
Prompt
 ↓
Predict token
 ↓
Append
 ↓
Predict next token
 ↓
Append
 ↓
Repeat
```

Sampling happens **at every generation step**.

Example:

```text
"The cat"
   ↓
choose "is"
   ↓
"The cat is"
   ↓
choose "sleeping"
   ↓
"The cat is sleeping"
   ↓
choose "."
```

At every step, the model creates a new probability distribution and the decoding strategy decides what to do with it.

---

# 🧠 Sampling vs Transformer

This distinction is very important.

### Transformer

Answers:

> **"Given the current context, what scores should I give the possible next tokens?"**

### Sampling / decoding

Answers:

> **"Given those scores/probabilities, which token should I actually choose?"**

So:

```text
TRANSFORMER
"What is likely?"

       ↓

DECODER
"What should I choose?"
```

---

# 🎯 Interview Cross-Questions

### "What is greedy decoding?"

> It always selects the highest-probability next token.

### "What is sampling?"

> It selects from the probability distribution, allowing less-probable tokens to sometimes be chosen.

### "What does temperature do?"

> It controls how concentrated or spread out the probability distribution is during sampling; lower values make selection more predictable and higher values make it more varied. 

### "What is top-p?"

> It keeps the smallest set of highest-probability tokens whose cumulative probability reaches at least `p`, then samples from that set.

### "Greedy vs sampling?"

```text
Greedy
→ highest probability always

Sampling
→ probability-based choice
```

### "Does sampling change the model's weights?"

> No. It changes how the next token is selected from the model's output distribution.

### "Does top-p change the model?"

> No. It filters the candidate tokens during decoding.

### "Does high temperature make the model more intelligent?"

> No. It changes output randomness/diversity; it does not increase the model's learned capability.

### "Why can two generations differ?"

> Sampling can introduce randomness, and once one token differs, the changed context can cause later predictions to diverge as well.
