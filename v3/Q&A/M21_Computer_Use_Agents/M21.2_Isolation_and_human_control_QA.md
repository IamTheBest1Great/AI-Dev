## Cross-cutting production interview drill

These questions are adapted from the source study guide’s interview section and assess how the individual concepts work together.

**Q29. [Interview] Explain isolation and human control to an interviewer.**

**Answer:** Interview answer: Isolation and human control addresses the need to ground screenshot actions in verified application state. I would begin with a bounded design for a sandboxed desktop computer-use assistant, then specify contracts for Sandboxed desktops and Isolated browser sessions. I would measure verified GUI goal completion under environmental changes, verify the actual outcome and demonstrate handling of the primary failure:.


**Q30. [Interview] How would you design Sandboxed desktops from scratch?**

**Answer:** Interview answer: I would identify the trusted input source, decide which component owns the operation, define typed fields, and specify success and failure states. Define the security and resource boundary in the infrastructure rather than only in agent instructions. Test its enforcement under unauthorized and exhausted-resource conditions. Then I would create at least a happy-path and an unauthorized/invalid-input test.


**Q31. [Interview] How do Isolated browser sessions and Network restrictions interact?**

**Answer:** Interview answer: First define their separate responsibilities. Identify who owns this information, where it lives, and when it changes. Keep transient model context distinct from durable application state and enforce scope on every read and write. Control destinations and protocols available to workloads. Deny unknown egress by default for privileged or untrusted tasks; DNS and proxy behavior matter as much as firewall rules.


**Q32. [Interview] What would you do if Tool permissions fails in production?**

**Answer:** Interview answer: I would contain the impact, check trace IDs, state and external receipts, then classify the failure as transient, permanent or unknown outcome. I would not blindly repeat a write. After fixing the cause, I would add the incident as a versioned regression case and measure verified GUI goal completion under environmental changes.


**Q33. [Interview] When would you avoid a framework or model for isolation and human control?**

**Answer:** Interview answer: When the rules and data contracts are deterministic, a small application service or workflow is usually easier to test and operate. I add an agent or new framework only when variable inputs and evidence show a measurable improvement that offsets extra coordination, cost and risk.


**Q34. [Interview] How would you demonstrate L3 production readiness for M21.2?**

**Answer:** Interview answer: I would present a working repository, a state and permission diagram, the GUI action trace with before/after screenshots and human takeover log, known limitations, representative evaluation fixtures, failure-injection results and tracing. I would also show restart behavior and an operator takeover path where needed.
