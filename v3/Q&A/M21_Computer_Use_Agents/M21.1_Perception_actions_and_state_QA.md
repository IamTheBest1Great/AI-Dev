## Cross-cutting production interview drill

These questions are adapted from the source study guide’s interview section and assess how the individual concepts work together.

**Q37. [Interview] Explain perception, actions and state to an interviewer.**

**Answer:** Interview answer: Perception, actions and state addresses the need to ground screenshot actions in verified application state. I would begin with a bounded design for a sandboxed desktop computer-use assistant, then specify contracts for Screenshot perception and GUI understanding. I would measure verified GUI goal completion under environmental changes, verify the actual outcome and demonstrate handling of the primary failure:.


**Q38. [Interview] How would you design Screenshot perception from scratch?**

**Answer:** Interview answer: I would identify the trusted input source, decide which component owns the operation, define typed fields, and specify success and failure states. Ground the operation in the current observable source and define how to verify it. Treat recognized or generated content as uncertain until checked against concrete evidence. Then I would create at least a happy-path and an unauthorized/invalid-input test.


**Q39. [Interview] How do GUI understanding and Vision-based actions interact?**

**Answer:** Interview answer: First define their separate responsibilities. Ground the operation in the current observable source and define how to verify it. Treat recognized or generated content as uncertain until checked against concrete evidence. Choose mouse or keyboard actions from screen understanding where DOM access is unavailable; constrain coordinates and verify every critical transition.


**Q40. [Interview] What would you do if Coordinate grounding fails in production?**

**Answer:** Interview answer: I would contain the impact, check trace IDs, state and external receipts, then classify the failure as transient, permanent or unknown outcome. I would not blindly repeat a write. After fixing the cause, I would add the incident as a versioned regression case and measure verified GUI goal completion under environmental changes.


**Q41. [Interview] When would you avoid a framework or model for perception, actions and state?**

**Answer:** Interview answer: When the rules and data contracts are deterministic, a small application service or workflow is usually easier to test and operate. I add an agent or new framework only when variable inputs and evidence show a measurable improvement that offsets extra coordination, cost and risk.


**Q42. [Interview] How would you demonstrate L3 production readiness for M21.1?**

**Answer:** Interview answer: I would present a working repository, a state and permission diagram, the GUI action trace with before/after screenshots and human takeover log, known limitations, representative evaluation fixtures, failure-injection results and tracing. I would also show restart behavior and an operator takeover path where needed.
