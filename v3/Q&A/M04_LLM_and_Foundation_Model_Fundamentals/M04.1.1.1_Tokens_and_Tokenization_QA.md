<a id="the-big-idea"></a>
## The Big Idea

**Q1. [Conceptual] What is a token?**

**Answer:** A token is a small piece of text that a language model processes. It can be a whole word, part of a word, punctuation, or another fragment.


**Q2. [Conceptual] What happens to raw text before an LLM processes it?**

**Answer:** The tokenizer splits the text into pieces and maps them to numeric token IDs; the model processes the resulting token representation.


<a id="the-five-core-terms"></a>
## The Five Core Terms

**Q3. [Conceptual] What is a tokenizer vocabulary?**

**Answer:** The vocabulary is the fixed collection of token pieces that a tokenizer can represent as token IDs.


**Q4. [Conceptual] What is the difference between a token and a token ID?**

**Answer:** A token is a text fragment; its token ID is the numerical label the model uses to identify that fragment.


<a id="tokens"></a>
## Tokens

**Q5. [Conceptual] Does one word always equal one token?**

**Answer:** No. One word can be several tokens, and some tokens may include punctuation or text fragments; boundaries depend on the tokenizer.


**Q6. [Interview] Why can the same sentence have different token counts across providers?**

**Answer:** Different tokenizers may divide the same text into different pieces. Use the tokenizer associated with the chosen model to count accurately.


<a id="vocabulary"></a>
## Vocabulary

**Q7. [Interview] Why does the tokenizer use a finite vocabulary?**

**Answer:** A finite collection of reusable token pieces can express many familiar and unseen words without requiring every word to be a unique token.


<a id="subword-tokenization"></a>
## Subword Tokenization

**Q8. [Interview] Why use subword tokenization instead of word-level tokenization?**

**Answer:** Subword units balance sequence length and vocabulary size and allow rare or unseen words to be represented using smaller pieces.


**Q9. [Interview] How do character-, word-, and subword-level tokenization differ?**

**Answer:** Characters produce very small pieces and long sequences; words are simple for known words but struggle with unseen words; subwords provide reusable pieces and a practical compromise.


<a id="bpe-byte-pair-encoding-intuition"></a>
## BPE — Byte Pair Encoding Intuition

**Q10. [Interview] How does Byte Pair Encoding work conceptually?**

**Answer:** In simplified terms, BPE starts with small pieces and repeatedly merges frequent neighboring pieces, learning reusable fragments such as play and ing.


**Q11. [Conceptual] Does BPE memorize every possible word?**

**Answer:** No. It uses a finite set of reusable fragments so unfamiliar words can be represented as combinations of pieces.


<a id="token-count"></a>
## Token Count

**Q12. [Interview] How do you calculate the token count of a prompt accurately?**

**Answer:** Run the exact prompt through the tokenizer for the target model; rules of thumb are estimates and can be unreliable for code, numbers and multilingual text.


**Q13. [Interview] Why is a fixed words-to-tokens ratio unreliable?**

**Answer:** Token count varies with the tokenizer and input content. Punctuation, code, numbers, unusual words and other languages can tokenize very differently.


<a id="why-token-count-matters"></a>
## Why Token Count Matters

**Q14. [Interview] How does token count affect LLM cost and latency?**

**Answer:** More input and output tokens generally increase processing work and can increase latency. Many providers bill for tokens, so total usage matters for cost.


**Q15. [Scenario] How would you prevent a RAG prompt from exceeding the context window?**

**Answer:** Count the instructions, query, retrieved chunks and reserved output budget with the model tokenizer. Reduce or select retrieved material before submitting the prompt.


**Q16. [Scenario] How would you investigate a sudden rise in production LLM costs?**

**Answer:** Log input/output tokens per operation and model, compare against the baseline, inspect prompt expansion and retrieval sizes, then enforce budget limits without dropping required context.


<a id="the-full-llm-text-pipeline"></a>
## The Full LLM Text Pipeline

**Q17. [Interview] Describe the full path from user text to generated answer.**

**Answer:** Raw text is tokenized, mapped to token IDs and embeddings, processed by the model for next-token prediction, and the generated token IDs are decoded back into text.


**Q18. [Conceptual] Where do embeddings fit into token processing?**

**Answer:** After token IDs are produced, the model maps them to vector representations called token embeddings; subsequent transformer layers process these representations.


**Q19. [Project / Real-world] How would you demonstrate tokenization to a teammate?**

**Answer:** Choose sample text with a common word, an uncommon word, punctuation and code. Run the actual tokenizer, show token strings and IDs, and compare token counts and cost estimates.


**Q20. [Scenario] What mistake might a developer make about The Big Idea when budgeting a production prompt?**

**Answer:** Estimating by word count or assuming one word equals one token can undercount the prompt. Verify tokenization using the actual model tokenizer, then reserve space for the response.
