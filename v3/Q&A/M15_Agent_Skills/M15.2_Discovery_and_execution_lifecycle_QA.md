**Answer:** Interview answer: Discovery and execution lifecycle addresses the need to make procedures discoverable, authorized, versioned and testable. I would begin with a bounded design for a reusable collection of document, research and coding agent skills, then specify contracts for Discover and Select. I would measure correct skill selection and validated output rate, verify the actual outcome and demonstrate handling of the primary failure:.


**Q30. [Interview] How would you design Discover from scratch?**

**Answer:** Interview answer: I would identify the trusted input source, decide which component owns the operation, define typed fields, and specify success and failure states. In this part of a reusable collection of document, research and coding agent skills, Discover is an explicit design concern. Define its inputs, owner, observable result and failure handling before implementing it. Its purpose must be linked to the overall goal: make procedures discoverable, authorized, versioned and testable.


**Q31. [Interview] How do Select and Authorize interact?**

**Answer:** Interview answer: First define their separate responsibilities. In this part of a reusable collection of document, research and coding agent skills, Select is an explicit design concern. Define its inputs, owner, observable result and failure handling before implementing it. Its purpose must be linked to the overall goal: make procedures discoverable, authorized, versioned and testable. Treat this as an explicitly enforced identity or permission boundary.


**Q32. [Interview] What would you do if Load fails in production?**

**Answer:** Interview answer: I would contain the impact, check trace IDs, state and external receipts, then classify the failure as transient, permanent or unknown outcome. I would not blindly repeat a write. After fixing the cause, I would add the incident as a versioned regression case and measure correct skill selection and validated output rate.


**Q33. [Interview] When would you avoid a framework or model for discovery and execution lifecycle?**

**Answer:** Interview answer: When the rules and data contracts are deterministic, a small application service or workflow is usually easier to test and operate. I add an agent or new framework only when variable inputs and evidence show a measurable improvement that offsets extra coordination, cost and risk.


**Q34. [Interview] How would you demonstrate L3 production readiness for M15.2?**

**Answer:** Interview answer: I would present a working repository, a state and permission diagram, the skill manifest with compatibility and test fixtures, known limitations, representative evaluation fixtures, failure-injection results and tracing. I would also show restart behavior and an operator takeover path where needed.
