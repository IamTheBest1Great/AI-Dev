## Cross-cutting production interview drill

These questions are adapted from the source study guide’s interview section and assess how the individual concepts work together.

**Q29. [Interview] Explain composition, validation and evolution to an interviewer.**

**Answer:** Follow-up 1 — What would you test first? A negative case involving skill permissions and a normal task with a verified outcome.


**Q30. [Interview] How would you design Skill composition from scratch?**

**Answer:** Interview answer: I would identify the trusted input source, decide which component owns the operation, define typed fields, and specify success and failure states. Combine multiple reusable procedures with explicit precedence, shared state and output contracts. Watch for conflicting requirements. Then I would create at least a happy-path and an unauthorized/invalid-input test.


**Q31. [Interview] How do Skill conflicts and Skill permissions interact?**

**Answer:** Interview answer: First define their separate responsibilities. Two capabilities provide incompatible instructions or compete for the same tool/state; enforce deterministic priority and human review for unresolved conflicts. Declared and enforced set of tool and resource rights needed to execute a skill; the skill document cannot grant itself new privileges.


**Q32. [Interview] What would you do if Skill testing fails in production?**

**Answer:** Interview answer: I would contain the impact, check trace IDs, state and external receipts, then classify the failure as transient, permanent or unknown outcome. I would not blindly repeat a write. After fixing the cause, I would add the incident as a versioned regression case and measure correct skill selection and validated output rate.


**Q33. [Interview] When would you avoid a framework or model for composition, validation and evolution?**

**Answer:** Interview answer: When the rules and data contracts are deterministic, a small application service or workflow is usually easier to test and operate. I add an agent or new framework only when variable inputs and evidence show a measurable improvement that offsets extra coordination, cost and risk.


**Q34. [Interview] How would you demonstrate L3 production readiness for M15.3?**

**Answer:** Interview answer: I would present a working repository, a state and permission diagram, the skill manifest with compatibility and test fixtures, known limitations, representative evaluation fixtures, failure-injection results and tracing. I would also show restart behavior and an operator takeover path where needed.
