## Cross-cutting production interview drill

These questions are adapted from the source study guide’s interview section and assess how the individual concepts work together.

**Q63. [Interview] Explain capability definition and boundaries to an interviewer.**

**Answer:** Follow-up 1 — What would you test first? A negative case involving optional extension brief and a normal task with a verified outcome.


**Q64. [Interview] How would you design Skill metadata from scratch?**

**Answer:** Interview answer: I would identify the trusted input source, decide which component owns the operation, define typed fields, and specify success and failure states. Manifest fields declaring skill identity, purpose, version, entrypoint, required tools and supported runtimes so a loader can match tasks safely. Then I would create at least a happy-path and an unauthorized/invalid-input test.


**Q65. [Interview] How do Skill instructions and Resources interact?**

**Answer:** Interview answer: First define their separate responsibilities. Reusable steps and constraints that guide how an agent should perform a task. Treat skill text as a procedure subject to policy, not a privilege grant. Supporting templates, guides, schemas or data bundled with a skill. Load only what is relevant and authorized. I would connect them only through a typed handoff with provenance and an explicit postcondition, rather than allowing hidden state coupling.


**Q66. [Interview] What would you do if Scripts fails in production?**

**Answer:** Interview answer: I would contain the impact, check trace IDs, state and external receipts, then classify the failure as transient, permanent or unknown outcome. I would not blindly repeat a write. After fixing the cause, I would add the incident as a versioned regression case and measure correct skill selection and validated output rate.


**Q67. [Interview] When would you avoid a framework or model for capability definition and boundaries?**

**Answer:** Interview answer: When the rules and data contracts are deterministic, a small application service or workflow is usually easier to test and operate. I add an agent or new framework only when variable inputs and evidence show a measurable improvement that offsets extra coordination, cost and risk.


**Q68. [Interview] How would you demonstrate L3 production readiness for M15.1?**

**Answer:** Interview answer: I would present a working repository, a state and permission diagram, the skill manifest with compatibility and test fixtures, known limitations, representative evaluation fixtures, failure-injection results and tracing. I would also show restart behavior and an operator takeover path where needed.
