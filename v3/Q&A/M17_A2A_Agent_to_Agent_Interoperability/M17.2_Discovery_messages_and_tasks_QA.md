## Cross-cutting production interview drill

These questions are adapted from the source study guide’s interview section and assess how the individual concepts work together.

**Q53. [Interview] Explain discovery, messages and tasks to an interviewer.**

**Answer:** Follow-up 1 — What would you test first? A negative case involving agent identity and a normal task with a verified outcome.


**Q54. [Interview] How would you design Agent discovery from scratch?**

**Answer:** Interview answer: I would identify the trusted input source, decide which component owns the operation, define typed fields, and specify success and failure states. Find remote agent endpoints and declared capabilities through registries or agent cards; separately validate authenticity and trust. Then I would create at least a happy-path and an unauthorized/invalid-input test.


**Q55. [Interview] How do Agent identity and Agent capabilities interact?**

**Answer:** Interview answer: First define their separate responsibilities. Principal representing a remote agent service, tied to credentials and operator accountability. Declared skills, endpoints and protocols an agent supports; match to task and verify with behavior tests. I would connect them only through a typed handoff with provenance and an explicit postcondition, rather than allowing hidden state coupling.


**Q56. [Interview] What would you do if Agent cards / capability descriptions fails in production?**

**Answer:** Interview answer: I would contain the impact, check trace IDs, state and external receipts, then classify the failure as transient, permanent or unknown outcome. I would not blindly repeat a write. After fixing the cause, I would add the incident as a versioned regression case and measure successful delegated task rate with cancellation propagation.


**Q57. [Interview] When would you avoid a framework or model for discovery, messages and tasks?**

**Answer:** Interview answer: When the rules and data contracts are deterministic, a small application service or workflow is usually easier to test and operate. I add an agent or new framework only when variable inputs and evidence show a measurable improvement that offsets extra coordination, cost and risk.


**Q58. [Interview] How would you demonstrate L3 production readiness for M17.2?**

**Answer:** Interview answer: I would present a working repository, a state and permission diagram, the delegation trace and signed or hashed artifact inventory, known limitations, representative evaluation fixtures, failure-injection results and tracing. I would also show restart behavior and an operator takeover path where needed.
