**Q59. [Interview] Explain federation and delegation to an interviewer.**

**Answer:** Interview answer: Federation and delegation addresses the need to delegate tasks across independent agents with verifiable outputs. I would begin with a bounded design for a federated research, coding and audit agent network, then specify contracts for User Agent and MCP → tools/data. I would measure successful delegated task rate with cancellation propagation, verify the actual outcome and demonstrate handling of the primary failure:.


**Q60. [Interview] How would you design User Agent from scratch?**

**Answer:** Interview answer: I would identify the trusted input source, decide which component owns the operation, define typed fields, and specify success and failure states. In this part of a federated research, coding and audit agent network, User Agent is an explicit design concern. Define its inputs, owner, observable result and failure handling before implementing it. Its purpose must be linked to the overall goal: delegate tasks across independent agents with verifiable outputs.


**Q61. [Interview] How do MCP → tools/data and A2A → research agent interact?**

**Answer:** Follow-up 1 — What would you test first? A negative case involving a2a → payment agent and a normal task with a verified outcome.


**Q62. [Interview] What would you do if A2A → payment agent fails in production?**

**Answer:** Interview answer: I would contain the impact, check trace IDs, state and external receipts, then classify the failure as transient, permanent or unknown outcome. I would not blindly repeat a write. After fixing the cause, I would add the incident as a versioned regression case and measure successful delegated task rate with cancellation propagation.


**Q63. [Interview] When would you avoid a framework or model for federation and delegation?**

**Answer:** Interview answer: When the rules and data contracts are deterministic, a small application service or workflow is usually easier to test and operate. I add an agent or new framework only when variable inputs and evidence show a measurable improvement that offsets extra coordination, cost and risk.


**Q64. [Interview] How would you demonstrate L3 production readiness for M17.3?**

**Answer:** Interview answer: I would present a working repository, a state and permission diagram, the delegation trace and signed or hashed artifact inventory, known limitations, representative evaluation fixtures, failure-injection results and tracing. I would also show restart behavior and an operator takeover path where needed.
