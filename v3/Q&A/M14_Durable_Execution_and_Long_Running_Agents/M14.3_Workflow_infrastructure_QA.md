## Cross-cutting production interview drill

These questions are adapted from the source study guide’s interview section and assess how the individual concepts work together.

**Q21. [Interview] Explain workflow infrastructure to an interviewer.**

**Answer:** Follow-up 1 — What would you test first? A negative case involving temporal-style durable execution and a normal task with a verified outcome.


**Q22. [Interview] How would you design Temporal-style durable execution from scratch?**

**Answer:** Interview answer: I would identify the trusted input source, decide which component owns the operation, define typed fields, and specify success and failure states. Record workflow decisions and activity results so deterministic orchestration can replay while side effects are executed through controlled activities. Then I would create at least a happy-path and an unauthorized/invalid-input test.


**Q23. [Interview] How do Queue workers and Event-driven workflows interact?**

**Answer:** Interview answer: First define their separate responsibilities. Processes consuming jobs from a broker and acknowledging or retrying them based on lease and delivery semantics. Define event identity, ordering assumptions, retry delivery and the terminal acknowledgement. Persist an outcome separately from the fact that a message arrived or was dispatched. I would connect them only through a typed handoff with provenance and an explicit postcondition, rather than allowing hidden state coupling.


**Q24. [Interview] What would you do if Workflow engines fails in production?**

**Answer:** Interview answer: I would contain the impact, check trace IDs, state and external receipts, then classify the failure as transient, permanent or unknown outcome. I would not blindly repeat a write. After fixing the cause, I would add the incident as a versioned regression case and measure exactly-one business outcome under replay tests.


**Q25. [Interview] When would you avoid a framework or model for workflow infrastructure?**

**Answer:** Interview answer: When the rules and data contracts are deterministic, a small application service or workflow is usually easier to test and operate. I add an agent or new framework only when variable inputs and evidence show a measurable improvement that offsets extra coordination, cost and risk.


**Q26. [Interview] How would you demonstrate L3 production readiness for M14.3?**

**Answer:** Interview answer: I would present a working repository, a state and permission diagram, the durable execution history and idempotency receipts, known limitations, representative evaluation fixtures, failure-injection results and tracing. I would also show restart behavior and an operator takeover path where needed.
