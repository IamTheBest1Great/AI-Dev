## Cross-cutting production interview drill

These questions are adapted from the source study guide’s interview section and assess how the individual concepts work together.

**Q5. [Interview] Explain replay and evolution to an interviewer.**

**Answer:** Follow-up 1 — What would you test first? A negative case involving deterministic orchestration and a normal task with a verified outcome.


**Q6. [Interview] How would you design Deterministic orchestration from scratch?**

**Answer:** Interview answer: I would identify the trusted input source, decide which component owns the operation, define typed fields, and specify success and failure states. In this part of a multi-hour evidence collection and report workflow, Deterministic orchestration is an explicit design concern. Define its inputs, owner, observable result and failure handling before implementing it. Its purpose must be linked to the overall goal: resume after crashes without duplicating real-world side effects.


**Q7. [Interview] How do Compatibility over time and State and evidence interact?**

**Answer:** Interview answer: First define their separate responsibilities. Make lifecycle and version information explicit. Record what changed, when it changed, and which cached or downstream copies need updating; compare against the current source of truth. Identify who owns this information, where it lives, and when it changes. Keep transient model context distinct from durable application state and enforce scope on every read and write.


**Q8. [Interview] What would you do if Validation fails in production?**

**Answer:** Interview answer: I would contain the impact, check trace IDs, state and external receipts, then classify the failure as transient, permanent or unknown outcome. I would not blindly repeat a write. After fixing the cause, I would add the incident as a versioned regression case and measure exactly-one business outcome under replay tests.


**Q9. [Interview] When would you avoid a framework or model for replay and evolution?**

**Answer:** Interview answer: When the rules and data contracts are deterministic, a small application service or workflow is usually easier to test and operate. I add an agent or new framework only when variable inputs and evidence show a measurable improvement that offsets extra coordination, cost and risk.


**Q10. [Interview] How would you demonstrate L3 production readiness for M14.5?**

**Answer:** Interview answer: I would present a working repository, a state and permission diagram, the durable execution history and idempotency receipts, known limitations, representative evaluation fixtures, failure-injection results and tracing. I would also show restart behavior and an operator takeover path where needed.
