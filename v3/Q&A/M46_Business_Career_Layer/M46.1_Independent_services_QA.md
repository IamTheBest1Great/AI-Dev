<a id="cross-cutting-production-interview-drill"></a>
## Cross-cutting production interview drill

These questions are adapted from the source study guide’s interview section and assess how the individual concepts work together.

**Q57. [Interview] Explain independent services to an interviewer.**

**Answer:** Follow-up 1 — What would you test first? A negative case involving problem-first proposals and a normal task with a verified outcome.


**Q58. [Interview] How would you design Problem-first proposals from scratch?**

**Answer:** Interview answer: I would identify the trusted input source, decide which component owns the operation, define typed fields, and specify success and failure states. Present client workflow pain, measurable acceptance criteria and delivery scope before recommending model technology. Then I would create at least a happy-path and an unauthorized/invalid-input test.


**Q59. [Interview] How do Discovery calls and Architecture scoping interact?**

**Answer:** Interview answer: First define their separate responsibilities. Structured stakeholder conversations that uncover users, constraints, data access, approval rules and budget. Bound the proposed implementation, integration points, security, reliability and non-goals with feasible milestones. I would connect them only through a typed handoff with provenance and an explicit postcondition, rather than allowing hidden state coupling.


**Q60. [Interview] What would you do if Statement of work fails in production?**

**Answer:** Interview answer: I would contain the impact, check trace IDs, state and external receipts, then classify the failure as transient, permanent or unknown outcome. I would not blindly repeat a write. After fixing the cause, I would add the incident as a versioned regression case and measure validated business impact and credible delivery references.


**Q61. [Interview] When would you avoid a framework or model for independent services?**

**Answer:** Interview answer: When the rules and data contracts are deterministic, a small application service or workflow is usually easier to test and operate. I add an agent or new framework only when variable inputs and evidence show a measurable improvement that offsets extra coordination, cost and risk.


**Q62. [Interview] How would you demonstrate L3 production readiness for M46.1?**

**Answer:** Interview answer: I would present a working repository, a state and permission diagram, the portfolio case study, proposal and implementation plan, known limitations, representative evaluation fixtures, failure-injection results and tracing. I would also show restart behavior and an operator takeover path where needed.
