## Cross-cutting production interview drill

These questions are adapted from the source study guide’s interview section and assess how the individual concepts work together.

**Q49. [Interview] Explain pipeline execution to an interviewer.**

**Answer:** Interview answer: Pipeline execution addresses the need to transform messy source data into trusted, lineage-rich AI inputs. I would begin with a bounded design for a document ingestion and intelligence pipeline, then specify contracts for Batch pipelines and Streaming pipelines. I would measure field extraction accuracy and rejected-bad-data rate, verify the actual outcome and demonstrate handling of the primary failure: a scanned table is flattened and loses row-to-column relationships.


**Q50. [Interview] How would you design Batch pipelines from scratch?**

**Answer:** Interview answer: I would identify the trusted input source, decide which component owns the operation, define typed fields, and specify success and failure states. In this part of a document ingestion and intelligence pipeline, Batch pipelines is an explicit design concern. Define its inputs, owner, observable result and failure handling before implementing it. Its purpose must be linked to the overall goal: transform messy source data into trusted, lineage-rich AI inputs.


**Q51. [Interview] How do Streaming pipelines and ETL vs ELT awareness interact?**

**Answer:** Follow-up 1 — What would you test first? A negative case involving code-first workflows and a normal task with a verified outcome.


**Q52. [Interview] What would you do if Airflow concepts fails in production?**

**Answer:** Interview answer: I would contain the impact, check trace IDs, state and external receipts, then classify the failure as transient, permanent or unknown outcome. I would not blindly repeat a write. After fixing the cause, I would add the incident as a versioned regression case and measure field extraction accuracy and rejected-bad-data rate.


**Q53. [Interview] When would you avoid a framework or model for pipeline execution?**

**Answer:** Interview answer: When the rules and data contracts are deterministic, a small application service or workflow is usually easier to test and operate. I add an agent or new framework only when variable inputs and evidence show a measurable improvement that offsets extra coordination, cost and risk.


**Q54. [Interview] How would you demonstrate L3 production readiness for M34.3?**

**Answer:** Interview answer: I would present a working repository, a state and permission diagram, the document pipeline manifest with extraction quality and lineage, known limitations, representative evaluation fixtures, failure-injection results and tracing. I would also show restart behavior and an operator takeover path where needed.
