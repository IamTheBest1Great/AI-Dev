**Answer:** Interview answer: Acquisition and extraction addresses the need to transform messy source data into trusted, lineage-rich AI inputs. I would begin with a bounded design for a document ingestion and intelligence pipeline, then specify contracts for Connectors and Crawling. I would measure field extraction accuracy and rejected-bad-data rate, verify the actual outcome and demonstrate handling of the primary failure: a scanned table is flattened and loses row-to-column relationships.

**Answer:** Interview answer: First define their separate responsibilities. In this part of a document ingestion and intelligence pipeline, Crawling is an explicit design concern. In this part of a document ingestion and intelligence pipeline, File uploads is an explicit design concern.


**Q72. [Interview] What would you do if API ingestion fails in production?**

**Answer:** Interview answer: I would contain the impact, check trace IDs, state and external receipts, then classify the failure as transient, permanent or unknown outcome. I would not blindly repeat a write. After fixing the cause, I would add the incident as a versioned regression case and measure field extraction accuracy and rejected-bad-data rate.


**Q73. [Interview] When would you avoid a framework or model for acquisition and extraction?**

**Answer:** Interview answer: When the rules and data contracts are deterministic, a small application service or workflow is usually easier to test and operate. I add an agent or new framework only when variable inputs and evidence show a measurable improvement that offsets extra coordination, cost and risk.


**Q74. [Interview] How would you demonstrate L3 production readiness for M34.1?**

**Answer:** Interview answer: I would present a working repository, a state and permission diagram, the document pipeline manifest with extraction quality and lineage, known limitations, representative evaluation fixtures, failure-injection results and tracing. I would also show restart behavior and an operator takeover path where needed.
