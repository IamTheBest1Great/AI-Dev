## Cross-cutting production interview drill

These questions are adapted from the source study guide’s interview section and assess how the individual concepts work together.

**Q77. [Interview] Explain shared developer capabilities to an interviewer.**

**Answer:** Interview answer: Shared developer capabilities addresses the need to offer shared building blocks without obstructing application ownership. I would begin with a bounded design for an internal AI developer platform used by multiple teams, then specify contracts for Model gateway and Prompt registry. I would measure time to first approved deployment and platform reliability, verify the actual outcome and demonstrate handling of the primary failure:.


**Q78. [Interview] How would you design Model gateway from scratch?**

**Answer:** Interview answer: I would identify the trusted input source, decide which component owns the operation, define typed fields, and specify success and failure states. Central routing/adapter layer for multiple models, policy enforcement and metering, with versioned behavior contracts. Then I would create at least a happy-path and an unauthorized/invalid-input test.


**Q79. [Interview] How do Prompt registry and Tool registry interact?**

**Answer:** Interview answer: First define their separate responsibilities. Versioned storage for prompt templates and associated evaluation/release metadata. Catalog of callable tools, schemas, risk levels and permissions used by agent runtimes. I would connect them only through a typed handoff with provenance and an explicit postcondition, rather than allowing hidden state coupling.


**Q80. [Interview] What would you do if Agent registry fails in production?**

**Answer:** Interview answer: I would contain the impact, check trace IDs, state and external receipts, then classify the failure as transient, permanent or unknown outcome. I would not blindly repeat a write. After fixing the cause, I would add the incident as a versioned regression case and measure time to first approved deployment and platform reliability.


**Q81. [Interview] When would you avoid a framework or model for shared developer capabilities?**

**Answer:** Interview answer: When the rules and data contracts are deterministic, a small application service or workflow is usually easier to test and operate. I add an agent or new framework only when variable inputs and evidence show a measurable improvement that offsets extra coordination, cost and risk.


**Q82. [Interview] How would you demonstrate L3 production readiness for M31.1?**

**Answer:** Interview answer: I would present a working repository, a state and permission diagram, the platform capability map and developer self-service API, known limitations, representative evaluation fixtures, failure-injection results and tracing. I would also show restart behavior and an operator takeover path where needed.
