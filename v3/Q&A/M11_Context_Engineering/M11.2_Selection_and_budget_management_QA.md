## Cross-cutting production interview drill

These questions are adapted from the source study guide’s interview section and assess how the individual concepts work together.

**Q29. [Interview] Explain selection and budget management to an interviewer.**

**Answer:** Follow-up 1 — What would you test first? A negative case involving summarize completed work and a normal task with a verified outcome.


**Q30. [Interview] How would you design Remove irrelevant history from scratch?**

**Answer:** Interview answer: I would identify the trusted input source, decide which component owns the operation, define typed fields, and specify success and failure states. Discard previous turns that no longer help solve the current task; retain references to full logs when auditability requires them. Then I would create at least a happy-path and an unauthorized/invalid-input test.


**Q31. [Interview] How do Compress repeated tool output and Summarize completed work interact?**

**Answer:** Interview answer: First define their separate responsibilities. Replace redundant returned rows or logs with a bounded summary plus stable identifiers, preserving exceptions, confidence and important errors. Record verified completed stages, artifacts and pending work, separating actions already performed from actions only proposed. I would connect them only through a typed handoff with provenance and an explicit postcondition, rather than allowing hidden state coupling.


**Q32. [Interview] What would you do if Keep critical constraints persistent fails in production?**

**Answer:** Interview answer: I would contain the impact, check trace IDs, state and external receipts, then classify the failure as transient, permanent or unknown outcome. I would not blindly repeat a write. After fixing the cause, I would add the incident as a versioned regression case and measure critical-constraint retention and cited-answer correctness.


**Q33. [Interview] When would you avoid a framework or model for selection and budget management?**

**Answer:** Interview answer: When the rules and data contracts are deterministic, a small application service or workflow is usually easier to test and operate. I add an agent or new framework only when variable inputs and evidence show a measurable improvement that offsets extra coordination, cost and risk.


**Q34. [Interview] How would you demonstrate L3 production readiness for M11.2?**

**Answer:** Interview answer: I would present a working repository, a state and permission diagram, the versioned context manifest with token counts and source IDs, known limitations, representative evaluation fixtures, failure-injection results and tracing. I would also show restart behavior and an operator takeover path where needed.
