## Cross-cutting production interview drill

These questions are adapted from the source study guide’s interview section and assess how the individual concepts work together.

**Q33. [Interview] Explain context integrity and failure analysis to an interviewer.**

**Answer:** Interview answer: Context integrity and failure analysis addresses the need to assemble accurate context under a fixed model token budget. I would begin with a bounded design for an enterprise RAG-based incident-investigation assistant, then specify contracts for Lost-in-the-middle and Context poisoning. I would measure critical-constraint retention and cited-answer correctness, verify the actual outcome and demonstrate handling of the primary failure:.


**Q34. [Interview] How would you design Lost-in-the-middle from scratch?**

**Answer:** Interview answer: I would identify the trusted input source, decide which component owns the operation, define typed fields, and specify success and failure states. Long prompts may cause an important fact in the middle to receive less effective attention than similarly relevant facts near the beginning or end. Test placement effects, but do not rely on ordering to enforce security. Then I would create at least a happy-path and an unauthorized/invalid-input test.


**Q35. [Interview] How do Context poisoning and Stale instructions interact?**

**Answer:** Interview answer: First define their separate responsibilities. An attacker or malfunction introduces misleading facts or instructions into material the agent later reads. Validate origins, treat retrieved text as untrusted, and make policy decisions outside the model. A cached or summarized instruction survives after the active rule changes. Pin policy versions and rebuild or invalidate affected context rather than mixing old and new constraints.


**Q36. [Interview] What would you do if Contradictory state fails in production?**

**Answer:** Interview answer: I would contain the impact, check trace IDs, state and external receipts, then classify the failure as transient, permanent or unknown outcome. I would not blindly repeat a write. After fixing the cause, I would add the incident as a versioned regression case and measure critical-constraint retention and cited-answer correctness.


**Q37. [Interview] When would you avoid a framework or model for context integrity and failure analysis?**

**Answer:** Interview answer: When the rules and data contracts are deterministic, a small application service or workflow is usually easier to test and operate. I add an agent or new framework only when variable inputs and evidence show a measurable improvement that offsets extra coordination, cost and risk.


**Q38. [Interview] How would you demonstrate L3 production readiness for M11.3?**

**Answer:** Interview answer: I would present a working repository, a state and permission diagram, the versioned context manifest with token counts and source IDs, known limitations, representative evaluation fixtures, failure-injection results and tracing. I would also show restart behavior and an operator takeover path where needed.
