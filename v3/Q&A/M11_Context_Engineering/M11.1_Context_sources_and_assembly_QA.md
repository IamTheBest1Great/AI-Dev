## M11.1.1 — Context as a system

**Q1. [Interview] What should an engineer understand about Context as a system (M11.1.1)?**

**Answer:** Treat context as a scarce runtime resource.


**Q2. [Scenario] Why could overlooking Context as a system create problems in a multi-tenant RAG incident-investigation assistant?**

**Answer:** In an enterprise RAG-based incident-investigation assistant, this changes the decision criteria or the allowed workflow. Record who owns the rule, when it applies and how to verify compliance.

## Cross-cutting production interview drill

These questions are adapted from the source study guide’s interview section and assess how the individual concepts work together.

**Q83. [Interview] Explain context sources and assembly to an interviewer.**

**Answer:** Interview answer: Context sources and assembly addresses the need to assemble accurate context under a fixed model token budget. I would begin with a bounded design for an enterprise RAG-based incident-investigation assistant, then specify contracts for Context assembly and Context selection. I would measure critical-constraint retention and cited-answer correctness, verify the actual outcome and demonstrate handling of the primary failure:.


**Q84. [Interview] How would you design Context assembly from scratch?**

**Answer:** Interview answer: I would identify the trusted input source, decide which component owns the operation, define typed fields, and specify success and failure states. Construct the exact model input by combining instruction hierarchy, the current request, state, selected history, tools, and relevant evidence. Assembly is a controlled pipeline with a token ledger, not blind concatenation. Then I would create at least a happy-path and an unauthorized/invalid-input test.


**Q85. [Interview] How do Context selection and Context prioritization interact?**

**Answer:** Interview answer: First define their separate responsibilities. Choose the subset of available material that is necessary for the current decision. Relevance, freshness, authority, permissions and token cost all matter; high semantic similarity alone is insufficient. Give non-negotiable constraints and recent authoritative state a protected place in the budget; use softer budgets for optional examples and background. The order of information affects attention and truncation behavior.


**Q86. [Interview] What would you do if Context routing fails in production?**

**Answer:** Interview answer: I would contain the impact, check trace IDs, state and external receipts, then classify the failure as transient, permanent or unknown outcome. I would not blindly repeat a write. After fixing the cause, I would add the incident as a versioned regression case and measure critical-constraint retention and cited-answer correctness.


**Q87. [Interview] When would you avoid a framework or model for context sources and assembly?**

**Answer:** Interview answer: When the rules and data contracts are deterministic, a small application service or workflow is usually easier to test and operate. I add an agent or new framework only when variable inputs and evidence show a measurable improvement that offsets extra coordination, cost and risk.


**Q88. [Interview] How would you demonstrate L3 production readiness for M11.1?**

**Answer:** Interview answer: I would present a working repository, a state and permission diagram, the versioned context manifest with token counts and source IDs, known limitations, representative evaluation fixtures, failure-injection results and tracing. I would also show restart behavior and an operator takeover path where needed.
