## Cross-cutting production interview drill

These questions are adapted from the source study guide’s interview section and assess how the individual concepts work together.

**Q5. [Interview] Explain context lifecycle to an interviewer.**

**Answer:** Interview answer: Context lifecycle addresses the need to assemble accurate context under a fixed model token budget. I would begin with a bounded design for an enterprise RAG-based incident-investigation assistant, then specify contracts for Sources and authority and Assembly and evaluation. I would measure critical-constraint retention and cited-answer correctness, verify the actual outcome and demonstrate handling of the primary failure:.


**Q6. [Interview] How would you design Sources and authority from scratch?**

**Answer:** Interview answer: I would identify the trusted input source, decide which component owns the operation, define typed fields, and specify success and failure states. Treat this as an explicitly enforced identity or permission boundary. Bind the decision to the authenticated actor, tenant, action and target resource; re-check at the API or execution layer. Then I would create at least a happy-path and an unauthorized/invalid-input test.


**Q7. [Interview] How do Assembly and evaluation and State and evidence interact?**

**Answer:** Interview answer: First define their separate responsibilities. Define an expected outcome on representative fixtures. Compare observed behavior against a predeclared criterion; separate deterministic correctness from probabilistic model quality. Identify who owns this information, where it lives, and when it changes. Keep transient model context distinct from durable application state and enforce scope on every read and write.


**Q8. [Interview] What would you do if Validation fails in production?**

**Answer:** Interview answer: I would contain the impact, check trace IDs, state and external receipts, then classify the failure as transient, permanent or unknown outcome. I would not blindly repeat a write. After fixing the cause, I would add the incident as a versioned regression case and measure critical-constraint retention and cited-answer correctness.


**Q9. [Interview] When would you avoid a framework or model for context lifecycle?**

**Answer:** Interview answer: When the rules and data contracts are deterministic, a small application service or workflow is usually easier to test and operate. I add an agent or new framework only when variable inputs and evidence show a measurable improvement that offsets extra coordination, cost and risk.


**Q10. [Interview] How would you demonstrate L3 production readiness for M11.5?**

**Answer:** Interview answer: I would present a working repository, a state and permission diagram, the versioned context manifest with token counts and source IDs, known limitations, representative evaluation fixtures, failure-injection results and tracing. I would also show restart behavior and an operator takeover path where needed.
