## Cross-cutting production interview drill

These questions are adapted from the source study guide’s interview section and assess how the individual concepts work together.

**Q45. [Interview] Explain tenant architecture and isolation to an interviewer.**

**Answer:** Follow-up 1 — What would you test first? A negative case involving per-tenant configuration and a normal task with a verified outcome.


**Q46. [Interview] How would you design Tenant isolation from scratch?**

**Answer:** Interview answer: I would identify the trusted input source, decide which component owns the operation, define typed fields, and specify success and failure states. Enforce separate company data and state through API, DB, retrieval, caches, object keys and telemetry. Then I would create at least a happy-path and an unauthorized/invalid-input test.


**Q47. [Interview] How do Database isolation and Vector namespace isolation interact?**

**Answer:** Interview answer: First define their separate responsibilities. Database strategies such as separate databases/schemas or shared tables with robust row-level policy. Tenant-scoped index partitions or filters, combined with current authorization and source status checks. I would connect them only through a typed handoff with provenance and an explicit postcondition, rather than allowing hidden state coupling.


**Q48. [Interview] What would you do if Row-level security fails in production?**

**Answer:** Interview answer: I would contain the impact, check trace IDs, state and external receipts, then classify the failure as transient, permanent or unknown outcome. I would not blindly repeat a write. After fixing the cause, I would add the incident as a versioned regression case and measure cross-tenant access violations and billing reconciliation correctness.


**Q49. [Interview] When would you avoid a framework or model for tenant architecture and isolation?**

**Answer:** Interview answer: When the rules and data contracts are deterministic, a small application service or workflow is usually easier to test and operate. I add an agent or new framework only when variable inputs and evidence show a measurable improvement that offsets extra coordination, cost and risk.


**Q50. [Interview] How would you demonstrate L3 production readiness for M42.1?**

**Answer:** Interview answer: I would present a working repository, a state and permission diagram, the tenant-isolation test suite and usage/billing ledger, known limitations, representative evaluation fixtures, failure-injection results and tracing. I would also show restart behavior and an operator takeover path where needed.
