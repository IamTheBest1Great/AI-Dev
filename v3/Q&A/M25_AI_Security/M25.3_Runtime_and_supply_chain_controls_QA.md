## Cross-cutting production interview drill

These questions are adapted from the source study guide’s interview section and assess how the individual concepts work together.

**Q93. [Interview] Explain runtime and supply-chain controls to an interviewer.**

**Answer:** Follow-up 1 — What would you test first? A negative case involving sbom concepts and a normal task with a verified outcome.


**Q94. [Interview] How would you design Sandboxing from scratch?**

**Answer:** Interview answer: I would identify the trusted input source, decide which component owns the operation, define typed fields, and specify success and failure states. Run potentially unsafe code or tools behind constrained execution, file, process, credential and network boundaries. Use stronger isolation for untrusted code and evaluate escape paths. Then I would create at least a happy-path and an unauthorized/invalid-input test.


**Q95. [Interview] How do Network isolation and Domain allowlists interact?**

**Answer:** Interview answer: First define their separate responsibilities. Define the security and resource boundary in the infrastructure rather than only in agent instructions. Test its enforcement under unauthorized and exhausted-resource conditions. Approved network destinations for egress; account for redirects, DNS resolution and domain impersonation. I would connect them only through a typed handoff with provenance and an explicit postcondition, rather than allowing hidden state coupling.


**Q96. [Interview] What would you do if File restrictions fails in production?**

**Answer:** Interview answer: I would contain the impact, check trace IDs, state and external receipts, then classify the failure as transient, permanent or unknown outcome. I would not blindly repeat a write. After fixing the cause, I would add the incident as a versioned regression case and measure blocked unauthorized actions and no cross-tenant leakage.


**Q97. [Interview] When would you avoid a framework or model for runtime and supply-chain controls?**

**Answer:** Interview answer: When the rules and data contracts are deterministic, a small application service or workflow is usually easier to test and operate. I add an agent or new framework only when variable inputs and evidence show a measurable improvement that offsets extra coordination, cost and risk.


**Q98. [Interview] How would you demonstrate L3 production readiness for M25.3?**

**Answer:** Interview answer: I would present a working repository, a state and permission diagram, the security test suite and policy decision trace, known limitations, representative evaluation fixtures, failure-injection results and tracing. I would also show restart behavior and an operator takeover path where needed.
