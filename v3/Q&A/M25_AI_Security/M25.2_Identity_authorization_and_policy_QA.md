**Q198. [Interview] How would you design User identity from scratch?**

Treat this as an explicitly enforced identity or permission boundary. Bind the decision to the authenticated actor, tenant, action and target resource; re-check at the API or execution layer. Then I would create at least a happy-path and an unauthorized/invalid-input test.


**Q199. [Interview] How do Agent identity and Service/workload identity interact?**

**Answer:** Interview answer: First define their separate responsibilities. Principal representing a remote agent service, tied to credentials and operator accountability. Treat this as an explicitly enforced identity or permission boundary. Bind the decision to the authenticated actor, tenant, action and target resource; re-check at the API or execution layer. I would connect them only through a typed handoff with provenance and an explicit postcondition, rather than allowing hidden state coupling.


**Q200. [Interview] What would you do if Delegated identity fails in production?**

**Answer:** Interview answer: I would contain the impact, check trace IDs, state and external receipts, then classify the failure as transient, permanent or unknown outcome. I would not blindly repeat a write. After fixing the cause, I would add the incident as a versioned regression case and measure blocked unauthorized actions and no cross-tenant leakage.


**Q201. [Interview] When would you avoid a framework or model for identity, authorization and policy?**

**Answer:** Interview answer: When the rules and data contracts are deterministic, a small application service or workflow is usually easier to test and operate. I add an agent or new framework only when variable inputs and evidence show a measurable improvement that offsets extra coordination, cost and risk.


**Q202. [Interview] How would you demonstrate L3 production readiness for M25.2?**

**Answer:** Interview answer: I would present a working repository, a state and permission diagram, the security test suite and policy decision trace, known limitations, representative evaluation fixtures, failure-injection results and tracing. I would also show restart behavior and an operator takeover path where needed.
