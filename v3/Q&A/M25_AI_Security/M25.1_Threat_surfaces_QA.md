## Cross-cutting production interview drill

These questions are adapted from the source study guide’s interview section and assess how the individual concepts work together.

**Q143. [Interview] Explain threat surfaces to an interviewer.**

**Answer:** Follow-up 1 — What would you test first? A negative case involving credential theft and a normal task with a verified outcome.


**Q144. [Interview] How would you design Prompt injection from scratch?**

**Answer:** Interview answer: I would identify the trusted input source, decide which component owns the operation, define typed fields, and specify success and failure states. Untrusted content contains instructions intended to redirect model behavior, often by masquerading as a higher-priority message. Keep retrieved documents and tool responses in a lower-trust data channel. Then I would create at least a happy-path and an unauthorized/invalid-input test.


**Q145. [Interview] How do Indirect prompt injection and Jailbreaks interact?**

**Answer:** Interview answer: First define their separate responsibilities. The attacker places instructions in sources the defender agent is expected to read: webpages, files, tickets or tool results. Correct design never treats such content as authorization. Attempts to steer a model into disregarding its behavioral constraints. Use layered application controls because prompt-level refusals do not replace tool permissions.


**Q146. [Interview] What would you do if Data leakage fails in production?**

**Answer:** Interview answer: I would contain the impact, check trace IDs, state and external receipts, then classify the failure as transient, permanent or unknown outcome. I would not blindly repeat a write. After fixing the cause, I would add the incident as a versioned regression case and measure blocked unauthorized actions and no cross-tenant leakage.


**Q147. [Interview] When would you avoid a framework or model for threat surfaces?**

**Answer:** Interview answer: When the rules and data contracts are deterministic, a small application service or workflow is usually easier to test and operate. I add an agent or new framework only when variable inputs and evidence show a measurable improvement that offsets extra coordination, cost and risk.


**Q148. [Interview] How would you demonstrate L3 production readiness for M25.1?**

**Answer:** Interview answer: I would present a working repository, a state and permission diagram, the security test suite and policy decision trace, known limitations, representative evaluation fixtures, failure-injection results and tracing. I would also show restart behavior and an operator takeover path where needed.
