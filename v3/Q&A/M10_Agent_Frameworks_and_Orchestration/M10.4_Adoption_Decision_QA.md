## Part 3 — Inspect State and Failure Semantics

**Q59. [Conceptual] Explain Part 3 — Inspect State and Failure Semantics in simple, interview-ready language.**

**Answer:** A retry boundary determines whether executing the same node repeats an external effect. A state checkpoint is not a distributed atomic transaction; business effect ledgers and reconciliation matter.


**Q60. [Interview] Why does Part 3 — Inspect State and Failure Semantics matter, and what is one important design implication?**

**Answer:** Concurrent nodes may produce updates in a super-step. Checkpoint semantics, reducers and replay behavior must be examined for your version. A partially completed parallel step can have different recovery behavior from sequential steps; protect each external side effect regardless.
