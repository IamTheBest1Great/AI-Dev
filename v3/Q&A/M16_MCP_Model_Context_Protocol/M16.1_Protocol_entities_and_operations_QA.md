## Cross-cutting production interview drill

These questions are adapted from the source study guide’s interview section and assess how the individual concepts work together.

**Q61. [Interview] Explain protocol entities and operations to an interviewer.**

**Answer:** Interview answer: Protocol entities and operations addresses the need to expose typed capabilities with authenticated, per-call authorization. I would begin with a bounded design for a remote MCP gateway for internal enterprise tools, then specify contracts for Hosts and Clients. I would measure unauthorized calls rejected and supported operations interoperable, verify the actual outcome and demonstrate handling of the primary failure:.


**Q62. [Interview] How would you design Hosts from scratch?**

**Answer:** Interview answer: I would identify the trusted input source, decide which component owns the operation, define typed fields, and specify success and failure states. Applications that contain or manage MCP clients and expose capabilities to models while controlling user consent, tool access and context. Then I would create at least a happy-path and an unauthorized/invalid-input test.


**Q63. [Interview] How do Clients and Servers interact?**

**Answer:** Interview answer: First define their separate responsibilities. Protocol peers created by a host that connect to MCP servers and negotiate available capabilities. Services that expose MCP tools, resources or prompts through a versioned protocol and enforce their own authorization. I would connect them only through a typed handoff with provenance and an explicit postcondition, rather than allowing hidden state coupling.


**Q64. [Interview] What would you do if Tools fails in production?**

**Answer:** Interview answer: I would contain the impact, check trace IDs, state and external receipts, then classify the failure as transient, permanent or unknown outcome. I would not blindly repeat a write. After fixing the cause, I would add the incident as a versioned regression case and measure unauthorized calls rejected and supported operations interoperable.


**Q65. [Interview] When would you avoid a framework or model for protocol entities and operations?**

**Answer:** Interview answer: When the rules and data contracts are deterministic, a small application service or workflow is usually easier to test and operate. I add an agent or new framework only when variable inputs and evidence show a measurable improvement that offsets extra coordination, cost and risk.


**Q66. [Interview] How would you demonstrate L3 production readiness for M16.1?**

**Answer:** Interview answer: I would present a working repository, a state and permission diagram, the version-pinned MCP integration and conformance test report, known limitations, representative evaluation fixtures, failure-injection results and tracing. I would also show restart behavior and an operator takeover path where needed.
