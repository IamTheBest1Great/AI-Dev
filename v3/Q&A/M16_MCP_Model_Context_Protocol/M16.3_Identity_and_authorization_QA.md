## Cross-cutting production interview drill

These questions are adapted from the source study guide’s interview section and assess how the individual concepts work together.

**Q45. [Interview] Explain identity and authorization to an interviewer.**

**Answer:** Interview answer: Identity and authorization addresses the need to expose typed capabilities with authenticated, per-call authorization. I would begin with a bounded design for a remote MCP gateway for internal enterprise tools, then specify contracts for Authentication and Authorization. I would measure unauthorized calls rejected and supported operations interoperable, verify the actual outcome and demonstrate handling of the primary failure:.


**Q46. [Interview] How would you design Authentication from scratch?**

**Answer:** Interview answer: I would identify the trusted input source, decide which component owns the operation, define typed fields, and specify success and failure states. Verify the identity of a caller, client or workload using an accepted credential and protocol. Then I would create at least a happy-path and an unauthorized/invalid-input test.


**Q47. [Interview] How do Authorization and OAuth concepts interact?**

**Answer:** Interview answer: First define their separate responsibilities. Decide which authenticated principal may perform a specific action on a specific resource under current policy. OAuth provides delegated authorization using scoped tokens with defined issuers, audiences, clients and expiry. Token presence alone is not proof that a particular resource is authorized.


**Q48. [Interview] What would you do if Client identity fails in production?**

**Answer:** Interview answer: I would contain the impact, check trace IDs, state and external receipts, then classify the failure as transient, permanent or unknown outcome. I would not blindly repeat a write. After fixing the cause, I would add the incident as a versioned regression case and measure unauthorized calls rejected and supported operations interoperable.


**Q49. [Interview] When would you avoid a framework or model for identity and authorization?**

**Answer:** Interview answer: When the rules and data contracts are deterministic, a small application service or workflow is usually easier to test and operate. I add an agent or new framework only when variable inputs and evidence show a measurable improvement that offsets extra coordination, cost and risk.


**Q50. [Interview] How would you demonstrate L3 production readiness for M16.3?**

**Answer:** Interview answer: I would present a working repository, a state and permission diagram, the version-pinned MCP integration and conformance test report, known limitations, representative evaluation fixtures, failure-injection results and tracing. I would also show restart behavior and an operator takeover path where needed.
