## Cross-cutting production interview drill

These questions are adapted from the source study guide’s interview section and assess how the individual concepts work together.

**Q49. [Interview] Explain task interaction and user control to an interviewer.**

**Answer:** Interview answer: Task interaction and user control addresses the need to let users inspect progress, evidence and actions while retaining control. I would begin with a bounded design for a React agent workspace for multi-step AI tasks, then specify contracts for Streaming UI and Agent status. I would measure task completion and approval/error recovery usability, verify the actual outcome and demonstrate handling of the primary failure:.


**Q50. [Interview] How would you design Streaming UI from scratch?**

**Answer:** Interview answer: I would identify the trusted input source, decide which component owns the operation, define typed fields, and specify success and failure states. Progressive display of model output and task events; label provisional text separately from verified completed actions. Then I would create at least a happy-path and an unauthorized/invalid-input test.


**Q51. [Interview] How do Agent status and Progress interact?**

**Answer:** Interview answer: First define their separate responsibilities. Authoritative task state such as queued, running, waiting for approval, completed, failed or canceled, synchronized with the backend. Meaningful milestone events showing what has actually completed, not an invented percentage for unpredictable model work. I would connect them only through a typed handoff with provenance and an explicit postcondition, rather than allowing hidden state coupling.


**Q52. [Interview] What would you do if Citations fails in production?**

**Answer:** Interview answer: I would contain the impact, check trace IDs, state and external receipts, then classify the failure as transient, permanent or unknown outcome. I would not blindly repeat a write. After fixing the cause, I would add the incident as a versioned regression case and measure task completion and approval/error recovery usability.


**Q53. [Interview] When would you avoid a framework or model for task interaction and user control?**

**Answer:** Interview answer: When the rules and data contracts are deterministic, a small application service or workflow is usually easier to test and operate. I add an agent or new framework only when variable inputs and evidence show a measurable improvement that offsets extra coordination, cost and risk.


**Q54. [Interview] How would you demonstrate L3 production readiness for M35.1?**

**Answer:** Interview answer: I would present a working repository, a state and permission diagram, the accessible React task workspace and event-contract tests, known limitations, representative evaluation fixtures, failure-injection results and tracing. I would also show restart behavior and an operator takeover path where needed.
