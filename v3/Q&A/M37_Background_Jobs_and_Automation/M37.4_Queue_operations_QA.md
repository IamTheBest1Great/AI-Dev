## Cross-cutting production interview drill

These questions are adapted from the source study guide’s interview section and assess how the individual concepts work together.

**Q3. [Interview] Explain queue operations to an interviewer.**

**Answer:** Interview answer: Queue operations addresses the need to run fair, observable work with restart and cancellation semantics. I would begin with a bounded design for a background job system for scheduled AI tasks, then specify contracts for Fairness and recovery and State and evidence. I would measure completion latency, retry rate and duplicate side effects, verify the actual outcome and demonstrate handling of the primary failure:.


**Q4. [Interview] How would you design Fairness and recovery from scratch?**

**Answer:** Interview answer: I would identify the trusted input source, decide which component owns the operation, define typed fields, and specify success and failure states. Define expected behavior before, during and after failure. Use bounded retries, transaction/receipt checks and explicit unknown-outcome states instead of assuming every retry is safe. Then I would create at least a happy-path and an unauthorized/invalid-input test.


**Q5. [Interview] How do State and evidence and Validation interact?**

**Answer:** Interview answer: First define their separate responsibilities. Identify who owns this information, where it lives, and when it changes. Keep transient model context distinct from durable application state and enforce scope on every read and write. Checking input and output data against schemas, required fields and domain constraints before further action. I would connect them only through a typed handoff with provenance and an explicit postcondition, rather than allowing hidden state coupling.


**Q6. [Interview] What would you do if Failure recovery fails in production?**

**Answer:** Interview answer: I would contain the impact, check trace IDs, state and external receipts, then classify the failure as transient, permanent or unknown outcome. I would not blindly repeat a write. After fixing the cause, I would add the incident as a versioned regression case and measure completion latency, retry rate and duplicate side effects.


**Q7. [Interview] When would you avoid a framework or model for queue operations?**

**Answer:** Interview answer: When the rules and data contracts are deterministic, a small application service or workflow is usually easier to test and operate. I add an agent or new framework only when variable inputs and evidence show a measurable improvement that offsets extra coordination, cost and risk.


**Q8. [Interview] How would you demonstrate L3 production readiness for M37.4?**

**Answer:** Interview answer: I would present a working repository, a state and permission diagram, the job state ledger and worker operations dashboard, known limitations, representative evaluation fixtures, failure-injection results and tracing. I would also show restart behavior and an operator takeover path where needed.
