## Cross-cutting production interview drill

These questions are adapted from the source study guide’s interview section and assess how the individual concepts work together.

**Q7. [Interview] Explain conversation evaluation to an interviewer.**

**Answer:** Follow-up 1 — What would you test first? A negative case involving trust, quality & control and a normal task with a verified outcome.


**Q8. [Interview] How would you design Trust, Quality & Control from scratch?**

**Answer:** Interview answer: I would identify the trusted input source, decide which component owns the operation, define typed fields, and specify success and failure states. Treat this as an explicitly enforced identity or permission boundary. Bind the decision to the authenticated actor, tenant, action and target resource; re-check at the API or execution layer. Then I would create at least a happy-path and an unauthorized/invalid-input test.


**Q9. [Interview] How do User experience and quality and State and evidence interact?**

**Answer:** Interview answer: First define their separate responsibilities. Define an expected outcome on representative fixtures. Compare observed behavior against a predeclared criterion; separate deterministic correctness from probabilistic model quality. Identify who owns this information, where it lives, and when it changes. Keep transient model context distinct from durable application state and enforce scope on every read and write.


**Q10. [Interview] What would you do if Validation fails in production?**

**Answer:** Interview answer: I would contain the impact, check trace IDs, state and external receipts, then classify the failure as transient, permanent or unknown outcome. I would not blindly repeat a write. After fixing the cause, I would add the incident as a versioned regression case and measure end-of-turn latency, completion rate and interruption recovery.


**Q11. [Interview] When would you avoid a framework or model for conversation evaluation?**

**Answer:** Interview answer: When the rules and data contracts are deterministic, a small application service or workflow is usually easier to test and operate. I add an agent or new framework only when variable inputs and evidence show a measurable improvement that offsets extra coordination, cost and risk.


**Q12. [Interview] How would you demonstrate L3 production readiness for M24.5?**

**Answer:** Interview answer: I would present a working repository, a state and permission diagram, the conversation event log with latency and handoff markers, known limitations, representative evaluation fixtures, failure-injection results and tracing. I would also show restart behavior and an operator takeover path where needed.
