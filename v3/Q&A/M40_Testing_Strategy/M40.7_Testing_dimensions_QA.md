## Cross-cutting production interview drill

These questions are adapted from the source study guide’s interview section and assess how the individual concepts work together.

**Q3. [Interview] Explain testing dimensions to an interviewer.**

**Answer:** Interview answer: Testing dimensions addresses the need to separate deterministic correctness from probabilistic task-quality evidence. I would begin with a bounded design for a test framework for agentic AI workflows, then specify contracts for Independent classification axes and State and evidence. I would measure defect detection and real-task completion coverage, verify the actual outcome and demonstrate handling of the primary failure:.


**Q4. [Interview] How would you design Independent classification axes from scratch?**

**Answer:** Interview answer: I would identify the trusted input source, decide which component owns the operation, define typed fields, and specify success and failure states. In this part of a test framework for agentic AI workflows, Independent classification axes is an explicit design concern. Define its inputs, owner, observable result and failure handling before implementing it. Its purpose must be linked to the overall goal: separate deterministic correctness from probabilistic task-quality evidence.


**Q5. [Interview] How do State and evidence and Validation interact?**

**Answer:** Interview answer: First define their separate responsibilities. Identify who owns this information, where it lives, and when it changes. Keep transient model context distinct from durable application state and enforce scope on every read and write. Checking input and output data against schemas, required fields and domain constraints before further action. I would connect them only through a typed handoff with provenance and an explicit postcondition, rather than allowing hidden state coupling.


**Q6. [Interview] What would you do if Failure recovery fails in production?**

**Answer:** Interview answer: I would contain the impact, check trace IDs, state and external receipts, then classify the failure as transient, permanent or unknown outcome. I would not blindly repeat a write. After fixing the cause, I would add the incident as a versioned regression case and measure defect detection and real-task completion coverage.


**Q7. [Interview] When would you avoid a framework or model for testing dimensions?**

**Answer:** Interview answer: When the rules and data contracts are deterministic, a small application service or workflow is usually easier to test and operate. I add an agent or new framework only when variable inputs and evidence show a measurable improvement that offsets extra coordination, cost and risk.


**Q8. [Interview] How would you demonstrate L3 production readiness for M40.7?**

**Answer:** Interview answer: I would present a working repository, a state and permission diagram, the layered test matrix and regression suite, known limitations, representative evaluation fixtures, failure-injection results and tracing. I would also show restart behavior and an operator takeover path where needed.
