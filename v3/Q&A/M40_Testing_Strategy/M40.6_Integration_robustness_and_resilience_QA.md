## Cross-cutting production interview drill

These questions are adapted from the source study guide’s interview section and assess how the individual concepts work together.

**Q61. [Interview] Explain integration, robustness and resilience to an interviewer.**

**Answer:** Follow-up 1 — What would you test first? A negative case involving performance and failure and a normal task with a verified outcome.


**Q62. [Interview] How would you design Contract testing from scratch?**

**Answer:** Interview answer: I would identify the trusted input source, decide which component owns the operation, define typed fields, and specify success and failure states. Define an expected outcome on representative fixtures. Compare observed behavior against a predeclared criterion; separate deterministic correctness from probabilistic model quality. Then I would create at least a happy-path and an unauthorized/invalid-input test.


**Q63. [Interview] How do Consumer-driven contract awareness and Database migration tests interact?**

**Answer:** Interview answer: First define their separate responsibilities. In this part of a test framework for agentic AI workflows, Consumer-driven contract awareness is an explicit design concern. Define its inputs, owner, observable result and failure handling before implementing it. Its purpose must be linked to the overall goal: separate deterministic correctness from probabilistic task-quality evidence. Make lifecycle and version information explicit.


**Q64. [Interview] What would you do if Webhook signature/replay tests fails in production?**

**Answer:** Interview answer: I would contain the impact, check trace IDs, state and external receipts, then classify the failure as transient, permanent or unknown outcome. I would not blindly repeat a write. After fixing the cause, I would add the incident as a versioned regression case and measure defect detection and real-task completion coverage.


**Q65. [Interview] When would you avoid a framework or model for integration, robustness and resilience?**

**Answer:** Interview answer: When the rules and data contracts are deterministic, a small application service or workflow is usually easier to test and operate. I add an agent or new framework only when variable inputs and evidence show a measurable improvement that offsets extra coordination, cost and risk.


**Q66. [Interview] How would you demonstrate L3 production readiness for M40.6?**

**Answer:** Interview answer: I would present a working repository, a state and permission diagram, the layered test matrix and regression suite, known limitations, representative evaluation fixtures, failure-injection results and tracing. I would also show restart behavior and an operator takeover path where needed.
