## Cross-cutting production interview drill

These questions are adapted from the source study guide’s interview section and assess how the individual concepts work together.

**Q25. [Interview] Explain adversarial verification to an interviewer.**

**Answer:** Interview answer: Adversarial verification addresses the need to separate deterministic correctness from probabilistic task-quality evidence. I would begin with a bounded design for a test framework for agentic AI workflows, then specify contracts for Prompt injection and Malicious documents. I would measure defect detection and real-task completion coverage, verify the actual outcome and demonstrate handling of the primary failure:.


**Q26. [Interview] How would you design Prompt injection from scratch?**

**Answer:** Interview answer: I would identify the trusted input source, decide which component owns the operation, define typed fields, and specify success and failure states. Untrusted content contains instructions intended to redirect model behavior, often by masquerading as a higher-priority message. Keep retrieved documents and tool responses in a lower-trust data channel. Then I would create at least a happy-path and an unauthorized/invalid-input test.


**Q27. [Interview] How do Malicious documents and Tool abuse interact?**

**Answer:** Interview answer: First define their separate responsibilities. Attacker-controlled files or pages embedding instructions, deceptive claims or active content that must remain lower-trust data. Misusing available tool endpoints or composing them to access unintended resources; verify action/resource policy independent of the model. I would connect them only through a typed handoff with provenance and an explicit postcondition, rather than allowing hidden state coupling.


**Q28. [Interview] What would you do if Data leakage fails in production?**

**Answer:** Interview answer: I would contain the impact, check trace IDs, state and external receipts, then classify the failure as transient, permanent or unknown outcome. I would not blindly repeat a write. After fixing the cause, I would add the incident as a versioned regression case and measure defect detection and real-task completion coverage.


**Q29. [Interview] When would you avoid a framework or model for adversarial verification?**

**Answer:** Interview answer: When the rules and data contracts are deterministic, a small application service or workflow is usually easier to test and operate. I add an agent or new framework only when variable inputs and evidence show a measurable improvement that offsets extra coordination, cost and risk.


**Q30. [Interview] How would you demonstrate L3 production readiness for M40.4?**

**Answer:** Interview answer: I would present a working repository, a state and permission diagram, the layered test matrix and regression suite, known limitations, representative evaluation fixtures, failure-injection results and tracing. I would also show restart behavior and an operator takeover path where needed.
