## A4. Why Query Processing Exists

**Q5. [Conceptual] Explain A4. Why Query Processing Exists in simple, interview-ready language.**

**Answer:** "Where is document M-104?" → metadata lookup "Explain the reasoning behind the revised procedure." → dense/hybrid passage search "How many open tasks belong to ship A?" → SQL aggregation "Which components depend on pump P-17?" → graph traversal "What is the status of ticket T-82?" → live API.


**Q6. [Interview] Why does A4. Why Query Processing Exists matter, and what is one important design implication?**

**Answer:** Definitions. Query processing = interpreting and preparing a request before searching. Retrieval routing = choosing which evidence sources/methods handle it.

<a id="1-2-query-normalization"></a>
### 1.2 Query Normalization

**Q23. [Conceptual] Explain Query Normalization in simple, interview-ready language.**

**Answer:** Definition: Making superficial variations easier to handle (whitespace, Unicode, dates, controlled casing) without changing meaning. Normalization ≠ semantic rewriting; removing repeated spaces is not changing "before" to "after.".


**Q24. [Interview] Why does Query Normalization matter, and what is one important design implication?**

**Answer:** Serial numbers, error codes, filenames, clause numbers, model names, document IDs are retrieval anchors. Aggressive stemming/punctuation removal damages them. P-17, P17, P-1.7 may be different things. Maintain an analyzed text field and a separate exact-value field.
