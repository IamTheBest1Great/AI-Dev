## A1. Advanced RAG Fundamentals

**Q1. [Conceptual] Explain A1. Advanced RAG Fundamentals in simple, interview-ready language.**

**Answer:** RAG uses evidence from an external source to help a model answer. Retrieval decides what material is available; generation decides what the answer says about it. The original research (Lewis et al.) combined a learned retriever with a generator; in practice "RAG" now broadly means assembling documents, DB results or tool outputs into a model's context.


**Q2. [Interview] Why does A1. Advanced RAG Fundamentals matter, and what is one important design implication?**

**Answer:** Which observed failure should it reduce? What simpler intervention addresses the same failure? Which metric should improve without breaking security, freshness, or cost? What new derived data and operational duties will it introduce?

### 2.2 Late Interaction and ColBERT

**Q27. [Conceptual] Explain Late Interaction and ColBERT in simple, interview-ready language.**

**Answer:** It is not a full cross-encoder (no joint query-document transformer pass) and not a single vector per document.


**Q28. [Interview] Why does Late Interaction and ColBERT matter, and what is one important design implication?**

**Answer:** Late interaction keeps multiple fine-grained vectors per document (per token) and combines them with query vectors at scoring time. ColBERT encodes query and document tokens independently, then scores via token-level similarity (MaxSim). Preserves more matching detail than one pooled vector, while document-side work can be precomputed.

## Branch 4 — Reasoning & Orchestration

**Q51. [Conceptual] Explain Branch 4 — Reasoning & Orchestration in simple, interview-ready language.**

**Answer:** Failure propagation: if hop 1 resolves P-20 as P-21, later retrieval is internally consistent but answers the wrong question. Store intermediate entity IDs + supporting evidence; validate before continuing.


**Q52. [Interview] Why does Branch 4 — Reasoning & Orchestration matter, and what is one important design implication?**

**Answer:** A model trained to emit special reflection tokens for deciding when to retrieve and for assessing evidence/output. It is a trained framework, not "a prompt that says check your answer". Lesson: retrieval need and evidence support can be explicit decision points. A generic critique loop should be called a critique loop. Model reflection ≠ authorization, source existence, or correctness.


**Q53. [Scenario] A developer misunderstands Branch 4 — Reasoning & Orchestration while building a multi-tenant RAG assistant over versioned training manuals. How would you correct the design?**

**Answer:** Clarify the actual behavior: All required claims have supporting evidence. Last attempt found no new evidence. Same query/evidence set repeating. Hard cost/latency/hop budget reached. Sources conflict → clarify rather than search more. Demonstrate the difference with a concrete input and expected result before changing the system.

### 4.3 Agentic RAG and Action-Space Control

**Q59. [Conceptual] Explain Agentic RAG and Action-Space Control in simple, interview-ready language.**

**Answer:** Agentic RAG: a model/policy chooses retrieval actions, tools, follow-ups toward an information goal (e.g., ReAct, Yao et al.: interleaving reasoning and actions).
