## 1. Candidate Refinement Fundamentals

**Q1. [Conceptual] Explain Candidate Refinement Fundamentals in simple, interview-ready language.**

**Answer:** The central requirement of this section is explicit: basic reranking belongs in the main pipeline. It is a practical component to learn and evaluate before treating advanced methods such as HyDE, Self-RAG or graph retrieval as necessary.


**Q2. [Interview] Why does Candidate Refinement Fundamentals matter, and what is one important design implication?**

**Answer:** Candidate refinement turns a broad set of potentially useful search results into a smaller, better-supported selection of evidence. It includes detailed relevance scoring, removal of duplicate or ineligible material, and selection under the answer’s context budget.

## 2. Candidate Generation Versus Reranking

**Q3. [Conceptual] Explain Candidate Generation Versus Reranking in simple, interview-ready language.**

**Answer:** Its immediate goal is sufficient coverage of potentially relevant eligible evidence within a reasonable cost and latency budget. It does not need to place every relevant passage in perfect order if a later stage can improve the ranking.


**Q4. [Interview] Why does Candidate Generation Versus Reranking matter, and what is one important design implication?**

### Reranking versus generation

**Q9. [Conceptual] Explain Reranking versus generation in simple, interview-ready language.**

**Answer:** A generator writes the answer. A reranker selects evidence. Asking the generator to “choose the best passages” inside an enormous context is an alternative architecture, but it should not be assumed to replace an evaluated candidate-refinement stage.


**Q10. [Interview] Why does Reranking versus generation matter, and what is one important design implication?**

**Answer:** Separation makes debugging easier: the trace can show whether the right evidence was retrieved, whether it survived reranking, and whether the final answer used it.

**Q13. [Conceptual] Explain The Main Retrieval Pipeline in simple, interview-ready language.**

**Answer:** The exact placement of internal filtering depends on the engine. The invariant is that unauthorized source content must not reach external rerankers, generators, user-visible snippets or citations.

<a id="4-basic-reranking-and-cross-encoders"></a>
## 4. Basic Reranking and Cross-Encoders

**Q15. [Conceptual] Explain Basic Reranking and Cross-Encoders in simple, interview-ready language.**

**Answer:** A bi-encoder computes query and document representations independently, allowing document vectors to be prepared in advance. A cross-encoder jointly processes the pair, allowing interactions between the query and passage during scoring.


**Q16. [Interview] Why does Basic Reranking and Cross-Encoders matter, and what is one important design implication?**

**Answer:** Sentence Transformers documents this architectural distinction and the tradeoff between reusable embeddings and pair-specific scoring. Cross-encoder scores are useful for reranking a bounded set, while independent embeddings support efficient corpus-wide comparison. Source: Sentence Transformers cross-encoders.

## 5. Candidate Budgets and Recall Ceilings

**Q17. [Conceptual] Explain Candidate Budgets and Recall Ceilings in simple, interview-ready language.**

**Answer:** A larger pool can improve coverage, but it adds scoring work and distractors. The useful question is whether the additional candidates supply previously missing evidence often enough to justify the cost.


**Q18. [Interview] Why does Candidate Budgets and Recall Ceilings matter, and what is one important design implication?**

**Answer:** An exact identifier query may need few candidates. A multi-part comparison may need broader coverage. A router can choose different budgets, but that adds another policy to test.

## 6. Deduplication, Diversity and Evidence Coverage

**Q23. [Conceptual] Explain Deduplication, Diversity and Evidence Coverage in simple, interview-ready language.**

**Answer:** Remove exact duplicate candidates before spending expensive reranker work when identity and policy allow it. Distinguish duplicated records from legitimately separate sources containing similar text.


**Q24. [Interview] Why does Deduplication, Diversity and Evidence Coverage matter, and what is one important design implication?**

**Answer:** Overlapping chunks can include the same statement repeatedly. Their repetition should not create the impression of independent corroboration.

## 9. Implementation Contracts and Failure Handling

**Q37. [Conceptual] Explain Implementation Contracts and Failure Handling in simple, interview-ready language.**

**Answer:** Keep the query that produced candidates and the query used for reranking in the trace. If they differ, the difference should be deliberate and testable.

## 10. Permission and Source-Lifecycle Checks

**Q43. [Conceptual] Explain Permission and Source-Lifecycle Checks in simple, interview-ready language.**

**Answer:** A reranker can expose content to a model service. Therefore, candidate text must already be authorized for the user and approved for that processing environment before it is submitted.


**Q44. [Interview] Why does Permission and Source-Lifecycle Checks matter, and what is one important design implication?**

**Answer:** If the user asks for the current manual, eligibility should follow the source’s approved effective revision, not whichever passage receives the highest reranker score.

### Deletion and caches

**Q45. [Conceptual] Explain Deletion and caches in simple, interview-ready language.**

**Answer:** A cache key should include the authorized scope and relevant source/index generation, or the cache lookup must revalidate dependencies. The precise design can vary, but “cache hit means skip access checks” is not acceptable.

## 11. Project Exercise and Acceptance Evidence

**Q49. [Conceptual] Explain Project Exercise and Acceptance Evidence in simple, interview-ready language.**

**Answer:** Include at least one example where lexical retrieval is expected to help, one paraphrase case, one multi-part question, one wrong-version distractor, one restricted document and one deleted source.
