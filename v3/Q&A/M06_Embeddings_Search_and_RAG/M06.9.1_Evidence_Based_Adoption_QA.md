## 1. Evidence-Based Adoption Fundamentals

**Q1. [Conceptual] Explain Evidence-Based Adoption Fundamentals in simple, interview-ready language.**

**Answer:** Evidence-based adoption means choosing a technique because a well-designed evaluation shows that it improves the intended task under the constraints that matter.


**Q2. [Interview] Why does Evidence-Based Adoption Fundamentals matter, and what is one important design implication?**

**Answer:** A persuasive demonstration is useful for forming a hypothesis. It is not sufficient evidence for deploying a method across every user, document and query type.


<a id="2-establish-the-baseline"></a>
## 2. Establish the Baseline

**Q3. [Conceptual] Explain Establish the Baseline in simple, interview-ready language.**

**Answer:** A baseline is a concrete, reproducible system against which changes are compared. It includes the corpus, queries, preprocessing, models, indexes, filters, reranking, answer prompt and evaluation definitions.


**Q4. [Interview] Why does Establish the Baseline matter, and what is one important design implication?**

**Answer:** Use the same authorized source snapshot and equivalent evaluation tasks. A lexical baseline should receive reasonable tokenization and field configuration rather than being deliberately weak.

### Basic reranking remains in the main pipeline

**Q9. [Conceptual] Explain Basic reranking remains in the main pipeline in simple, interview-ready language.**

**Answer:** Candidate generation and reranking have different jobs. The main working pipeline should contain a basic reranker. Keep ablations without it to measure its value.


**Q10. [Interview] Why does Basic reranking remains in the main pipeline matter, and what is one important design implication?**

**Answer:** Do not compare an optional advanced method plus a reranker against a baseline that lacks reranking, then attribute all improvement to the advanced method.


**Q11. [Scenario] A developer misunderstands Basic reranking remains in the main pipeline while building a multi-tenant RAG assistant over versioned training manuals. How would you correct the design?**

**Answer:** Clarify the actual behavior: Do not compare an optional advanced method plus a reranker against a baseline that lacks reranking, then attribute all improvement to the advanced method. Demonstrate the difference with a concrete input and expected result before changing the system.

## 5. Choose Metrics and Release Gates

**Q25. [Conceptual] Explain Choose Metrics and Release Gates in simple, interview-ready language.**

**Answer:** Choose one primary outcome that reflects the task. For an evidence-based answer system, an example is supported correct answer rate: the proportion of evaluated questions whose required answer is correct and backed by acceptable evidence.


**Q26. [Interview] Why does Choose Metrics and Release Gates matter, and what is one important design implication?**

**Answer:** Other requirements are hard gates. A system that leaks another tenant's evidence should not be released because its average correctness improved.

<a id="7-uncertainty-and-paired-evaluation"></a>
## 7. Uncertainty and Paired Evaluation

**Q33. [Conceptual] Explain Uncertainty and Paired Evaluation in simple, interview-ready language.**

**Answer:** If both systems answer the same question, their outcomes are related. A difficult question may defeat both; an easy question may be answered by both.


**Q34. [Interview] Why does Uncertainty and Paired Evaluation matter, and what is one important design implication?**

**Answer:** A measured improvement can depend on which questions happened to be sampled. Another representative set might produce a different difference.


<a id="assumptions-and-limitations"></a>
### Assumptions and limitations

**Q35. [Conceptual] Explain Assumptions and limitations in simple, interview-ready language.**

**Answer:** The resampling unit must match the dependence structure. If many questions come from one document or one user session, independently resampling them can overstate the effective sample size. Consider document-level or session-level grouping where appropriate.


**Q36. [Interview] Why does Assumptions and limitations matter, and what is one important design implication?**

**Answer:** Different interval methods and small or degenerate samples require care. Use an appropriate validated statistical method for consequential release decisions.


**Q37. [Scenario] A developer misunderstands Assumptions and limitations while building a multi-tenant RAG assistant over versioned training manuals. How would you correct the design?**

**Answer:** Clarify the actual behavior: A bootstrap cannot fix biased question selection, incorrect labels or missing production slices. It reuses the data you supplied. Demonstrate the difference with a concrete input and expected result before changing the system.

<a id="8-offline-evidence-and-online-validation"></a>
## 8. Offline Evidence and Online Validation

**Q39. [Conceptual] Explain Offline Evidence and Online Validation in simple, interview-ready language.**

**Answer:** Offline evaluation uses a fixed corpus and labeled questions outside the live user interaction. It is useful for reproducibility, debugging and controlled comparisons.


**Q40. [Interview] Why does Offline Evidence and Online Validation matter, and what is one important design implication?**

**Answer:** Its limitation is coverage. Real users may ask different questions, use different languages or interact with the system in unexpected ways.


<a id="9-adoption-rollout-and-rejection"></a>
## 9. Adoption, Rollout and Rejection

**Q41. [Conceptual] Explain Adoption, Rollout and Rejection in simple, interview-ready language.**

**Answer:** Rejecting a sophisticated method can be a strong engineering result. The project has produced evidence that a simpler design is preferable for its workload.


**Q42. [Interview] Why does Adoption, Rollout and Rejection matter, and what is one important design implication?**

**Answer:** A rollback should revert the method while continuing to honor the latest permission and deletion state. Never restore a stale source snapshot merely because it belonged to the previous retrieval configuration.


<a id="13-project-exercise-and-completion-evidence"></a>
## 13. Project Exercise and Completion Evidence

**Q43. [Conceptual] Explain Project Exercise and Completion Evidence in simple, interview-ready language.**

**Answer:** The reader should be able to verify the numerical calculations, understand what changed, inspect a successful and failed case, and reproduce the comparison. A justified rejection is an acceptable outcome.


**Q44. [Interview] Why does Project Exercise and Completion Evidence matter, and what is one important design implication?**

**Answer:** Choose one elective method and write a complete experiment report for a permission-aware document assistant.
