<a id="1-the-fundamental-distinction"></a>
## 1. The Fundamental Distinction

**Q1. [Conceptual] Explain The Fundamental Distinction in simple, interview-ready language.**

**Answer:** Here, “offline” means outside the latency-critical answering path. It does not mean the computer is disconnected from the internet. An offline worker can use network APIs, run continuously, and process events immediately after a document changes.


**Q2. [Interview] Why does The Fundamental Distinction matter, and what is one important design implication?**

**Answer:** The terms also appear in evaluation: offline evaluation uses a fixed dataset, while online evaluation observes live behavior or controlled traffic experiments. That is a different distinction from indexing versus serving. An offline evaluation job can execute the entire online answering pipeline without real users.


<a id="2-offline-stage-1-ingest"></a>
## 2. Offline Stage 1 — Ingest

**Q3. [Conceptual] Explain Offline Stage 1 — Ingest in simple, interview-ready language.**

**Answer:** A file upload alone is not a searchable knowledge base. It creates an input to the preparation pipeline.


**Q4. [Interview] Why does Offline Stage 1 — Ingest matter, and what is one important design implication?**

**Answer:** A connector failure should produce a visible processing status. It must not silently create an empty successful document. Similarly, a partial source inventory must not be treated as proof that all unseen documents were deleted.


<a id="3-offline-stage-2-extract"></a>
## 3. Offline Stage 2 — Extract

**Q5. [Conceptual] Explain Offline Stage 2 — Extract in simple, interview-ready language.**

**Answer:** Extraction converts source formats into an interpretable representation: text blocks, headings, tables, image descriptions, page locations, and other structured elements.


**Q6. [Interview] Why does Offline Stage 2 — Extract matter, and what is one important design implication?**

**Answer:** Different formats require different handling. A digital PDF may contain text; a scanned PDF may require OCR; an office document may contain tables and headings; a webpage may include navigation unrelated to the main content.


<a id="extraction-quality-checks"></a>
### Extraction quality checks

**Q7. [Conceptual] Explain Extraction quality checks in simple, interview-ready language.**

**Answer:** Extraction is not generation. If a parser cannot read a value, it should mark uncertainty or failure rather than inventing a plausible value to fill the gap.


**Q8. [Interview] Why does Extraction quality checks matter, and what is one important design implication?**

**Answer:** Check for empty text, unusually low text volume, repeated headers, broken characters, suspicious reading order, missing table columns, and OCR uncertainty. Keep representative rendered-source comparisons in the development workflow.

<a id="4-offline-stage-3-chunk"></a>
## 4. Offline Stage 3 — Chunk

**Q11. [Conceptual] Explain Offline Stage 3 — Chunk in simple, interview-ready language.**

**Answer:** Each chunk should retain text, source ID, revision, location, heading path, relevant business metadata, and permission lineage. If a parent-child strategy is used, record the parent relationship explicitly.


**Q12. [Interview] Why does Offline Stage 3 — Chunk matter, and what is one important design implication?**

**Answer:** Useful units depend on source structure and query needs. A short definition, a procedure with conditions, and a table row may require different handling.


<a id="5-offline-stage-4-embed"></a>
## 5. Offline Stage 4 — Embed

**Q13. [Conceptual] Explain Offline Stage 4 — Embed in simple, interview-ready language.**

**Answer:** Embedding maps the chunk's chosen representation into a vector for dense similarity search. The embedding represents relationships learned by a model; it is not a database record of verified facts.


**Q14. [Interview] Why does Offline Stage 4 — Embed matter, and what is one important design implication?**

**Answer:** Equal dimensions alone do not establish compatibility. Two different models can produce vectors of the same length with unrelated coordinate meanings.

### Batching and reuse

**Q15. [Conceptual] Explain Batching and reuse in simple, interview-ready language.**

**Answer:** Batch compatible inputs to improve throughput where supported, while retaining an exact input-to-output mapping. Reuse an embedding only when the embedded text and relevant configuration are unchanged.

<a id="what-embedding-does-not-solve"></a>
### What embedding does not solve

**Q19. [Conceptual] Explain What embedding does not solve in simple, interview-ready language.**

**Answer:** Embedding does not grant permissions, verify source authority, fix OCR errors, or establish current revision state. Those properties must remain explicit metadata and enforced decisions.


**Q20. [Interview] Why does What embedding does not solve matter, and what is one important design implication?**

## 7. Online Stage 1 — Understand the Query

**Q23. [Conceptual] Explain Online Stage 1 — Understand the Query in simple, interview-ready language.**

**Answer:** For example, “What changed from v3 to v4?” is different from “What does the current manual say?” The first requires a permitted comparison of two revisions; the second normally selects the current published revision.


**Q24. [Interview] Why does Online Stage 1 — Understand the Query matter, and what is one important design implication?**

**Answer:** Use deterministic routes for exact structured lookups where appropriate. A question asking for a current record count should not force a language model to estimate from a few retrieved passages.


<a id="security-scope"></a>
### Security scope

**Q25. [Conceptual] Explain Security scope in simple, interview-ready language.**

### Recall under filtering

**Q39. [Conceptual] Explain Recall under filtering in simple, interview-ready language.**

**Answer:** A global top-10 followed by a filter can leave only one permitted item even when many relevant permitted items exist outside the global top-10. That result does not prove the allowed collection lacks evidence.


**Q40. [Interview] Why does Recall under filtering matter, and what is one important design implication?**

**Answer:** Test the chosen engine's filtered-search behavior and compare quality under realistic tenant sizes and filter selectivity.

<a id="9-online-stage-3-rerank"></a>
## 9. Online Stage 3 — Rerank

**Q43. [Conceptual] Explain Online Stage 3 — Rerank in simple, interview-ready language.**

**Answer:** Candidate generation prioritizes efficient coverage. Reranking prioritizes ordering and selection among those candidates. These are different responsibilities.


**Q44. [Interview] Why does Online Stage 3 — Rerank matter, and what is one important design implication?**

**Answer:** A cross-encoder may score the query and passage together; another implementation may use a different reranking model. The implementation choice should follow measured quality, latency, and processing-policy requirements.


<a id="10-online-stage-4-assemble-evidence-and-answer"></a>
## 10. Online Stage 4 — Assemble Evidence and Answer

**Q45. [Conceptual] Explain Online Stage 4 — Assemble Evidence and Answer in simple, interview-ready language.**

**Answer:** Context assembly is not “take the first K chunks and concatenate.” It must consider overlap, source authority, contradictory revisions, coverage of subquestions, and the space needed for instructions and the answer.


**Q46. [Interview] Why does Online Stage 4 — Assemble Evidence and Answer matter, and what is one important design implication?**

**Answer:** The answer should distinguish direct facts, supported synthesis, unresolved contradictions, and missing information. It should not fill gaps merely because a complete-sounding answer is more fluent.


<a id="citation-validation"></a>
### Citation validation

**Q47. [Conceptual] Explain Citation validation in simple, interview-ready language.**

**Answer:** Validate that every citation ID exists in the allowed evidence package, refers to the correct version and location, and supports its associated claim. Citation presence alone is not citation correctness.


**Q48. [Interview] Why does Citation validation matter, and what is one important design implication?**

<a id="11-contracts-between-the-two-pipelines"></a>
## 11. Contracts between the Two Pipelines

**Q51. [Conceptual] Explain Contracts between the Two Pipelines in simple, interview-ready language.**

**Answer:** Specify what a query sees while an update is in progress. Options include a pinned published generation, an explicitly labeled older permitted revision, or temporary unavailability for sources that must be current.


**Q52. [Interview] Why does Contracts between the Two Pipelines matter, and what is one important design implication?**

**Answer:** Do not accidentally mix versions because one index updated first. A request should record which source generation it used.
