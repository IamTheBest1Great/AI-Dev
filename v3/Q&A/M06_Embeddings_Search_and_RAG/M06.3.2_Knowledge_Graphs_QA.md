## 1. Knowledge Graph Fundamentals

**Q1. [Conceptual] Explain Knowledge Graph Fundamentals in simple, interview-ready language.**

**Answer:** A knowledge graph represents entities and the relationships or claims connecting them. It makes selected structure explicit so a system can query connections, combine facts, and trace evidence.


**Q2. [Interview] Why does Knowledge Graph Fundamentals matter, and what is one important design implication?**

**Answer:** For this foundation module, learn the shared ideas first: entities, relationships, identifiers, types, properties, provenance, and query scope. You do not need to master every graph standard before building a useful small example.


<a id="2-m06-3-2-1-entities-and-relationships"></a>
## 2. M06.3.2.1 — Entities and Relationships

**Q3. [Conceptual] Explain M06.3.2.1 — Entities and Relationships in simple, interview-ready language.**

**Answer:** An entity is a distinct thing the application needs to identify: a document, version, person, organization, component, procedure, event, or task.


**Q4. [Interview] Why does M06.3.2.1 — Entities and Relationships matter, and what is one important design implication?**

**Answer:** A relationship connects entities with a defined meaning. Names should be specific enough to support the questions you intend to ask.

## 3. Graph Modeling

**Q5. [Conceptual] Explain Graph Modeling in simple, interview-ready language.**

**Answer:** Modeling starts with the questions the graph should answer. If the target is “Which tasks are affected by changed procedures?”, the graph needs tasks, procedures, version changes, and explicit task-to-procedure links.


**Q6. [Interview] Why does Graph Modeling matter, and what is one important design implication?**

**Answer:** A schema helps reject impossible or ambiguous extractions early. It also makes evaluation more specific: a wrong endpoint type is different from a missing source.

### Avoid over-modeling

**Q15. [Conceptual] Explain Avoid over-modeling in simple, interview-ready language.**

**Answer:** A graph containing a node for every word is usually not useful for this task. A graph that collapses every document into one generic node may be too coarse.

## 4. Cypher Concepts

**Q27. [Conceptual] Explain Cypher Concepts in simple, interview-ready language.**

**Answer:** Cypher is a declarative graph query language used by Neo4j. A query describes patterns to match rather than manually instructing the database how to walk every edge.


**Q28. [Interview] Why does Cypher Concepts matter, and what is one important design implication?**

**Answer:** Read-only database privileges are useful, but they do not prevent unauthorized reads or excessively expensive traversals. Validate scope and complexity separately.

## 7. Multi-Hop Reasoning

**Q53. [Conceptual] Explain Multi-Hop Reasoning in simple, interview-ready language.**

**Answer:** M-104 v4 changed procedure PR-7. Task T-82 references PR-7. T-82 belongs to ship A and is open.

**Q59. [Conceptual] Explain Cost and stopping rules in simple, interview-ready language.**

## 8. Entity Resolution and Disambiguation

**Q63. [Conceptual] Explain Entity Resolution and Disambiguation in simple, interview-ready language.**

**Answer:** Resolution can use stable identifiers, tenant/resource scope, source registries, normalized names, attributes, and verified aliases. Similar wording alone is weak evidence for identity.


**Q64. [Interview] Why does Entity Resolution and Disambiguation matter, and what is one important design implication?**

**Answer:** Entity resolution determines whether different records or mentions refer to the same real entity.


<a id="9-graph-provenance-permissions-and-deletion"></a>
## 9. Graph Provenance, Permissions, and Deletion

**Q65. [Conceptual] Explain Graph Provenance, Permissions, and Deletion in simple, interview-ready language.**

**Answer:** If source A is deleted but source B independently supports the same claim and is current and authorized, the claim may remain usable with B’s provenance. Do not retain A’s text or citation merely because a similar fact survives.


**Q66. [Interview] Why does Graph Provenance, Permissions, and Deletion matter, and what is one important design implication?**

**Answer:** A practical claim record should connect to source document/version, source span, extraction method/version, review result, effective dates, and ingestion event.


<a id="10-graph-and-vector-hybrid-retrieval"></a>
## 10. Graph and Vector Hybrid Retrieval

**Q67. [Conceptual] Explain Graph and Vector Hybrid Retrieval in simple, interview-ready language.**

**Answer:** “Graph RAG” can refer broadly to graph-assisted retrieval. Microsoft’s From Local to Global paper describes a more specific approach using graph-derived community structure and summaries for query-focused global summarization.


**Q68. [Interview] Why does Graph and Vector Hybrid Retrieval matter, and what is one important design implication?**

**Answer:** Vector retrieval finds semantically similar text or entities. Graph retrieval follows explicit relationships. Combining them can help when users describe an entity indirectly and then ask a relationship question.
