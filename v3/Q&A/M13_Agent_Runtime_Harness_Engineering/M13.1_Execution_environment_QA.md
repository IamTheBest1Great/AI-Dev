#### Execution environment

**Q1. [Conceptual] What is execution environment, and why does it matter in Workspace and capabilities?**

**Answer:** The compute and permission context in which an agent and its tools run: processes, files, credentials, network and resource limits.

## Cross-cutting production interview drill

These questions are adapted from the source study guide’s interview section and assess how the individual concepts work together.

**Q41. [Interview] Explain execution environment to an interviewer.**

**Answer:** Follow-up 1 — What would you test first? A negative case involving environment variables and a normal task with a verified outcome.


**Q42. [Interview] How would you design Execution environment from scratch?**

**Answer:** Interview answer: I would identify the trusted input source, decide which component owns the operation, define typed fields, and specify success and failure states. The compute and permission context in which an agent and its tools run: processes, files, credentials, network and resource limits. Then I would create at least a happy-path and an unauthorized/invalid-input test.


**Q43. [Interview] How do Workspace and Filesystem interact?**

**Answer:** Interview answer: First define their separate responsibilities. Task-scoped area for inputs, intermediate files and outputs; segregate jobs and clean sensitive temporary data after completion. Namespace of paths and mounted storage available to a task. Apply path normalization, mount restrictions and read-only boundaries as appropriate. I would connect them only through a typed handoff with provenance and an explicit postcondition, rather than allowing hidden state coupling.


**Q44. [Interview] What would you do if Shell fails in production?**

**Answer:** Interview answer: I would contain the impact, check trace IDs, state and external receipts, then classify the failure as transient, permanent or unknown outcome. I would not blindly repeat a write. After fixing the cause, I would add the incident as a versioned regression case and measure policy violations blocked and terminated-job cleanup rate.


**Q45. [Interview] When would you avoid a framework or model for execution environment?**

**Answer:** Interview answer: When the rules and data contracts are deterministic, a small application service or workflow is usually easier to test and operate. I add an agent or new framework only when variable inputs and evidence show a measurable improvement that offsets extra coordination, cost and risk.


**Q46. [Interview] How would you demonstrate L3 production readiness for M13.1?**

**Answer:** Interview answer: I would present a working repository, a state and permission diagram, the job manifest with artifact hashes, logs and resource measurements, known limitations, representative evaluation fixtures, failure-injection results and tracing. I would also show restart behavior and an operator takeover path where needed.
