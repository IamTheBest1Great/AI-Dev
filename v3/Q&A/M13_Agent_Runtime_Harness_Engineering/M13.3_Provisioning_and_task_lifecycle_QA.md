## Cross-cutting production interview drill

These questions are adapted from the source study guide’s interview section and assess how the individual concepts work together.

**Q37. [Interview] Explain provisioning and task lifecycle to an interviewer.**

**Answer:** Follow-up 1 — What would you test first? A negative case involving destroy or retain environment and a normal task with a verified outcome.


**Q38. [Interview] How would you design Create task from scratch?**

**Answer:** Interview answer: I would identify the trusted input source, decide which component owns the operation, define typed fields, and specify success and failure states. In this part of an isolated agent coding and report-generation workspace, Create task is an explicit design concern. Define its inputs, owner, observable result and failure handling before implementing it. Its purpose must be linked to the overall goal: run tool actions with enforceable resource, secret and network boundaries.


**Q39. [Interview] How do Provision environment and Load context / skills interact?**

**Answer:** Interview answer: First define their separate responsibilities. Ground the operation in the current observable source and define how to verify it. Treat recognized or generated content as uncertain until checked against concrete evidence. Identify who owns this information, where it lives, and when it changes. Keep transient model context distinct from durable application state and enforce scope on every read and write.


**Q40. [Interview] What would you do if Execute agent fails in production?**

**Answer:** Interview answer: I would contain the impact, check trace IDs, state and external receipts, then classify the failure as transient, permanent or unknown outcome. I would not blindly repeat a write. After fixing the cause, I would add the incident as a versioned regression case and measure policy violations blocked and terminated-job cleanup rate.


**Q41. [Interview] When would you avoid a framework or model for provisioning and task lifecycle?**

**Answer:** Interview answer: When the rules and data contracts are deterministic, a small application service or workflow is usually easier to test and operate. I add an agent or new framework only when variable inputs and evidence show a measurable improvement that offsets extra coordination, cost and risk.


**Q42. [Interview] How would you demonstrate L3 production readiness for M13.3?**

**Answer:** Interview answer: I would present a working repository, a state and permission diagram, the job manifest with artifact hashes, logs and resource measurements, known limitations, representative evaluation fixtures, failure-injection results and tracing. I would also show restart behavior and an operator takeover path where needed.
