## Cross-cutting production interview drill

These questions are adapted from the source study guide’s interview section and assess how the individual concepts work together.

**Q41. [Interview] Explain execution control to an interviewer.**

**Answer:** Follow-up 1 — What would you test first? A negative case involving concurrency and a normal task with a verified outcome.


**Q42. [Interview] How would you design Cancellation from scratch?**

**Answer:** Interview answer: I would identify the trusted input source, decide which component owns the operation, define typed fields, and specify success and failure states. Propagate a stop request through agent, worker and tool boundaries. Mark external actions with known or unknown outcomes, persist status, and avoid treating UI cancellation as rollback. Then I would create at least a happy-path and an unauthorized/invalid-input test.


**Q43. [Interview] How do Interruptibility and Timeouts interact?**

**Answer:** Interview answer: First define their separate responsibilities. In this part of an isolated agent coding and report-generation workspace, Interruptibility is an explicit design concern. Define its inputs, owner, observable result and failure handling before implementing it. Its purpose must be linked to the overall goal: run tool actions with enforceable resource, secret and network boundaries. Define expected behavior before, during and after failure.


**Q44. [Interview] What would you do if Emergency stop fails in production?**

**Answer:** Interview answer: I would contain the impact, check trace IDs, state and external receipts, then classify the failure as transient, permanent or unknown outcome. I would not blindly repeat a write. After fixing the cause, I would add the incident as a versioned regression case and measure policy violations blocked and terminated-job cleanup rate.


**Q45. [Interview] When would you avoid a framework or model for execution control?**

**Answer:** Interview answer: When the rules and data contracts are deterministic, a small application service or workflow is usually easier to test and operate. I add an agent or new framework only when variable inputs and evidence show a measurable improvement that offsets extra coordination, cost and risk.


**Q46. [Interview] How would you demonstrate L3 production readiness for M13.4?**

**Answer:** Interview answer: I would present a working repository, a state and permission diagram, the job manifest with artifact hashes, logs and resource measurements, known limitations, representative evaluation fixtures, failure-injection results and tracing. I would also show restart behavior and an operator takeover path where needed.
