## Cross-cutting production interview drill

These questions are adapted from the source study guide’s interview section and assess how the individual concepts work together.

**Q37. [Interview] Explain visual and document understanding to an interviewer.**

**Answer:** Follow-up 1 — What would you test first? A negative case involving forms and a normal task with a verified outcome.


**Q38. [Interview] How would you design Image understanding from scratch?**

**Answer:** Interview answer: I would identify the trusted input source, decide which component owns the operation, define typed fields, and specify success and failure states. Interpret visible content and relationships within an image; verify fine text, measurements and visual ambiguities against the source when accuracy matters. Then I would create at least a happy-path and an unauthorized/invalid-input test.


**Q39. [Interview] How do Multi-image comparison and Visual grounding interact?**

**Answer:** Interview answer: First define their separate responsibilities. Compare separate visual sources, controlling viewpoint, time and scale differences before claiming a change. Identify the specific region or frame that supports a visual claim; use coordinates, page or frame references rather than relying on plausible narration. I would connect them only through a typed handoff with provenance and an explicit postcondition, rather than allowing hidden state coupling.


**Q40. [Interview] What would you do if OCR fails in production?**

**Answer:** Interview answer: I would contain the impact, check trace IDs, state and external receipts, then classify the failure as transient, permanent or unknown outcome. I would not blindly repeat a write. After fixing the cause, I would add the incident as a versioned regression case and measure visual grounding accuracy and source-attribution completeness.


**Q41. [Interview] When would you avoid a framework or model for visual and document understanding?**

**Answer:** Interview answer: When the rules and data contracts are deterministic, a small application service or workflow is usually easier to test and operate. I add an agent or new framework only when variable inputs and evidence show a measurable improvement that offsets extra coordination, cost and risk.


**Q42. [Interview] How would you demonstrate L3 production readiness for M23.1?**

**Answer:** Interview answer: I would present a working repository, a state and permission diagram, the multimodal evidence map with page/frame references, known limitations, representative evaluation fixtures, failure-injection results and tracing. I would also show restart behavior and an operator takeover path where needed.
