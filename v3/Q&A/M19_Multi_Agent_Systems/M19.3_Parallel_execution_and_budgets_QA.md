## Cross-cutting production interview drill

These questions are adapted from the source study guide’s interview section and assess how the individual concepts work together.

**Q25. [Interview] Explain parallel execution and budgets to an interviewer.**

**Answer:** Interview answer: Parallel execution and budgets addresses the need to compare multi-agent coordination against a strong single-workflow baseline. I would begin with a bounded design for a research organization with specialist agents, then specify contracts for Parallel agents and Fan-out. I would measure task quality per cost and coordination-failure rate, verify the actual outcome and demonstrate handling of the primary failure:.


**Q26. [Interview] How would you design Parallel agents from scratch?**

**Answer:** Interview answer: I would identify the trusted input source, decide which component owns the operation, define typed fields, and specify success and failure states. Workers execute independent actions concurrently; protect shared budgets, state and external writes and define the join condition. Then I would create at least a happy-path and an unauthorized/invalid-input test.


**Q27. [Interview] How do Fan-out and Fan-in interact?**

**Answer:** Interview answer: First define their separate responsibilities. Split independent subtasks so they can execute concurrently under a shared budget and authorization scope. Join multiple branches with clear completeness, timeout, provenance and conflict-resolution rules. I would connect them only through a typed handoff with provenance and an explicit postcondition, rather than allowing hidden state coupling.


**Q28. [Interview] What would you do if Race-to-answer fails in production?**

**Answer:** Interview answer: I would contain the impact, check trace IDs, state and external receipts, then classify the failure as transient, permanent or unknown outcome. I would not blindly repeat a write. After fixing the cause, I would add the incident as a versioned regression case and measure task quality per cost and coordination-failure rate.


**Q29. [Interview] When would you avoid a framework or model for parallel execution and budgets?**

**Answer:** Interview answer: When the rules and data contracts are deterministic, a small application service or workflow is usually easier to test and operate. I add an agent or new framework only when variable inputs and evidence show a measurable improvement that offsets extra coordination, cost and risk.


**Q30. [Interview] How would you demonstrate L3 production readiness for M19.3?**

**Answer:** Interview answer: I would present a working repository, a state and permission diagram, the single-agent versus multi-agent benchmark and coordination trace, known limitations, representative evaluation fixtures, failure-injection results and tracing. I would also show restart behavior and an operator takeover path where needed.
