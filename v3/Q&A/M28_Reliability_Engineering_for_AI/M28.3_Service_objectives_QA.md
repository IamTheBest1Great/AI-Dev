## Cross-cutting production interview drill

**Q33. [Interview] Explain service objectives to an interviewer.**

**Answer:** Interview answer: Service objectives addresses the need to meet reliability objectives despite partial outages. I would begin with a bounded design for a production AI API with model, database and queue dependencies, then specify contracts for Availability and P50/P95/P99 latency. I would measure task-success SLO and recovery time under injected faults, verify the actual outcome and demonstrate handling of the primary failure: provider outage causes a retry storm and duplicate tool writes.

Specify the measured unit, attribution owner and ceiling.


**Q36. [Interview] What would you do if Tool success rate fails in production?**

**Answer:** Interview answer: I would contain the impact, check trace IDs, state and external receipts, then classify the failure as transient, permanent or unknown outcome. I would not blindly repeat a write. After fixing the cause, I would add the incident as a versioned regression case and measure task-success SLO and recovery time under injected faults.


**Q37. [Interview] When would you avoid a framework or model for service objectives?**

**Answer:** Interview answer: When the rules and data contracts are deterministic, a small application service or workflow is usually easier to test and operate. I add an agent or new framework only when variable inputs and evidence show a measurable improvement that offsets extra coordination, cost and risk.


**Q38. [Interview] How would you demonstrate L3 production readiness for M28.3?**

**Answer:** Interview answer: I would present a working repository, a state and permission diagram, the failure-injection report with runbooks and SLO results, known limitations, representative evaluation fixtures, failure-injection results and tracing. I would also show restart behavior and an operator takeover path where needed.
