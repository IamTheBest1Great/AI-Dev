## Cross-cutting production interview drill

These questions are adapted from the source study guide’s interview section and assess how the individual concepts work together.

**Q7. [Interview] Explain memory quality to an interviewer.**

**Answer:** Interview answer: Memory quality addresses the need to store useful experience while respecting correction, deletion and tenancy. I would begin with a bounded design for a persistent training assistant for seafarers, then specify contracts for Agent Infrastructure & Ecosystem and Evaluation. I would measure stale-recall rate and correction propagation success, verify the actual outcome and demonstrate handling of the primary failure: old user preferences reappear after the user corrected them.

**Q9. [Interview] How do Evaluation and State and evidence interact?**

**Answer:** Interview answer: First define their separate responsibilities. Define an expected outcome on representative fixtures. Compare observed behavior against a predeclared criterion; separate deterministic correctness from probabilistic model quality. Identify who owns this information, where it lives, and when it changes. Keep transient model context distinct from durable application state and enforce scope on every read and write.


**Q10. [Interview] What would you do if Validation fails in production?**

**Answer:** Interview answer: I would contain the impact, check trace IDs, state and external receipts, then classify the failure as transient, permanent or unknown outcome. I would not blindly repeat a write. After fixing the cause, I would add the incident as a versioned regression case and measure stale-recall rate and correction propagation success.


**Q11. [Interview] When would you avoid a framework or model for memory quality?**

**Answer:** Interview answer: When the rules and data contracts are deterministic, a small application service or workflow is usually easier to test and operate. I add an agent or new framework only when variable inputs and evidence show a measurable improvement that offsets extra coordination, cost and risk.


**Q12. [Interview] How would you demonstrate L3 production readiness for M12.6?**

**Answer:** Interview answer: I would present a working repository, a state and permission diagram, the memory ledger with provenance, TTL and deletion receipts, known limitations, representative evaluation fixtures, failure-injection results and tracing. I would also show restart behavior and an operator takeover path where needed.
