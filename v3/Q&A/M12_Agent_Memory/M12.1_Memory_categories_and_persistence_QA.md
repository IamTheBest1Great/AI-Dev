## Cross-cutting production interview drill

These questions are adapted from the source study guide’s interview section and assess how the individual concepts work together.

**Q57. [Interview] Explain memory categories and persistence to an interviewer.**

**Answer:** Interview answer: Memory categories and persistence addresses the need to store useful experience while respecting correction, deletion and tenancy. I would begin with a bounded design for a persistent training assistant for seafarers, then specify contracts for Working memory and Short-term memory. I would measure stale-recall rate and correction propagation success, verify the actual outcome and demonstrate handling of the primary failure:.


**Q58. [Interview] How would you design Working memory from scratch?**

**Answer:** Interview answer: I would identify the trusted input source, decide which component owns the operation, define typed fields, and specify success and failure states. Information actively available in the current inference context. It is temporary and limited by the context window; it should not be confused with persisted database records. Then I would create at least a happy-path and an unauthorized/invalid-input test.


**Q59. [Interview] How do Short-term memory and Episodic memory interact?**

**Answer:** Interview answer: First define their separate responsibilities. Recent history or state retained across a limited conversation or task. It often sits in thread storage or checkpoints and is selectively loaded into active context. Record of a past event, interaction or task with time, actor, outcome and provenance. It helps recall what happened without converting a single observation into an eternal general rule.


**Q60. [Interview] What would you do if Semantic memory fails in production?**

**Answer:** Interview answer: I would contain the impact, check trace IDs, state and external receipts, then classify the failure as transient, permanent or unknown outcome. I would not blindly repeat a write. After fixing the cause, I would add the incident as a versioned regression case and measure stale-recall rate and correction propagation success.


**Q61. [Interview] When would you avoid a framework or model for memory categories and persistence?**

**Answer:** Interview answer: When the rules and data contracts are deterministic, a small application service or workflow is usually easier to test and operate. I add an agent or new framework only when variable inputs and evidence show a measurable improvement that offsets extra coordination, cost and risk.


**Q62. [Interview] How would you demonstrate L3 production readiness for M12.1?**

**Answer:** Interview answer: I would present a working repository, a state and permission diagram, the memory ledger with provenance, TTL and deletion receipts, known limitations, representative evaluation fixtures, failure-injection results and tracing. I would also show restart behavior and an operator takeover path where needed.
