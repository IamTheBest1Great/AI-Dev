## Cross-cutting production interview drill

These questions are adapted from the source study guide’s interview section and assess how the individual concepts work together.

**Q65. [Interview] Explain supply-chain verification to an interviewer.**

**Answer:** Interview answer: Supply-chain verification addresses the need to gate deployments on code, security, and AI behavior. I would begin with a bounded design for a CI/CD pipeline for prompt- and model-dependent services, then specify contracts for Dependency scanning and Secret scanning. I would measure change failure rate and behavior-regression escape rate, verify the actual outcome and demonstrate handling of the primary failure:.


**Q66. [Interview] How would you design Dependency scanning from scratch?**

**Answer:** Interview answer: I would identify the trusted input source, decide which component owns the operation, define typed fields, and specify success and failure states. Analyze packages against vulnerability databases, applying risk-based fixes and mitigating exposure. Then I would create at least a happy-path and an unauthorized/invalid-input test.


**Q67. [Interview] How do Secret scanning and SAST concepts interact?**

**Answer:** Follow-up 1 — What would you test first? A negative case involving secret scanning and a normal task with a verified outcome.


**Q68. [Interview] What would you do if DAST awareness fails in production?**

**Answer:** Interview answer: I would contain the impact, check trace IDs, state and external receipts, then classify the failure as transient, permanent or unknown outcome. I would not blindly repeat a write. After fixing the cause, I would add the incident as a versioned regression case and measure change failure rate and behavior-regression escape rate.


**Q69. [Interview] When would you avoid a framework or model for supply-chain verification?**

**Answer:** Interview answer: When the rules and data contracts are deterministic, a small application service or workflow is usually easier to test and operate. I add an agent or new framework only when variable inputs and evidence show a measurable improvement that offsets extra coordination, cost and risk.


**Q70. [Interview] How would you demonstrate L3 production readiness for M39.3?**

**Answer:** Interview answer: I would present a working repository, a state and permission diagram, the release evidence bundle with evaluation and security thresholds, known limitations, representative evaluation fixtures, failure-injection results and tracing. I would also show restart behavior and an operator takeover path where needed.
