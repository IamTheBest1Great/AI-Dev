## Cross-cutting production interview drill

These questions are adapted from the source study guide’s interview section and assess how the individual concepts work together.

**Q45. [Interview] Explain browser interaction foundations to an interviewer.**

**Answer:** Follow-up 1 — What would you test first? A negative case involving downloads and a normal task with a verified outcome.


**Q46. [Interview] How would you design Playwright from scratch?**

**Answer:** Interview answer: I would identify the trusted input source, decide which component owns the operation, define typed fields, and specify success and failure states. Browser automation framework with browser contexts, accessible locators, assertions and tracing useful for deterministic web tasks. Then I would create at least a happy-path and an unauthorized/invalid-input test.


**Q47. [Interview] How do Form filling and Navigation interact?**

**Answer:** Interview answer: First define their separate responsibilities. Populate and validate fields, preserve hidden constraints and verify that submission produced the intended record rather than assuming button clicks succeeded. Move between authorized pages while tracking URL, page lifecycle, tab, frame and redirects; detect login expiration and unexpected destinations.


**Q48. [Interview] What would you do if Downloads fails in production?**

**Answer:** Interview answer: I would contain the impact, check trace IDs, state and external receipts, then classify the failure as transient, permanent or unknown outcome. I would not blindly repeat a write. After fixing the cause, I would add the incident as a versioned regression case and measure successful task completion across controlled UI changes.


**Q49. [Interview] When would you avoid a framework or model for browser interaction foundations?**

**Answer:** Interview answer: When the rules and data contracts are deterministic, a small application service or workflow is usually easier to test and operate. I add an agent or new framework only when variable inputs and evidence show a measurable improvement that offsets extra coordination, cost and risk.


**Q50. [Interview] How would you demonstrate L3 production readiness for M20.1?**

**Answer:** Interview answer: I would present a working repository, a state and permission diagram, the Playwright trace, screenshots and verified action receipt, known limitations, representative evaluation fixtures, failure-injection results and tracing. I would also show restart behavior and an operator takeover path where needed.
