## Cross-cutting production interview drill

These questions are adapted from the source study guide’s interview section and assess how the individual concepts work together.

**Q25. [Interview] Explain sessions and browser infrastructure to an interviewer.**

**Answer:** Follow-up 1 — What would you test first? A negative case involving proxy architecture and a normal task with a verified outcome.


**Q26. [Interview] How would you design Browserbase-style managed browsers from scratch?**

**Answer:** Interview answer: I would identify the trusted input source, decide which component owns the operation, define typed fields, and specify success and failure states. Ground the operation in the current observable source and define how to verify it. Treat recognized or generated content as uncertain until checked against concrete evidence. Then I would create at least a happy-path and an unauthorized/invalid-input test.


**Q27. [Interview] How do Session persistence and Parallel sessions interact?**

**Answer:** Interview answer: First define their separate responsibilities. Identify who owns this information, where it lives, and when it changes. Keep transient model context distinct from durable application state and enforce scope on every read and write. Identify who owns this information, where it lives, and when it changes. Keep transient model context distinct from durable application state and enforce scope on every read and write.


**Q28. [Interview] What would you do if Resource limits fails in production?**

**Answer:** Interview answer: I would contain the impact, check trace IDs, state and external receipts, then classify the failure as transient, permanent or unknown outcome. I would not blindly repeat a write. After fixing the cause, I would add the incident as a versioned regression case and measure successful task completion across controlled UI changes.


**Q29. [Interview] When would you avoid a framework or model for sessions and browser infrastructure?**

**Answer:** Interview answer: When the rules and data contracts are deterministic, a small application service or workflow is usually easier to test and operate. I add an agent or new framework only when variable inputs and evidence show a measurable improvement that offsets extra coordination, cost and risk.


**Q30. [Interview] How would you demonstrate L3 production readiness for M20.3?**

**Answer:** Interview answer: I would present a working repository, a state and permission diagram, the Playwright trace, screenshots and verified action receipt, known limitations, representative evaluation fixtures, failure-injection results and tracing. I would also show restart behavior and an operator takeover path where needed.
