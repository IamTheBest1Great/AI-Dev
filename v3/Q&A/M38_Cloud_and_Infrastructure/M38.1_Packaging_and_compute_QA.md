## Cross-cutting production interview drill

These questions are adapted from the source study guide’s interview section and assess how the individual concepts work together.

**Q121. [Interview] Explain packaging and compute to an interviewer.**

**Answer:** Interview answer: Packaging and compute addresses the need to deploy secure services with recoverable data and controlled costs. I would begin with a bounded design for a cloud deployment for an AI training platform, then specify contracts for Images and Multi-stage builds. I would measure availability and measured recovery time, verify the actual outcome and demonstrate handling of the primary failure: a database is accidentally reachable from the public internet.


**Q122. [Interview] How would you design Images from scratch?**

**Answer:** Interview answer: I would identify the trusted input source, decide which component owns the operation, define typed fields, and specify success and failure states. Immutable container build artifacts identified by digest; scan and sign where appropriate before deployment. Then I would create at least a happy-path and an unauthorized/invalid-input test.


**Q123. [Interview] How do Multi-stage builds and Layers interact?**

**Answer:** Interview answer: First define their separate responsibilities. Docker technique using separate build and runtime stages to reduce artifact size and unnecessary runtime tooling. Cached filesystem changes in container images, enabling reuse but requiring attention to embedded secret leaks. I would connect them only through a typed handoff with provenance and an explicit postcondition, rather than allowing hidden state coupling.


**Q124. [Interview] What would you do if Volumes fails in production?**

**Answer:** Interview answer: I would contain the impact, check trace IDs, state and external receipts, then classify the failure as transient, permanent or unknown outcome. I would not blindly repeat a write. After fixing the cause, I would add the incident as a versioned regression case and measure availability and measured recovery time.


**Q125. [Interview] When would you avoid a framework or model for packaging and compute?**

**Answer:** Interview answer: When the rules and data contracts are deterministic, a small application service or workflow is usually easier to test and operate. I add an agent or new framework only when variable inputs and evidence show a measurable improvement that offsets extra coordination, cost and risk.


**Q126. [Interview] How would you demonstrate L3 production readiness for M38.1?**

**Answer:** Interview answer: I would present a working repository, a state and permission diagram, the deployment diagram, IaC plan and tested restore runbook, known limitations, representative evaluation fixtures, failure-injection results and tracing. I would also show restart behavior and an operator takeover path where needed.
