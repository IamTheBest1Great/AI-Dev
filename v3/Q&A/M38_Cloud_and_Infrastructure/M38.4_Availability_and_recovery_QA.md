## Cross-cutting production interview drill

These questions are adapted from the source study guide’s interview section and assess how the individual concepts work together.

**Q49. [Interview] Explain availability and recovery to an interviewer.**

**Answer:** Interview answer: Availability and recovery addresses the need to deploy secure services with recoverable data and controlled costs. I would begin with a bounded design for a cloud deployment for an AI training platform, then specify contracts for Backups and Restore testing. I would measure availability and measured recovery time, verify the actual outcome and demonstrate handling of the primary failure: a database is accidentally reachable from the public internet.


**Q50. [Interview] How would you design Backups from scratch?**

**Answer:** Interview answer: I would identify the trusted input source, decide which component owns the operation, define typed fields, and specify success and failure states. In this part of a cloud deployment for an AI training platform, Backups is an explicit design concern. Define its inputs, owner, observable result and failure handling before implementing it. Its purpose must be linked to the overall goal: deploy secure services with recoverable data and controlled costs.


**Q51. [Interview] How do Restore testing and Snapshot concepts interact?**

**Answer:** Follow-up 1 — What would you test first? A negative case involving multi-az concepts and a normal task with a verified outcome.


**Q52. [Interview] What would you do if Backup retention fails in production?**

**Answer:** Interview answer: I would contain the impact, check trace IDs, state and external receipts, then classify the failure as transient, permanent or unknown outcome. I would not blindly repeat a write. After fixing the cause, I would add the incident as a versioned regression case and measure availability and measured recovery time.


**Q53. [Interview] When would you avoid a framework or model for availability and recovery?**

**Answer:** Interview answer: When the rules and data contracts are deterministic, a small application service or workflow is usually easier to test and operate. I add an agent or new framework only when variable inputs and evidence show a measurable improvement that offsets extra coordination, cost and risk.


**Q54. [Interview] How would you demonstrate L3 production readiness for M38.4?**

**Answer:** Interview answer: I would present a working repository, a state and permission diagram, the deployment diagram, IaC plan and tested restore runbook, known limitations, representative evaluation fixtures, failure-injection results and tracing. I would also show restart behavior and an operator takeover path where needed.
