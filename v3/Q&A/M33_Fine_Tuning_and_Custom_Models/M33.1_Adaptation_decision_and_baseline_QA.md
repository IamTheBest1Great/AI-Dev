## Cross-cutting production interview drill

These questions are adapted from the source study guide’s interview section and assess how the individual concepts work together.

**Q35. [Interview] Explain adaptation decision and baseline to an interviewer.**

**Answer:** Follow-up 1 — What would you test first? A negative case involving before tuning: and a normal task with a verified outcome.


**Q36. [Interview] How would you design Before tuning: from scratch?**

**Answer:** Interview answer: I would identify the trusted input source, decide which component owns the operation, define typed fields, and specify success and failure states. In this part of a domain-specific text classification and extraction model, Before tuning: is an explicit design concern. Define its inputs, owner, observable result and failure handling before implementing it. Its purpose must be linked to the overall goal: justify fine-tuning only after stronger low-cost baselines.


**Q37. [Interview] How do Prompting and Better context interact?**

**Answer:** Interview answer: First define their separate responsibilities. Choose the model or data transformation by the task and evaluate it against a fixed baseline. Version the input contract and inspect failure slices rather than trusting aggregate scores. Identify who owns this information, where it lives, and when it changes. Keep transient model context distinct from durable application state and enforce scope on every read and write.


**Q38. [Interview] What would you do if RAG fails in production?**

**Answer:** Interview answer: I would contain the impact, check trace IDs, state and external receipts, then classify the failure as transient, permanent or unknown outcome. I would not blindly repeat a write. After fixing the cause, I would add the incident as a versioned regression case and measure verified improvement on held-out domain slices without regression.


**Q39. [Interview] When would you avoid a framework or model for adaptation decision and baseline?**

**Answer:** Interview answer: When the rules and data contracts are deterministic, a small application service or workflow is usually easier to test and operate. I add an agent or new framework only when variable inputs and evidence show a measurable improvement that offsets extra coordination, cost and risk.


**Q40. [Interview] How would you demonstrate L3 production readiness for M33.1?**

**Answer:** Interview answer: I would present a working repository, a state and permission diagram, the versioned training run and held-out evaluation report, known limitations, representative evaluation fixtures, failure-injection results and tracing. I would also show restart behavior and an operator takeover path where needed.
