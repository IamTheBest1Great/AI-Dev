## Cross-cutting production interview drill

These questions are adapted from the source study guide’s interview section and assess how the individual concepts work together.

**Q35. [Interview] Explain evaluation and deployment to an interviewer.**

**Answer:** Follow-up 1 — What would you test first? A negative case involving evaluation & serving and a normal task with a verified outcome.


**Q36. [Interview] How would you design Benchmark against the base model from scratch?**

**Answer:** Interview answer: I would identify the trusted input source, decide which component owns the operation, define typed fields, and specify success and failure states. Define an expected outcome on representative fixtures. Compare observed behavior against a predeclared criterion; separate deterministic correctness from probabilistic model quality. Then I would create at least a happy-path and an unauthorized/invalid-input test.


**Q37. [Interview] How do Behavior regression tests and Safety regression tests interact?**

**Answer:** Interview answer: First define their separate responsibilities. Define an expected outcome on representative fixtures. Compare observed behavior against a predeclared criterion; separate deterministic correctness from probabilistic model quality. Define an expected outcome on representative fixtures. Compare observed behavior against a predeclared criterion; separate deterministic correctness from probabilistic model quality.


**Q38. [Interview] What would you do if Cost/quality comparison fails in production?**

**Answer:** Interview answer: I would contain the impact, check trace IDs, state and external receipts, then classify the failure as transient, permanent or unknown outcome. I would not blindly repeat a write. After fixing the cause, I would add the incident as a versioned regression case and measure verified improvement on held-out domain slices without regression.


**Q39. [Interview] When would you avoid a framework or model for evaluation and deployment?**

**Answer:** Interview answer: When the rules and data contracts are deterministic, a small application service or workflow is usually easier to test and operate. I add an agent or new framework only when variable inputs and evidence show a measurable improvement that offsets extra coordination, cost and risk.


**Q40. [Interview] How would you demonstrate L3 production readiness for M33.5?**

**Answer:** Interview answer: I would present a working repository, a state and permission diagram, the versioned training run and held-out evaluation report, known limitations, representative evaluation fixtures, failure-injection results and tracing. I would also show restart behavior and an operator takeover path where needed.
