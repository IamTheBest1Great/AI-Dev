## Cross-cutting production interview drill

These questions are adapted from the source study guide’s interview section and assess how the individual concepts work together.

**Q33. [Interview] Explain instrumentation and propagation to an interviewer.**

**Answer:** Interview answer: Instrumentation and propagation addresses the need to trace decisions and costs without exposing restricted payloads. I would begin with a bounded design for an AI request path spanning API, retrieval, model, and tools, then specify contracts for Trace propagation and Spans. I would measure trace coverage and mean time to diagnose, verify the actual outcome and demonstrate handling of the primary failure: tool latency spikes but logs contain no correlation ID.


**Q34. [Interview] How would you design Trace propagation from scratch?**

**Answer:** Interview answer: I would identify the trusted input source, decide which component owns the operation, define typed fields, and specify success and failure states. Emit structured, correlated evidence of behavior and outcomes. Choose stable field names and retention rules, and avoid exporting credentials or private source text unnecessarily. Then I would create at least a happy-path and an unauthorized/invalid-input test.


**Q35. [Interview] How do Spans and Span attributes interact?**

**Answer:** Interview answer: First define their separate responsibilities. Individual traced operations with start/end timestamps, attributes, status and parent links. Typed metadata describing each operation such as model ID, tool name, request ID or outcome, subject to redaction. I would connect them only through a typed handoff with provenance and an explicit postcondition, rather than allowing hidden state coupling.


**Q36. [Interview] What would you do if GenAI semantic conventions fails in production?**

**Answer:** Interview answer: I would contain the impact, check trace IDs, state and external receipts, then classify the failure as transient, permanent or unknown outcome. I would not blindly repeat a write. After fixing the cause, I would add the incident as a versioned regression case and measure trace coverage and mean time to diagnose.


**Q37. [Interview] When would you avoid a framework or model for instrumentation and propagation?**

**Answer:** Interview answer: When the rules and data contracts are deterministic, a small application service or workflow is usually easier to test and operate. I add an agent or new framework only when variable inputs and evidence show a measurable improvement that offsets extra coordination, cost and risk.


**Q38. [Interview] How would you demonstrate L3 production readiness for M27.2?**

**Answer:** Interview answer: I would present a working repository, a state and permission diagram, the trace waterfall and incident diagnostic summary, known limitations, representative evaluation fixtures, failure-injection results and tracing. I would also show restart behavior and an operator takeover path where needed.
