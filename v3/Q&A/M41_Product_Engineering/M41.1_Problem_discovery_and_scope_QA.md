#### User problem definition

**Q1. [Conceptual] What is user problem definition, and why does it matter in Problem and scope?**

**Answer:** Specific user role, task, pain, frequency and current workflow; quantify the cost of the problem before selecting a model.


**Q2. [Interview] Where would you apply user problem definition when designing a customer-facing AI product, and how would you explain your decision?**

**Answer:** Use user problem definition in the interview users and map work stage. Define the relevant input, output, or decision; specify a measurable acceptance check instead of trusting a generated description alone.


**Q3. [Scenario] Your customer-facing AI product encounters this problem: a polished chatbot is launched but users have no reason to adopt it. How would you handle it specifically for user problem definition?**

**Answer:** To address it, prepare or implement problem-first discovery and observed workflow experiments. ## Cross-cutting production interview drill

These questions are adapted from the source study guide’s interview section and assess how the individual concepts work together.

**Q43. [Interview] Explain problem discovery and scope to an interviewer.**

**Answer:** Interview answer: Problem discovery and scope addresses the need to solve an expensive user workflow and quantify adoption and ROI. I would begin with a bounded design for a commercial AI workflow assistant, then specify contracts for User problem definition and Workflow mapping. I would measure time saved, accepted outcomes and retention, verify the actual outcome and demonstrate handling of the primary failure: a polished chatbot is launched but users have no reason to adopt it.


**Q44. [Interview] How would you design User problem definition from scratch?**

**Answer:** Interview answer: I would identify the trusted input source, decide which component owns the operation, define typed fields, and specify success and failure states. Specific user role, task, pain, frequency and current workflow; quantify the cost of the problem before selecting a model. Then I would create at least a happy-path and an unauthorized/invalid-input test.


**Q45. [Interview] How do Workflow mapping and AI fit vs deterministic fit interact?**

**Answer:** Interview answer: First define their separate responsibilities. Document existing steps, systems, handoffs and approvals to identify where automation produces verifiable benefit. Compare ambiguous knowledge work against predictable rule-based automation; select the simpler approach when it achieves the requirement. I would connect them only through a typed handoff with provenance and an explicit postcondition, rather than allowing hidden state coupling.


**Q46. [Interview] What would you do if MVP scope fails in production?**

**Answer:** Interview answer: I would contain the impact, check trace IDs, state and external receipts, then classify the failure as transient, permanent or unknown outcome. I would not blindly repeat a write. After fixing the cause, I would add the incident as a versioned regression case and measure time saved, accepted outcomes and retention.


**Q47. [Interview] When would you avoid a framework or model for problem discovery and scope?**

**Answer:** Interview answer: When the rules and data contracts are deterministic, a small application service or workflow is usually easier to test and operate. I add an agent or new framework only when variable inputs and evidence show a measurable improvement that offsets extra coordination, cost and risk.


**Q48. [Interview] How would you demonstrate L3 production readiness for M41.1?**

**Answer:** Interview answer: I would present a working repository, a state and permission diagram, the problem brief, workflow ROI model and prioritized backlog, known limitations, representative evaluation fixtures, failure-injection results and tracing. I would also show restart behavior and an operator takeover path where needed.
