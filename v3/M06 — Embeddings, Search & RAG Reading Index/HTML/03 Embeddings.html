Part 1

Part 1 · Foundations

Understand what vectors can help find—and what they cannot decide.

10 Q&A
What an embedding does

It gives text a searchable representation

An embedding model converts a text item—such as a chunk or a user query—into a dense vector. A search system compares compatible vectors to find candidate passages that may express related meaning.

What it does not do

It does not certify the answer

A vector does not prove that a passage is true, relevant to the exact question, approved, current, or authorized. The system must retrieve the source text and apply policy and evidence checks.

Dense and sparse representations

Dense vectors

Use a fixed-size set of learned, distributed features. They are useful when different wording expresses similar meaning, such as “inspect” and “check”. A coordinate is not a human-readable label by itself.

Strength: semantic and paraphrase matching. Risk: related topics or contradictory instructions can look close.

Traditional sparse / lexical representations

Use a large vocabulary-related space in which most values for a passage are empty. Methods such as BM25 are strong when exact words, identifiers, model codes, and rare terms matter.

Strength: exact terms and identifiers. Risk: a paraphrase may use different words and be missed.

“Sparse” does not always mean an untrained word-count method. Learned sparse approaches also exist. The practical distinction is whether the representation is based on vocabulary terms or dense learned features.

How the encoders fit together

Bi-encoder / dual encoderEncodes a query and each document independently. Document vectors can be created offline and reused, making first-stage search efficient.
→
Candidate retrievalCompares the query representation with eligible document vectors and returns a manageable candidate set.
→
Cross-encoder / rerankerReads a query and one candidate passage together. It can judge their relationship more closely, but is usually reserved for a small candidate set.
Three boundaries to remember
  • Similarity is not relevance. Two passages about the same equipment can express opposite instructions.
  • A similarity score is not a probability. It is a score under one model, configuration, corpus, and comparison method.
  • A vector is an index entry, not the source or a security control. Keep the source text, provenance, version, and permissions.

FOUNDATIONS · Q01
InterviewJunior

Explain an embedding to a junior developer without using machine-learning jargon.

View model answer⌄

An embedding turns a piece of text into a list of numbers that a search system can compare. Texts the model considers related may receive nearby representations. The system uses those representations to find candidate passages, then reads the actual source. The numbers do not prove that a passage is correct or permitted.

FOUNDATIONS · Q02
ConceptFoundation

How do dense and traditional sparse representations differ?

View model answer⌄

Dense representations use learned features distributed across a fixed-size vector. Traditional sparse lexical representations use vocabulary-related features, with most entries absent for a given passage. Dense search often helps with paraphrases; lexical search is often strong for exact words and identifiers.

FOUNDATIONS · Q03
ConceptFoundation

Does sparse search always mean a simple, untrained word-count method?

View model answer⌄

No. BM25 is a traditional lexical approach, but learned sparse models can use neural methods to learn term weights or expansions. “Sparse” describes the representation pattern, not necessarily whether learning was involved.

FOUNDATIONS · Q04
InterviewJunior

Why are bi-encoders useful for large-scale search, and where do cross-encoders fit?

View model answer⌄

A bi-encoder encodes documents independently ahead of time and encodes the query at search time. The system can compare the query vector with precomputed document vectors efficiently. A cross-encoder reads the query and a candidate passage together, so it is more expensive per item but useful for reranking a small candidate set.

FOUNDATIONS · Q05
Real-world scenarioMid-level

A high-similarity passage is about the right machine but gives an instruction opposite to the user’s question. Why can this happen?

View model answer⌄

The passages share topic vocabulary and context, so the embedding model may place them close even though a short negation or condition reverses the meaning. Similarity retrieves candidates; it does not resolve contradiction. Exclude obsolete or non-authoritative sources with metadata, rerank candidates, inspect the actual evidence, and require the answer to be supported by the approved source.

FOUNDATIONS · Q06
Real-world scenarioSenior

A product manager proposes one universal similarity cutoff for every embedding model. What is wrong with that proposal?

View model answer⌄

Scores are not probabilities and their distributions change with the model, corpus, query style, and preprocessing. A cutoff that works for one setup may reject valid evidence or accept weak evidence in another. Calibrate an abstention rule using labelled examples and hard negatives for each model and task, then re-check it after relevant changes.

FOUNDATIONS · Q07
Real-world scenarioJunior

Can the company delete the original PDFs after creating embeddings to save storage?

View model answer⌄

No. Vectors do not preserve the full readable source needed for citations, exact verification, reprocessing, version comparison, or investigation. They are also derived from the source and must inherit its access, retention, and deletion controls. Keep the canonical source and traceable extracted text under the applicable policy.

FOUNDATIONS · Q08
InterviewMid-level

Can embeddings be treated as anonymized because they contain numbers rather than readable text?

View model answer⌄

No. Numeric representation does not remove the source’s confidentiality or privacy obligations. Treat vectors as sensitive derived data, apply the same tenant and authorization boundaries, and include them in deletion and retention workflows.

FOUNDATIONS · Q09
InterviewJunior

A stakeholder says “the vector database found it, so the answer must be correct.” How would you correct that assumption?

View model answer⌄

The database found a candidate according to the configured representation and metric. It did not establish truth, source authority, version, or user authorization. The application must apply source-state and permission filters, fetch the underlying text, inspect whether it supports the claim, and cite the source span.

FOUNDATIONS · Q10
ConceptFoundation

What is the difference between semantic similarity and business relevance?

View model answer⌄

Semantic similarity describes how close two representations are under a model. Business relevance also depends on the user’s intent, source authority, effective revision, applicability, and whether the user may access the passage. A historically similar manual or a confidential document can be semantically close and still be unsuitable.

Part 2

Part 2 · Stage A

Select the model and lock the representation contract before encoding.

13 Q&A

Choose a model for the retrieval relationship you actually need, then freeze the rules that make document and query vectors compatible. Do this before creating a production index.

Start with the search task

Symmetric search

Both sides have similar form, such as finding a duplicate question from another question or matching one short description to another.

Asymmetric search

A short user question is matched to a longer passage. This is common in question-to-document retrieval and should influence model selection and evaluation examples.

Evaluate model fit across the whole operating environment

Selection areaWhat to examine
Retrieval trainingWas the model trained for the relationship between the query and target passage?
Domain fitDoes it distinguish specialist vocabulary, abbreviations, equipment names, and similar part codes?
Language fitTest same-language, cross-language, mixed-language, transliterated, and specialist text separately.
Input limitCan the complete constructed input fit without silent truncation?
Output contractConfirm dimension, precision, pooling, normalization, and intended comparison metric.
DeploymentCheck whether the model can run in the approved environment and meet data-handling requirements.
OperationsMeasure throughput, query latency, update volume, cost, and reproducibility.

Benchmarks are a shortlist, not a production decision

MTEB covers multiple embedding task types; BEIR focuses on heterogeneous retrieval evaluation. Their results help shortlist candidates, but aggregate benchmark performance does not guarantee performance on a private corpus. Test your own domain terms, languages, exact identifiers, opposite conditions, and revision-sensitive questions.

Dimensionality, precision, and storage

Dimensionality describes the shape of a vector, not the meaning of its coordinates. Two models can produce vectors with the same number of coordinates and still use incompatible learned spaces. Higher dimensionality is not automatically better; evaluate retrieval quality against storage, latency, and cost. Lower-precision storage or quantization may reduce resource use, but can affect retrieval fidelity and must be tested.

Never shorten an ordinary vector by arbitrarily dropping coordinates. A shortened representation is appropriate only when the model explicitly supports it (for example, a Matryoshka-style representation), and the shortened configuration still needs its own evaluation and index generation.

The compatibility contract

Model identityModel family and pinned revision
Encoding modeQuery versus passage/document mode
Instructions / prefixesExact model-specific query and passage prefixes
Text assemblyTitle, section path, body, and any other included fields
Input preparationTokenizer, Unicode/preprocessing version, special tokens, truncation policy
Vector handlingPooling, normalization, output dimension, and precision
ComparisonSimilarity metric and score direction
Index identityEmbedding configuration ID recorded with the index
Silent compatibility failure

Switching only the query service to another model—even one with the same vector dimension—can make search return meaningless results without throwing an error. The query service and index must agree on the full contract, not merely vector shape.

Connection to Chunking (M06.1.2)

Embedding begins with approved chunks. The exact embedded input may include a title, section path, heading, prefix, and body. All of those pieces count toward the model’s input limit. If the embedder silently truncates the end of a chunk, important exceptions may never influence its vector. Treat truncation as an explicit failure or deliberately split the input; do not assume the full stored chunk was encoded.

Prefer the simplest retrieval design that solves the observed problem

If dense search handles conceptual questions but misses exact part numbers, compare lexical and hybrid retrieval before commissioning fine-tuning. A lexical signal can complement dense semantic matching for identifiers. Fine-tuning should follow evidence that simpler alternatives do not solve the target failure slice.

13 questions
STAGE A · Q01
ConceptFoundation

What is the difference between symmetric and asymmetric semantic search?

View model answer⌄

Symmetric search compares items with similar form, such as one short question against another. Asymmetric search matches a short query to a longer passage. For question-to-manual retrieval, choose and evaluate a model for the asymmetric relationship rather than assuming any general sentence-similarity model will behave well.

STAGE A · Q02
InterviewJunior

Why should model selection consider more than a benchmark leaderboard position?

View model answer⌄

Benchmarks describe performance on their own datasets and task mixes. Your corpus may contain specialist terms, codes, multiple languages, revisions, and safety-critical opposites that are underrepresented in public benchmarks. Use benchmarks to shortlist candidates, then compare them on a labelled local evaluation set.

STAGE A · Q03
ConceptFoundation

What are MTEB and BEIR useful for, and what can they not prove?

View model answer⌄

They provide benchmark suites for comparing embedding and retrieval approaches across tasks or heterogeneous datasets. They help narrow the candidate list, but cannot prove that a model is best for a private enterprise corpus or that it will meet your latency, security, or cost requirements.

STAGE A · Q04
Real-world scenarioMid-level

A model interprets “port” as a harbour, but your users mean a network port. What is the likely issue and next step?

View model answer⌄

This is a domain-fit problem. Create a local test slice using the relevant IT sense of “port”, specialist terms, abbreviations, and confusing alternatives. Compare the dense model with lexical and hybrid baselines. Do not jump straight to a larger model or fine-tuning without identifying which failure is occurring.

STAGE A · Q05
Real-world scenarioMid-level

A multilingual embedding model performs poorly on scanned Hindi logs. Should you immediately switch to a larger multilingual model?

View model answer⌄

No. Inspect the extracted Hindi text first. If OCR used the wrong language configuration or produced damaged Devanagari text, the embedding model cannot recover characters that were never extracted correctly. Check OCR language support, Unicode normalization, same-language retrieval, cross-language retrieval, and the raw source text before changing the embedding model.

STAGE A · Q06
InterviewSenior

What belongs in an embedding compatibility contract?

View model answer⌄

At minimum: model family and pinned revision; query and document modes; required prefixes or instructions; tokenizer and preprocessing; text-construction template; truncation policy; pooling; normalization; output dimension and precision; similarity metric; and a configuration identifier stored with the index. The contract should be shared by offline document generation and online query encoding.

STAGE A · Q07
ConceptFoundation

Why do some models require different query and passage prefixes?

View model answer⌄

Those models were trained to distinguish the role of the input. A query prefix and a passage prefix help project the two sides into the intended shared retrieval space. Omitting or swapping the prefix can degrade results. Prefix rules are model-specific; do not copy one model’s instructions onto another model unless its documentation requires them.

STAGE A · Q08
Real-world scenarioJunior

A developer changes the query encoder to Model B while leaving document vectors from Model A in the index. Both models output the same dimension. Why does search break?

View model answer⌄

The coordinate spaces are learned independently. Equal dimension only means the arrays have the same shape; it does not make their distances meaningful together. Store a configuration ID with the index and have the query service assert compatibility at startup and before serving. A model change should trigger a controlled re-embedding and index migration.

STAGE A · Q09
InterviewJunior

A team says two models are compatible because they both output the same number of coordinates. Is that sufficient?

View model answer⌄

No. The model revision, query/document mode, prefixes, text template, preprocessing, tokenizer, pooling, normalization, dimension, precision, and metric all affect the representation. Shape compatibility is not semantic compatibility.

STAGE A · Q10
Real-world scenarioMid-level

Chunks fit the chunker’s target size but the embedding model accepts a shorter input. Search misses exceptions that occur near the end. Diagnose the failure.

View model answer⌄

The constructed passage is probably being silently truncated by the embedding model. The stored text appears complete, but the vector represents only the portion accepted by the encoder. Count tokens with the consuming model’s tokenizer, include prefixes and headings in the count, and make truncation fail visibly or split the input under a defined policy.

STAGE A · Q11
Real-world scenarioMid-level

Dense search handles conceptual questions but misses exact part codes. A colleague proposes fine-tuning immediately. What would you recommend first?

View model answer⌄

Benchmark a lexical baseline and a hybrid combination of lexical plus dense retrieval on the exact-code query slice. Lexical retrieval is often strong for exact alphanumeric identifiers, while dense retrieval helps paraphrases. Fine-tuning may be justified later, but first establish whether a simpler hybrid design solves the observed gap.

STAGE A · Q12
Real-world scenarioSenior

Bulk ingestion uses “title + section path + body”, but an incremental update script embeds only the body. Why might updated passages stop ranking well?

View model answer⌄

The index now contains vectors produced from two different input conventions under the same configuration label. The title and section context influenced the older vectors but not the updated ones. Put input construction in one shared, versioned component and use it for bulk ingestion, updates, and query-side conventions as appropriate. Re-embed affected inputs when the embedded text recipe changes.

STAGE A · Q13
InterviewSenior

An architect wants to cut every vector in half by dropping its trailing coordinates. When is shortening valid?

View model answer⌄

Only when the model explicitly supports a shortened representation, such as a documented Matryoshka-style output or another validated projection approach. Arbitrary slicing can discard learned information and damage retrieval. Treat a supported shorter form as a distinct configuration, prepare the matching query vectors, and evaluate it in a separate index generation.

Part 3

Part 3 · Stage B

Generate correctly mapped, validated, safely cached vectors.

12 Q&A

Once the contract is pinned, create vectors efficiently without losing the link between each vector, its exact input, its source, and its permissions.

Offline document path

Runs during ingestion and updates. It can batch work for throughput, checkpoint progress, retry recoverable failures, and prepare vectors before publication.

Online query path

Runs when a user searches. It is on the request latency path, so it needs predictable response time and the same compatible query-side contract.

Construct the exact input first

Build the passage exactly as the contract specifies—for example, title, section path, body, and a model-specific passage prefix. Apply the correct query prefix to queries when required. Version preprocessing and Unicode handling because a seemingly small text change can alter the representation. Count all included tokens and do not rely on silent provider truncation.

Batch by workload, not just item count

A batch of many short labels is not equivalent to the same number of long technical passages. Set limits using total token volume as well as item count, concurrency, provider limits, memory, throughput, and online service objectives.

Protect the input-to-output mapping

Stable input IDAssign every chunk a durable record identifier before submitting a batch.
→
Provider response index / IDUse the response’s documented index or explicit identifier to match each vector to its input.
→
Validated upsertWrite only after the mapping and vector checks pass.

Asynchronous jobs can finish out of order. Never zip returned vectors to source IDs based on completion order. A mis-mapped vector can be numerically valid but attached to the wrong manual, creating plausible-looking but incorrect search results.

The vector validation firewall

01 · IdentityResponse belongs to the requested input ID.
02 · CountExpected number of vectors was returned.
03 · ShapeEvery vector matches the index’s expected dimension.
04 · Finite valuesNo NaN or infinite coordinates.
05 · Valid normReject or explicitly handle zero/invalid vectors.
06 · Config recordedModel and embedding configuration identity is stored.
07 · Source eligibilityRecheck that the source is still active and publishable.

Partial failures and safe retries

Persist successful items using idempotent writes, retry only unresolved transient failures with backoff, and separate permanent input failures from service failures. A malformed or over-limit passage should be quarantined for correction rather than retried endlessly. Use a dead-letter or review state so one bad item does not repeatedly block a large batch.

Understand the three cache layers

CacheWhat it storesWhat it saves
Embedding cacheVector for an exact input under an exact encoding contractRepeated model calls for unchanged text and settings
Retrieval-result cacheCandidate chunk IDs for a query and filter scopeRepeated search work
Semantic-answer cacheFinal generated answer for a question/context scopeRepeated answer generation

An embedding cache key must represent the approved scope, model revision, query or passage mode, exact input text, prefix, tokenizer/preprocessing version, pooling and normalization settings, and output dimension. If the title or heading was part of the input, changing it changes the embedding input and invalidates reuse for affected chunks.

Tenant-safe caching

Do not key private vectors by text and model alone in a global cross-tenant cache. A global cache can create existence/timing side channels or accidentally return metadata across boundaries. Scope private cache entries to the tenant or an explicitly approved sharing boundary, and always re-check authorization before serving source text. A cache hit is not permission.

12 questions
STAGE B · Q01
ConceptFoundation

Why are document embeddings usually generated offline while query embeddings are generated online?

View model answer⌄

Documents are known ahead of time and can be processed in batches for throughput. A user query arrives during an interactive request and therefore has a latency requirement. Both paths must use compatible settings, but their execution and service objectives differ.

STAGE B · Q02
InterviewJunior

Why should embedding batches be limited by total tokens as well as number of chunks?

View model answer⌄

Items can vary greatly in length. A batch containing many long passages can exceed memory or service limits even when its item count is modest. Use the consuming tokenizer and control both aggregate token volume and item count, with concurrency and provider limits included.

STAGE B · Q03
ConceptFoundation

Can an asynchronous batch’s returned vector list be matched to inputs by completion order?

View model answer⌄

No. Jobs can finish out of order. Use the documented response index or explicit request ID to map every vector back to its stable input ID, then validate the mapping before writing.

STAGE B · Q04
Real-world scenarioJunior

Searching for a database restart procedure returns the canteen menu, while the citation points to the database manual. What batch-processing bug is likely?

View model answer⌄

The vector for one input was attached to another input’s ID because asynchronous completion order was mistaken for submission order. Audit the mapping code and batch records, rebuild affected entries from stable IDs, and add tests with deliberately varied input lengths and out-of-order responses.

STAGE B · Q05
InterviewMid-level

What checks should pass before a vector is accepted into the index?

View model answer⌄

Verify that it belongs to the right input; the expected vector count is present; the dimension matches; all coordinates are finite; the norm is valid for the chosen metric; the model/configuration identity is recorded; and the source is still eligible for publication. A successful API response alone is not enough.

STAGE B · Q06
Real-world scenarioMid-level

A batch has many successful items and one malformed passage. Should the entire batch be retried?

View model answer⌄

No. Persist the successful results idempotently and isolate the failed item. Retry transient errors such as temporary service or rate-limit failures; route permanent input problems such as malformed text or length violations to a review/dead-letter path. This avoids recomputing successful work and burning credits on an unfixable input.

STAGE B · Q07
InterviewSenior

How would you make embedding retries safe?

View model answer⌄

Use stable source/chunk IDs and an idempotent key that includes the embedding configuration. Track per-item state, persist successes, retry only unresolved transient failures, and prevent duplicate active vectors. Before publication, confirm that the source and version are still eligible.

STAGE B · Q08
ConceptFoundation

What is the difference between an embedding cache, retrieval-result cache, and answer cache?

View model answer⌄

An embedding cache reuses a vector for an exact input and encoding configuration. A retrieval-result cache reuses the candidate IDs returned by a query under a particular filter scope. An answer cache reuses generated prose. They contain different data, have different invalidation rules, and must all respect current authorization and deletion policy.

STAGE B · Q09
InterviewMid-level

Which settings should be represented in an embedding cache key?

View model answer⌄

Include the approved cache scope; pinned model revision; query or passage mode; exact constructed input including prefixes and included headings; tokenizer and preprocessing version; pooling and normalization; and output dimension. Include any additional setting that changes the representation. Serialize key parts unambiguously before hashing.

STAGE B · Q10
Real-world scenarioMid-level

The body of a chunk is unchanged, but its included heading changes. Can the old embedding safely be reused?

View model answer⌄

Not if the heading was part of the model input. The exact encoded text has changed, so the old vector represents a different input. Recompute affected vectors or redesign the input template so display-only fields are not unnecessarily embedded.

STAGE B · Q11
Real-world scenarioSenior

A global Redis cache is keyed only by model revision and text. Why is this risky in a multi-tenant product?

View model answer⌄

A tenant may infer that another tenant has processed a sensitive phrase through timing or cache-existence behavior. Poorly designed cache records may also expose linked metadata or bypass an authorization check. Scope private cache entries to an approved tenant boundary and authorize source access independently on every serving path.

STAGE B · Q12
Real-world scenarioSenior

A source is deleted while a long embedding job is still running. What must happen when the worker finishes?

View model answer⌄

The worker must re-check the current source state before publication. A completed computation does not override a deletion or revocation. The result should be discarded or quarantined, and the source must not be reactivated by an in-flight job.

Part 4

Part 4 · Stage C

Encode queries compatibly and interpret similarity results correctly.

10 Q&A

At query time, encode the question under the same contract as the stored passages, then compare only eligible vectors using the metric the model and index expect.

Query-time sequence

  1. Establish trusted user scope. Resolve tenant, ship/company scope, ACLs, version requirements, and source state from trusted backend context.
  2. Build the query input. Apply the correct query mode, prefix, preprocessing, and configuration.
  3. Check compatibility. Confirm the query encoder and target index generation share the required embedding configuration.
  4. Validate the query vector. Reject non-finite or invalid outputs, including zero vectors where the metric cannot handle them.
  5. Search eligible vectors. Apply authorization, version, and deletion constraints as part of the retrieval design—not as a final wording check.
  6. Interpret the returned scores correctly. Confirm whether larger similarity or smaller distance is better, and pass candidate source text and provenance to the next retrieval stage.

The three comparison approaches

01

Cosine similarity

Compares direction and largely ignores vector length. It is undefined for a zero vector, so invalid vectors must be rejected or handled before indexing and searching.

Usually: higher means more directionally similar.
02

Dot product / inner product

Reflects both direction and vector magnitude. It is appropriate when the chosen model is intended for inner-product retrieval. Do not substitute it just because the vector database supports it.

Usually: higher means a larger inner product.
03

Euclidean / L2 distance

Measures straight-line separation. The closest vector has the smallest distance. Confirm whether the database returns raw distance, squared distance, or a transformed score.

Usually: lower means closer.

Normalization and consistency

L2 normalization puts nonzero vectors on a common unit length. When both query and document vectors are normalized consistently, cosine and inner product align, and exact distance-based ranking can agree as well. Do not normalize one side by accident or change normalization without changing the contract and evaluation. Approximate indexes and quantization can still cause practical ranking differences.

Score meaning and abstention

A score is meaningful only within the model, preprocessing, normalization, metric, and task that produced it. Calibrate thresholds using labelled relevant and irrelevant examples, include no-evidence queries and hard negatives, and test slices such as languages, identifiers, and revisions. Recalibrate after a model or pipeline change. Never treat a threshold as proof of authority, correctness, or authorization.

Do not confuse retrieval ranking with access control

A highly similar vector from the wrong tenant, wrong revision, or deleted source must not be eligible. Apply trusted metadata and policy filters before candidate text can reach rerankers, generators, snippets, or citations.

10 questions
STAGE C · Q01
ConceptFoundation

How do cosine similarity, dot product, and Euclidean distance differ in practical terms?

View model answer⌄

Cosine focuses on the direction of vectors and largely ignores their length. Dot product is influenced by both direction and magnitude. Euclidean distance measures separation, where a smaller distance means closer. Select the metric that matches the model’s intended retrieval behavior and the index contract.

STAGE C · Q02
Real-world scenarioJunior

Why can a zero vector break a cosine search pipeline?

View model answer⌄

Cosine compares vector directions, but a zero vector has no direction. The comparison can become undefined and produce a non-finite score that corrupts ranking or result handling. Reject empty or invalid embedding inputs and validate vector norms before indexing.

STAGE C · Q03
Real-world scenarioMid-level

A team changes its vector database from cosine similarity to raw Euclidean distance but leaves the application sorting scores from highest to lowest. What happens?

View model answer⌄

The result order is reversed. Similarity scores are commonly ranked high to low, while raw distance is ranked low to high. The system can show the farthest passages first. Check the database’s score semantics and update sorting, thresholds, and UI labels together.

STAGE C · Q04
Real-world scenarioSenior

The document vectors are normalized but the query vectors are not. Is the ranking always wrong?

View model answer⌄

For a single query under an inner-product comparison with normalized document vectors, the query’s length acts as the same positive scale factor for every document and may preserve that query’s relative order. However, scores become inconsistent across queries, which can break thresholds, score comparisons, and score-based fusion. Normalize both sides consistently under the contract.

STAGE C · Q05
InterviewMid-level

Why must the query service confirm the embedding configuration before searching an index?

View model answer⌄

A query vector from a different model revision, prefix, input recipe, pooling, or normalization may be incompatible with the stored vectors even if the dimensions match. A configuration check turns a silent correctness failure into an explicit deployment or request error.

STAGE C · Q06
InterviewJunior

A vector database returns a field called “score”. Can the application assume that higher is always better?

View model answer⌄

No. The field may represent similarity, a distance, a negated distance, or a transformed value. Confirm the backend’s documented semantics and test known examples before sorting or applying thresholds.

STAGE C · Q07
InterviewSenior

Why should a similarity threshold be calibrated separately for each model and retrieval task?

View model answer⌄

Score distributions vary by model, corpus, query type, and preprocessing. A single cutoff can reject useful evidence in one setting and accept weak matches in another. Use labelled positives, hard negatives, and no-evidence cases to choose and validate an abstention policy for each configuration.

STAGE C · Q08
Real-world scenarioSenior

At query time, should the system search first and then check whether the user is allowed to see the result?

View model answer⌄

No. Authorization and source-state restrictions must constrain retrieval before unauthorized text can be exposed to snippets, rerankers, language models, or citations. A final answer refusal does not repair an earlier leak of restricted evidence.

STAGE C · Q09
TroubleshootingMid-level

What practical checks would you perform when similarity results suddenly contain NaN or invalid scores?

View model answer⌄

Inspect the query and document vector validation path, empty inputs, zero norms, non-finite coordinates, normalization differences, and any change to the metric or index. Reject invalid vectors before insertion and prevent them from participating in ranking. Trace the source input to determine whether extraction or encoding produced the invalid vector.

STAGE C · Q10
ConceptMid-level

Why can approximate nearest-neighbour search return different candidates from an exact search even with the same vectors?

View model answer⌄

An approximate index deliberately avoids comparing every vector and uses index structures or compressed representations to reduce latency and resource use. That trade-off can miss some exact nearest neighbours. Keep an exact-search baseline on a representative sample so model quality can be distinguished from approximation effects.

Part 5

Part 5 · Stage D

Prove retrieval quality with controlled, representative evaluation.

9 Q&A

Do not choose a model from a demo or a single benchmark. Freeze a representative dataset, compare fair baselines, inspect failure slices, and test the full serving pipeline.

Build a trustworthy evaluation set

  • Use an immutable corpus snapshot and keep extraction, chunking, metadata, and permissions constant during model comparison.
  • Label the source spans that actually answer each query, the required source revision, and the user’s authorization scope.
  • Include queries for which no authorized evidence exists.
  • Add hard negatives: similar equipment with a different revision, near-identical part codes, opposite instructions, wrong tenant, or unrelated passages with similar wording.

Compare meaningful baselines

LexicalExact words and identifiers
Dense ACandidate embedding model A
Dense BCandidate embedding model B
HybridCombined lexical and dense candidates

On a manageable sample, use exact vector search first to isolate embedding quality from approximate-index behavior. Then evaluate the production approximate index and reranker using a fixed configuration.

Measure more than the first result

Recall@KDoes the required evidence appear somewhere in the first K candidates?
MRRHow early does the first correct result appear across queries?
nDCGDoes the ranking place the most relevant results near the top, including graded relevance?
Operational measuresLatency, throughput, storage, cost, and index build/update time.

First-stage retrieval must bring useful evidence into the candidate pool. A reranker can improve ordering among retrieved candidates, but it cannot rescue the correct passage if that passage was never retrieved.

Use failure slices to find what needs fixing

Failure sliceWhat it may revealNext diagnostic
ParaphrasesDense retrieval may help where lexical terms differ.Inspect local query and passage pairs.
Exact identifiersDense search may miss codes or rare strings.Compare lexical and hybrid retrieval.
MultilingualLanguage direction or vocabulary may be weak.Separate same-language and cross-language tests; inspect OCR text.
Revision-sensitiveOld and current manuals may be semantically close.Apply authoritative version filters.
Negation / oppositesContradictory instructions may rank close.Add hard negatives, reranking, and evidence checks.
Restricted contentUnauthorized passages are entering candidates.Audit tenant and ACL pre-filters.
Keep experiments fair

Change one variable at a time. If the model, chunk size, reranker, corpus, or filters all change together, an improvement cannot be attributed to the embedding model.

Acceptance evidence

A production decision should be supported by the model/configuration manifest, dataset description, baseline comparison, results by failure slice, representative failure traces, vector validation report, cache design, and migration/deletion test results. Explain why the model fits this corpus and its operating constraints; do not claim it is universally best.

Why should an embedding comparison use a frozen corpus and fixed chunk boundaries?

View model answer⌄

Otherwise the experiment changes more than the embedding model. New chunk boundaries or extraction changes can alter what is represented and retrieved. Keep the source snapshot, extraction, chunks, permissions, questions, and other pipeline settings fixed so results can be attributed to the model configuration being tested.

Why run exact vector search before benchmarking HNSW or IVF?

View model answer⌄

Approximate nearest-neighbour indexes trade some exactness for speed. Their parameters can change which candidates are found. Exact search on a representative sample isolates embedding behavior from index approximation; afterward, evaluate the actual approximate index separately.

STAGE D · Q03
InterviewMid-level

Which baselines should be compared before selecting a production embedding model?

View model answer⌄

Compare lexical retrieval, the current dense model, candidate dense models, and a hybrid combination. Use the same labelled questions and source snapshot, then evaluate the production reranker with a fixed configuration. This shows whether a new model adds value beyond simpler approaches.

STAGE D · Q04
Real-world scenarioSenior

A model has a weaker first-stage top-five ranking but much better candidate recall deeper in the list. Why might it win after reranking?

View model answer⌄

The first stage must place the correct evidence somewhere in the candidate pool. A reranker can then inspect and reorder those candidates. A model with better candidate coverage can outperform one that ranks its initial top results more neatly but misses the true passage entirely.

STAGE D · Q05
ConceptFoundation

What do Recall@K, MRR, and nDCG tell you in an embedding evaluation?

View model answer⌄

Recall@K checks whether required evidence appears within the first K results. MRR emphasizes how early the first correct result appears. nDCG rewards high placement of relevant results and can account for graded relevance. Use them together with latency, cost, and slice-level inspection rather than relying on one headline metric.

STAGE D · Q06
InterviewMid-level

What hard negatives should be included in a maintenance-manual embedding evaluation?

View model answer⌄

Include the wrong revision of the same manual, a similar equipment code, the opposite of a safety instruction, a document from another tenant, an unrelated passage with similar vocabulary, and cases where no authorized evidence exists. These test failure modes that ordinary paraphrase examples may hide.

STAGE D · Q07
Real-world scenarioSenior

An engineer changes the embedding model, chunk size, and reranker together. The score improves. Can they conclude the new model is better?

View model answer⌄

No. The experiment is confounded because several variables changed at once. The improvement may come from different chunks or reranking rather than the model. Repeat with a fixed corpus, extraction, chunking, permissions, and reranker, varying the embedding configuration only.

STAGE D · Q08
InterviewSenior

How would you decide whether a model is worth the additional storage and latency?

View model answer⌄

Compare retrieval quality on the target corpus and difficult slices, then evaluate query latency, throughput, storage, index build cost, update cost, deployment constraints, and operational complexity. Choose the best quality-to-cost fit for the task rather than the largest model or highest public benchmark score.

STAGE D · Q09

Part 6

Part 6 · Stage E

Migrate safely, preserve compatibility, and prevent stale data from returning.

10 Q&A

A model or representation change is a data migration, not a harmless configuration edit. Keep query and index generations compatible while updates and deletions continue.

Know what requires new vectors

ChangeTypical actionReason
Body text changesRe-embed affected inputsThe represented content changed.
Included title or heading changesRe-embed affected chunksThe exact embedded input changed.
Model revision, pooling, or normalization changesBuild a new compatible vector setThe representation contract changed.
Dimension or supported precision changesUse a new index configuration and evaluateIndex schema or representation behavior changed.
ACL membership changes onlyUpdate control metadata and serving cachesPermissions are control data, not vector content.
Citation display label changes onlyUpdate display metadataThe embedded text may be unchanged.

Safe migration sequence

1 · Freeze the new contractAssign a new configuration ID and create a separate index generation.
2 · Capture a source checkpointRecord the source state and a durable change log for additions, revisions, deletions, and ACL changes.
3 · Build offlineRe-embed canonical source inputs under the new contract and validate every vector.
4 · Evaluate and test policyRun retrieval quality, authorization, version, cache, and deletion tests.
5 · Reconcile live changesReplay changes since the checkpoint and verify against the current source database immediately before publication.
6 · Switch a compatible pairRoute the new query encoder to the new index together. Keep the old encoder/index pair available for rollback.
7 · Observe, then retireShadow or canary test, monitor, retain the rollback window, then purge old generations and dependent caches under policy.

Prevent zombie documents

A zombie document is a source that was deleted from the live system while a long re-embedding job was working from an older snapshot, then reappears in the new index because the migration failed to replay deletions. The same risk exists when a slow in-flight batch finishes after deletion. Reconcile current state before publication and reject results whose sources are no longer eligible.

Switch query service and index together

Do not let half the application pods use a new query encoder while the router still points them to the old index. Keep both generations online during rollout and route each service version to its matching index generation through an explicit compatibility identifier. Rollback must restore the matching encoder/index pair, not just one side.

Deletion is a lifecycle operation

Remove or invalidate source-derived vectors, retrieval caches, answer caches, and other serving artifacts. Test both fresh and cached queries. A retained audit record may remain under its own controls, but deleted content must not remain searchable or citable through ordinary serving paths.

Which changes normally require re-embedding, and which can be metadata-only?

View model answer⌄

STAGE E · Q03
InterviewMid-level

Why should a model migration build a separate index generation?

View model answer⌄

A separate generation prevents vectors from incompatible spaces being mixed, allows fair evaluation, supports controlled cutover, and provides rollback. The new query encoder must target the new generation, while the old pair remains consistent until retirement.

STAGE E · Q04
InterviewSenior

What is a source checkpoint and why is a change log needed during migration?

View model answer⌄

The checkpoint records the source state from which the new index build began. A durable change log captures additions, revisions, deletions, and permission changes that happen while the background build runs. Replay and reconcile those changes before publication so the new index reflects current state.

STAGE E · Q05
ConceptFoundation

What is a zombie document?

View model answer⌄

It is deleted source content that becomes searchable again because a migration built from an old snapshot and did not reconcile deletions before switching to the new index. It can also happen when an in-flight embedding worker writes a vector after the source was deleted.

STAGE E · Q06
Real-world scenarioSenior

A deleted manual reappears after a multi-day model migration. What should you do immediately and what should change in the migration process?

View model answer⌄

Immediately block the source from serving, remove or invalidate its derived vectors and caches, and verify that fresh and cached queries cannot return it. For future migrations, record the source checkpoint, replay deletion/update events, run a pre-publish verification against live source state, and re-check source eligibility before every write/publication.

STAGE E · Q07
Real-world scenarioSenior

During a rolling deployment, some API pods use the new query encoder while the database router still points to the old index. What is the failure?

View model answer⌄

Those pods compare vectors from the new representation with document vectors from the old one. The dimensions may match and requests may succeed, but results are semantically meaningless. Keep both generations online and route each encoder version explicitly to its matching index generation.

STAGE E · Q08
InterviewSenior

What must rollback restore during an embedding migration?

View model answer⌄

Rollback must restore a consistent pair: the query encoder/configuration and the index generation built under that same contract. Reverting only the index or only the model can recreate the compatibility failure.

STAGE E · Q09
Real-world scenarioSenior

A legal team corrects one word in document titles, and the title is included in every chunk input. Can the old vectors be reused?

View model answer⌄

Not if the changed title was part of each encoded input. All affected chunks whose constructed text includes that title need to be re-embedded. For future efficiency, distinguish retrieval-relevant text from display-only metadata and avoid embedding fields that do not need to influence retrieval.

STAGE E · Q10
InterviewSenior

How do you verify that deletion has propagated beyond the vector index?

View model answer⌄

Check source eligibility, vector records, embedding caches, retrieval-result caches, answer caches, snippets, replicas, and citations. Run both fresh and repeated cached queries under authorized and unauthorized users. Verify that retained audit artifacts are not exposed through normal search paths.

Part 7

Part 7 · Cross-cutting System Design

Trace production failures across the complete vector lifecycle.

5 Q&A

Real incidents rarely belong to one stage. Trace evidence from canonical source, through input construction and vector generation, into search, authorization, caching, and migration.

Diagnostic order for bad retrieval

1. CompatibilityDoes the query service use the configuration required by the target index?
2. Vector integrityAre vectors valid and attached to the correct chunk IDs?
3. ComparisonAre metric, normalization, score direction, and threshold consistent?
4. Source eligibilityAre tenant, ACL, revision, and deletion filters correct?
5. Evaluation slicesDoes the issue cluster around codes, languages, negation, or particular sources?
6. Downstream evidenceDoes reranking or answer assembly select and cite the correct source span?

End-to-end M-104 example

A tenant-A user asks, “When do I check the indicator?” The system must retrieve an approved source passage, not merely a passage with similar language.

Before encodingUse the approved M-104 chunk created by the Chunking module. Preserve its title, section path, body, source version, and tenant/ACL metadata.
Model contractChoose a question-to-passage model and pin its revision, mode, prefixes, input recipe, normalization, and metric.
Document vectorBuild the exact passage input, check token limits, use tenant-safe caching, batch by workload, map the output to the correct chunk ID, validate, and publish only if the source is still active.
User queryEncode the question with the query-side contract. Resolve tenant-A authorization from trusted backend context.
Candidate searchFilter out the old M-104 revision, tenant-B material, and deleted sources before exposing candidate text. Compare only compatible vectors.
Evidence handoffSend authorized candidate text and source spans to the next retrieval module for reranking and evidence assembly. Cite the original source, not the vector.
Ongoing changesUpdate affected vectors when embedded text changes; update ACL metadata when access changes; reconcile deletions and caches during migration.

System-design review checklist

  • Is the source of truth retained and linked to every vector?
  • Can the system prove which model configuration produced each vector?
  • Can a batch be resumed without duplicates or ID misalignment?
  • Can a deleted source be blocked even when a worker is still running?
  • Are all search, cache, reranking, snippet, and citation paths permission-aware?
  • Can a model migration be evaluated and rolled back as a consistent pair?

InterviewSenior

Explain the entire Embeddings lifecycle in an interview answer.

View model answer⌄

Start with the retrieval task and select a model that fits its domain, languages, and query-to-passage relationship. Pin a compatibility contract for model revision, mode, prefixes, text construction, preprocessing, pooling, normalization, dimension, and metric. Generate vectors in token-aware batches, map outputs by stable IDs, validate each vector, and use a tenant-safe cache. At query time, encode under the same contract, apply trusted authorization and source-state filters, and compare with the contracted metric. CROSS CUTTING · Q05
ConceptFoundation

What is the boundary between Embeddings (M06.1.3) and Retrieval (M06.2.1)?

View model answer⌄

Embeddings defines how approved document chunks and user queries are represented as compatible vectors and how those vectors are validated, stored, compared, and maintained. Retrieval uses the available candidate signals to search, combine results, rerank, assemble evidence, and return cited context. Embedding similarity is a candidate-finding mechanism, not the entire retrieval or answer process.

Glossary

EmbeddingA learned vector representation of an item such as text.
Dense vectorA fixed-size representation with learned distributed features.
Sparse / lexical representationA vocabulary-oriented representation suited to term and identifier matching.
DimensionThe number of coordinates in a vector; not a measure of truth or quality by itself.
Bi-encoderEncodes query and passage independently for efficient candidate search.
Cross-encoderScores a query and passage jointly, commonly used for reranking.
Compatibility contractThe pinned settings that make query and document representations comparable.
PoolingThe method used to produce one representation from model token outputs.
NormalizationA defined transformation applied consistently to vectors.
Embedding cacheReuse of a vector for an identical input under an identical configuration.
Hard negativeA misleading candidate that looks similar but is wrong, outdated, contradictory, or unauthorized.
Recall@KWhether required evidence appears within the first K candidates.
RerankerA model that re-scores a smaller set of candidate passages.
Index generationA separately versioned set of vectors and metadata built under one configuration.
Zombie documentDeleted content that reappears after a stale migration or in-flight job.
Matryoshka-style embeddingA model explicitly trained to support usable shortened representations.

Ten rules to rehearse

  1. Similarity finds candidates; source evidence establishes what can be claimed.
  2. Dense vectors help paraphrases; lexical retrieval helps exact terms and codes.
  3. Benchmark leaderboards shortlist models; local labelled tests select them.
  4. Equal vector dimension does not guarantee compatible representation spaces.
  5. Version the entire input recipe, not only the model name.
  6. Never map asynchronous batch outputs by arrival order.
  7. Validate identity, count, shape, finite values, norm, configuration, and source eligibility.
  8. A cache key must include the exact input and all settings that affect its vector, within a safe scope.
  9. Measure embedding quality with controlled baselines and failure slices.
  10. Build new index generations and switch the query encoder/index as a matched pair.
